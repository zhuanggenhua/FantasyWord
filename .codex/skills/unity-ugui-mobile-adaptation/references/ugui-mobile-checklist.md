# Unity UGUI 移动端适配检查清单

## 1. 先判定问题层级

- 先确认这是 UGUI 问题，不是 UI Toolkit。
- 先确认异常发生在编辑器静态布局、运行时分辨率变化，还是安全区设备上。
- 先找正式消费节点，不要对错的副本、嵌套预制体实例或临时容器下手。

## 2. Canvas 与基准分辨率

- 检查 `Canvas.renderMode`、父级 `Canvas` 数量和嵌套关系。
- 检查 `CanvasScaler.uiScaleMode` 是否为当前项目预期。
- 移动端常见正式入口是 `Scale With Screen Size`；确认 `referenceResolution`、`screenMatchMode`、`matchWidthOrHeight` 是否合理。
- 若项目已有统一 `CanvasScaler` 规则，不要为单个面板另起一套缩放真相。

## 3. 父级 RectTransform 真相

- 先看父级是否已经贴边、拉伸或受布局控制。
- 目标节点再正确，也无法突破父级裁剪、偏移或尺寸错误。
- 若父级由 `LayoutGroup` 驱动，优先在父级布局链里修，而不是只改子节点。

## 4. 目标节点锚点与偏移

- 固定在某个角或某条边的节点：
  使用贴边锚点，避免只靠 `anchoredPosition` 摆在视觉位置。
- 全屏背景、遮罩、弹窗根：
  优先四边拉伸，再用 `offsetMin/offsetMax` 控制边距。
- 中央弹窗：
  先确认锚点与 `pivot` 都在中心，再检查 `sizeDelta` 是否承担实际尺寸。
- 左右或上下自适应容器：
  先确认是否该使用 stretch 锚点，而不是固定宽高。

## 5. 布局组件冲突排查

- `HorizontalLayoutGroup` / `VerticalLayoutGroup` / `GridLayoutGroup` 在控制子项时，不要再手改子项位置。
- `ContentSizeFitter` 与 `LayoutGroup` 同节点共存时，先确认是不是 Unity 官方不推荐的双向驱动组合。
- `AspectRatioFitter` 容易和父级布局、锚点拉伸互相打架；只有确实需要固定比例时再保留。
- `ScrollRect` 问题先拆成 `Viewport`、`Content`、内容布局三层分别核对。

## 6. 安全区与异形屏

- 先判断是否真的是安全区问题，而不是锚点或边距错误。
- 如果项目已有统一安全区脚本或安全区容器，继续沿用它，不要为单个面板新增第二套入口。
- 顶栏、返回按钮、货币栏、底部操作区是最需要安全区校验的对象。
- 安全区修正应收口到容器层，避免每个子节点单独加补丁。

## 7. 运行时代码边界

- 若运行时脚本会在 `Awake`、`OnEnable`、`Start` 或分辨率变化后改 `RectTransform`，必须把它纳入正式消费链分析。
- 静态锚点正确但运行时又被脚本重写时，根因在脚本，不在预制体表象。
- 只有当设备差异无法通过静态布局表达时，才增加运行时布局逻辑。

## 8. 常见错误模式

- 锚点在中心，但元素要贴边。
- 用固定像素 `anchoredPosition` 模拟贴边。
- 父级没拉伸，子级却试图全屏。
- 同时使用 `LayoutGroup`、`ContentSizeFitter` 和手写尺寸。
- 把安全区问题误当成缩放问题。
- 通过整体缩放面板掩盖文本溢出和按钮拥挤。

## 9. 默认修复策略

1. 先修 `CanvasScaler` 或父级边界真相。
2. 再修目标节点锚点、`pivot`、边距和尺寸职责。
3. 再收口布局组件冲突。
4. 最后才处理安全区或运行时适配脚本。

## 10. 输出时必须交代

- 问题根因属于哪一层。
- 采用的是静态布局修复还是运行时适配修复。
- 是否影响其他共享预制体、共享面板或同级布局骨架。
- 是否已经覆盖不同分辨率、横竖屏或异形屏验证。
