# 测试换装场景验证器与显示缺口 - 2026-03-13

## 本轮目标
- 给 `Assets/Scenes/SampleScene.unity` 增加一个可重复执行的验证入口
- 判断当前主线是否已经只剩“换装验证”
- 区分 `换装可用` 与 `换装可见` 两类剩余问题

## 本轮完成
- 新增 `Assets/Scripts/_Editor/Playtest/DressUpSceneValidator.cs`
  - 用于固定化检查：
    - `SampleScene` 是否能进场
    - `GameManager` / `PlayerSystem` / `InventorySystem` 是否存在
    - `Devon` 是否生成
    - 起始金钱是否为 `250`
    - 三件测试装备是否存在
    - 三件测试装备的装备 / 卸下闭环是否成立
- 用 Unity Roslyn 复编验证器脚本，确认新增 Editor 代码可编译

## 关键发现
- 当前长期主线确实已经收敛到“测试换装场景验证”
- 但这条主线内部仍分两类问题：
  - `换装可用`
    - 是否能进场
    - 是否能生成玩家
    - 是否能装备 / 卸下
    - 是否会正确更新背包、槽位、属性
  - `换装可见`
    - 装备后角色外观是否真的变化
- 静态检查结果表明：
  - `ITEM_Iron_Helmet.asset`、`ITEM_Iron_Plate.asset`、`ITEM_Iron_Boots.asset`
    - `equippedSprite = null`
    - `visualOverride = null`
  - `Devon.prefab` / `0_Hero_Base.prefab`
    - 当前没有挂 `EquipmentSpriteLibraryUpdater`
  - `EquipmentSpriteLibraryUpdater` 只在 `MeleeAttackAbility.cs` 中有源码级引用，没有落到当前测试角色宿主

## 运行时验证结果
- 尝试执行：
  - `Unity.exe -batchmode -executeMethod DressUpSceneValidator.RunBatchValidation`
- 结果：
  - 验证器没有真正执行到
  - Unity 在进入项目之前就被环境拦截
- 失败原因：
  - `LocalLow/Unity` 权限失败
  - Unity Package Manager IPC 连接失败
- 对应日志：
  - `RecoveryNotes/dress-up-scene-validator-20260313-2.log`
  - `RecoveryNotes/dress-up-scene-validator-20260313-3.log`

## 当前结论
- 不能把这次 batchmode 失败当成 `SampleScene` 运行失败
- 当前可信结论是：
  - `换装可用` 仍待在真实 Unity Editor 环境里验证
  - `换装可见` 当前静态上还没有配置完成，不能默认成立
