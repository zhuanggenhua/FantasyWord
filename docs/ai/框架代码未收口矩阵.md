# 框架代码未收口矩阵

> 用途：只记录“文档已裁决，但代码还没彻底收口”的部分。
> 若要看已经成立的代码证据，先读 `框架代码现态矩阵.md`。
> 若要看谁该赢、为什么该赢，回到 `框架最终裁决.md`、`框架三项判分矩阵.md`、`三方框架系统对照.md`。

## 读取规则

- `已收口`：代码现态已经和裁决一致。
- `半收口`：方向已经对，但仍保留明显后续项。
- `未收口`：文档已裁决，但代码还没有形成正式实现。
- `禁止项`：文档已明确不能做，代码当前也不应出现。

## 一页结论

- 世界规则层和工具层主体已经收口。
- 动作表现层已经收口到“核心闭包成立”，但还没收口到“表现链完整”。
- UI 菜单运行时已经收口，当前只剩共享构件、旧资源残留和少量非菜单 utility panel 命名继续收尾；点击移动、实例宿主、出生点分流、开放世界模拟层仍是代码未收口区。
- `TopDownEngine` manager、`YokiFrame` 架构层当前没有误入正式运行时，这属于“边界已守住”，不是未收口。

## 当前最值得继续做的收口项

### 1. 表现链深化

这是当前最接近“已经在做，只差继续补”的一段。

已成立：

- `GameplayFeedbackSet` 已正式覆盖 `damage/heal/mana/temporal/death/loot/pickup/interaction` 核心表现上下文
- `CameraShake`
- `DamageScreenFlash`
- `CombatTextDisplay`

还没证明的部分：

- 更多相机表现是否已统一回到同一入口边界
- 更多屏幕表现是否已统一回到同一入口边界
- 更多 HUD 或日志类表现是否也沿同一上下文接入，而不是回退到业务通知或实体直连

所以这条线属于：

- `半收口`

### 2. UI 宿主后续收口

当前正式运行时代码里已经有：

- `UIManager + UIKitMenuPanelBase + UIKit` 原生 stack
- `Pause/Character/Abilities/Inventory/Journal/Save/Settings/Death/Shop/Craft` 这组正式菜单面板
- 对旧 `AUIMenu/UIMenuManager/UIMenuRegistry/MenuHostRuntimeOwnershipGuard/MenuRouteTopology` 的回归门禁

这说明当前结论已经不是“UI 还没迁”，而是：

- `宿主替换已完成`
- `代码侧唯一真相已锁到 UIKit 菜单 seam`
- `剩余工作集中在旧资源、共享构件和文档遗留清理`

所以这条线属于：

- `半收口`

### 3. 点击移动与导航

当前代码里已经存在：

- `InputSystem` 把点击输入转发到当前正式输入目标
- `PlayerController.NavigationRuntime` 负责 UI 遮挡、屏幕点转世界点和最近合法落点修正
- `Movable.MoveTo(destination, stoppingDistance, ...)` 负责当前 2D 直线靠近

这能证明：

- 第一阶段基础点击移动链路已经进入正式代码
- 当前点击移动链已经吸收了 `stoppingDistance`、UI 遮挡和最近合法落点修正这几条规则

它还不能证明：

- 已有完整点击移动正式闭包
- 已有导航 Provider
- 已有自动靠近续接动作入口

所以这条线属于：

- `半收口`

### 4. 开放世界模拟层

当前正式运行时代码里，以下命名搜索为 `0`：

- `WorldSystem`
- `WorldContext`
- `Faction`
- `Squad`
- `Economy`
- `Cell`
- `Worldspace`

这不是坏事，它只说明一件事：

- 当前没有误把空世界架构写出来

但也同时说明：

- 开放世界模拟层还没有进入正式实现

所以这条线属于：

- `未收口`

## 推荐下一步

如果继续按“最小成本、最大收口收益”推进，顺序应是：

1. 继续补表现链收口
2. 继续维持 UI 宿主审计与禁止项门禁，不提前写 `UIPanel` 业务样板
3. 在补齐一级参考前，不写点击移动/实例宿主/出生点分流代码
4. 开放世界模拟层等具体规格锁定后再建正式模块
