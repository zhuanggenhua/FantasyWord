# 2D移动与场景组织外部参考提交模板

> 用途：后面你给我外部新参考时，直接按这一页贴，避免我再反问字段。
> 本文只服务**提交参考**，不服务实现。
> 边界：本文只服务 `2D 移动与场景组织` 的 4 个一级缺口，不处理开放世界模拟层本身。

## 最短可用版本

至少给我这 5 项：

1. 仓库路径或 URL
2. 命中的一级缺口
3. 直接命中的源码文件
4. 你怀疑能直接搬的类或方法
5. 你怀疑它绑死了什么

如果能带文件定位，优先直接写成：

- `路径:行号`
- 或 `URL#Lxx-Lyy`

## 最好顺手补的 3 个小信息

这 3 项不是必须，但有的话能明显减少来回追问：

1. 这是**运行时代码**还是只编辑器工具
2. 该源码是服务**玩家专用**、**NPC 专用**，还是两者共用
3. 你觉得它更像落到我们现有哪一层：
   - `Movable`
   - `PlayerController`
   - `MapSystem`
   - `MapInfo`
   - `Teleporter`
   - 仍看不出来

## 如果你愿意多补一点，最值钱的是这些

### 命中缺口 1：单机/本地 2D 导航 Provider

最好额外补：

- 如何判断“当前是否在导航”
- 如何取消旧导航
- 如何修正到最近合法落点
- 停止半径在哪里处理

### 命中缺口 2：2D 点击移动执行闭包

最好额外补：

- 点地源码
- UI 遮挡判定源码
- 目标修正源码
- 路径取消源码
- 到达停止距离源码

### 命中缺口 3：单机/本地场景实例宿主参考

最好额外补：

- 实例入口字段
- 实例归属字段
- 实例边界字段
- 实例内出生点字段
- 实例清理方法

### 命中缺口 4：单机/本地出生点分流宿主参考

最好额外补：

- 分流规则挂在哪
- 默认回退逻辑
- 失败处理逻辑
- 入口点索引 / 入口点标识

## 直接不要发这类参考

- 只有视频，没有源码
- 只有 README，没有运行时代码
- 只有 `NavMeshAgent` / `CharacterController` 包装
- `Mirror + 3D CharacterController` 玩家移动体系
- 已经在本机判退过的 `uMMORPG MovementSystems` 负证据文件
- 只有 3D 鼠标点地 demo
- 只有传送门，没有实例宿主
- 只有出生点数组，没有分流宿主
- 只有安全区 trigger / 区域 gizmo，没有正式区域或实例宿主
- 只有“死亡后显示复活按钮”的 UI，没有正式重生/出生点宿主
- 只有怪物自己记 `startPosition + respawnTime` 的自复活状态机
- 只有一张产品型 `World.unity` 大场景，但看不到正式实例/分流宿主源码

补充说明：

- 这些内容不是“完全没价值”，而是当前只会形成局部规则证据，不能直接关闭 4 个一级缺口。
- 典型假阳性就是 `uMMORPG` 里的 `SafeZone.cs`、`UIRespawn.cs` 和怪物自复活状态机：它们能证明局部行为该怎么做，但不能证明当前项目已经找到了实例宿主、区域宿主或出生点分流宿主。
- 另外一类不用再重复提交的是 `uMMORPG` 的旧移动目录负证据：`NavMeshMovement.cs`、`RegularNavMeshMovement.cs`、`PlayerCharacterControllerMovement.cs`、`CharacterController2k.cs` 当前都已经固定判退；除非你发现的是这个目录里的**新文件**，否则没必要再拿这几份来让我重判一遍。
