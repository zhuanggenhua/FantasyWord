# 角色素材处理工作流

## 适用范围

- 本文规范俯视角像素角色素材从来源图、切片、动画、装备层到 Prefab 的处理流程。
- 当前重点是 MiniFantasy 类四向/八向像素角色和装备换装素材。
- 本文不继承横版角色的脚底锁点、平台动作偏移或 Swordmaster 专项流程。

## 真相源

- 原始素材包保留在 `Assets/Art`、`Assets/ArtRes`、`Assets/Minifantasy_NPCs_Assets`、`Assets/Sprites` 或 `Assets/ThirdParty` 的明确来源目录。
- MiniFantasy UV 证据保留在 `docs/archive/mini-fantasy-uv-evidence`，用于追溯资源和 GUID，不作为运行时目录。
- 旧恢复任务中的角色和 UI 资产若脚本断裂，只能作为 `docs/archive/legacy-rpg-assets` 参考，不直接恢复为正式 Prefab。

## 导入约束

- 像素贴图默认使用 `Texture Type = Sprite (2D and UI)`。
- 固定网格角色图优先使用 `Sprite Mode = Multiple`。
- 像素素材默认 `Filter Mode = Point`、`MipMap = Off`、压缩策略按平台和清晰度另行确认。
- 动画必须引用导入后的 Sprite 子资源；不得把运行时 `Sprite.Create` 生成的临时 Sprite 写入正式动画资产。
- 移动素材、动画、Sprite Library、Animator Controller 和 Prefab 时必须保留 `.meta`。

## 俯视角表现约束

- 方向维度优先支持 `S/SE/E/NE/N/NW/W/SW` 或素材包已有方向命名。
- 角色表现要区分：基础身体层、装备层、动画状态、方向、动作和特效。
- 装备表现优先走 `EquipmentSystem` 候选框架审查，不把装备 Sprite 直接硬塞到场景对象。
- 采集、制作和交互动画要能被世界对象或角色状态驱动，不写死在素材包 demo manager 里。

## 处理步骤

1. 锁定素材来源、授权、路径和 `.meta`。
2. 判断素材是原图、处理版、demo 场景、demo Prefab、正式候选 Prefab 还是历史证据。
3. 对原图和动画保留来源结构；对 demo 场景归档；对可复用 Prefab 暂保留并后续逐项纳入正式闭包。
4. 角色进入正式链路前，建立角色数据、表现配置、Animator/AnimationClip、Prefab 和验证入口。
5. 装备或换装进入正式链路前，先补 `EquipmentSystem` 的逐文件参考记录和数据闭包检查。

## 不要继续硬修的情况

- 资源缺脚本但不清楚来源时，不要直接补一个同名空脚本。
- demo 场景能打开不等于它是正式场景。
- 素材包 Prefab 能显示不等于它已经满足项目角色、交互或战斗合同。
- 发现 Sprite Library、Animator 或 Prefab 断引用时，先追溯 GUID 和包依赖，不直接删除。

## 验证顺序

- 静态阶段：路径、`.meta`、GUID、脚本引用、Prefab/动画引用。
- Unity 阶段：迁移完成后刷新资源、检查 Console、跑编译和定向 EditMode。
- 可视阶段：只有需要确认真实画面时，再通过 AIBridge 或人工打开对应场景/Prefab。
