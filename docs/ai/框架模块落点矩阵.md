# 框架模块落点矩阵

> 用途：把“直接替换 / 正式融合 / 暂不动”三类裁决，压到 `GameCore` 的具体文件落点。
> 这份文档不重新决定胜负，只回答“这项裁决现在到底落在哪些代码里”。

## 读取规则

- `正式拥有者`：这项职责最终归谁。
- `当前落点`：当前项目里真正承载这项职责的文件。
- `状态`：
  - `已收口`：代码落点已和裁决一致。
  - `半收口`：主要落点已成立，但还存在后续深化项。
  - `未收口`：文档已裁决，但代码还没有正式落点。

## 暂不动落点

| 模块 | 当前边界 | 当前代码证据 | 状态 | 说明 |
| --- | --- | --- | --- | --- |
| `TopDownEngine` manager / 输入 / GUI / Level 生命周期 | 禁止升格为正式入口 | 当前正式运行时代码对 `InputManager / GUIManager / LevelManager` 只有注释与 Tooltip 命中 | 已守住边界 | 说明吸收的是模式，不是 manager 本体 |
| `YokiFrame` 架构层 | 禁止接管生命周期 | 当前正式运行时代码未见 `Architecture/EventKit/SingletonKit` 进入 | 已守住边界 | 说明引入的是工具，不是框架生命周期 |
| UI 全量迁 `UIKit` | 已进入正式运行时代码 | `UIManager` 菜单 seam、`UIKitMenuPanelBase` 与正式菜单面板当前都已存在 | 半收口 | 宿主替换已完成；剩余不是“要不要迁”，而是继续清旧资源、共享构件和文档口径 |
| 第一阶段点击移动 / 双模式切换 | 已进入正式代码，但只限基础链路 | `Controllers/PlayerController.cs`、`Controllers/PlayerController.NavigationRuntime.cs`、`Game/Systems/InputSystem.cs`、`Entities/Movable.cs` | 半收口 | 当前已存在 `Directional + ClickToMove` 两种正式移动模式，点击链也已包含 UI 遮挡、最近合法落点修正和 `MoveTo(..., stoppingDistance)` 直线靠近；输入路由真相现已直接回到 `InputSystem` 本体，不再额外保留 `InputGameplayRoutingRuntime` 这类中间 helper；但它还不是完整 2D 导航 Provider，更不是自动靠近后续接动作闭包 |
| 自动靠近 / 控制组穿越 / 实例入口 | 暂不进入正式代码 | 当前已有 `InputSystem -> PlayerController.NavigationRuntime -> Movable.MoveTo(..., stoppingDistance, ...)` 的第一阶段基础点击移动链，但仍没有完整导航 Provider、自动续接动作、实例宿主或出生点分流宿主 | 未收口 | 还缺完整导航 Provider、自动续接动作、实例宿主和出生点分流宿主 |
| 实例宿主 / 出生点分流宿主 | 暂不进入正式代码 | 正式运行时代码对 `WorldSystem / WorldContext / Spawn host` 类命名命中 `0` | 未收口 | 还缺一级正式参考 |
| 开放世界模拟空壳 | 禁止先写空架构 | `WorldSystem`、`Faction`、`Squad`、`Economy`、`Cell` 等命中 `0` | 已守住边界 | 当前没有误把空世界架构提前写出来 |
