# 框架与运行时入口

## 适用范围

- 本文定义 `FantasyWord` 的运行时目录、框架级能力和正式边界。
- 本项目是俯视角开放世界像素游戏，不沿用 `dark-corridor` 的横版平台动作运行时合同。
- 当前没有 OpenSpec 目录时，阶段状态以 `AGENTS.md`、`docs/ai/` 和当前提交记录为准。

## 正式运行时方向

- 先建立单机核心，再评估小规模联机。
- 核心规则放在项目侧 C#、ScriptableObject 和可审计数据中。
- 场景、Prefab、Animator、Tilemap 和 UI 只承载初始引用、视觉表现和编辑辅助。
- 联机预留只影响边界设计：输入、世界事件、存档状态和表现层要能拆开；当前不创建网络空框架。

## 目录边界

- `Assets/Scripts/GameCore`：游戏启动、系统生命周期、事件、时间、存档、资源门面和共享基础抽象。
- `Assets/Scripts/Characters`：玩家、NPC、怪物、角色控制、角色状态和角色数据。
- `Assets/Scripts/World`：地图、区域、采集点、交互对象、场景对象和世界状态。
- `Assets/Scripts/Items`：物品、装备、背包、掉落、制作和装备表现。
- `Assets/Scripts/Combat`：伤害、技能、状态效果、命中、目标选择和 EX-GAS 项目侧接入。
- `Assets/Scripts/Presentation`：动画、角色表现、相机、视觉反馈、音效触发和表现层适配。
- `Assets/Scripts/Networking`：只有小规模联机进入正式目标后才创建。
- `Assets/GameData`：项目侧 ScriptableObject、配置、数据库和可 diff 设计数据。
- `Assets/Editor`：人工可理解、低误点风险的正式编辑器工具。
- `Assets/Tests`：Unity Test Framework 测试和验证夹具。

## 当前已存在能力

- `Assets/Scripts/Items/EquipmentSystem`：装备/换装表现框架候选，不是临时垃圾；后续要继续审查命名空间、菜单入口、运行时依赖和正式落点。
- `Assets/GameData/EquipmentSystem`：装备/换装相关数据候选。
- `Assets/ThirdParty/MiniFantasyUV`：MiniFantasy UV 资源/来源链候选。
- `Assets/Plugins/GAS`：EX-GAS 插件本体；项目侧正式接入代码应放在 `Assets/Scripts/Combat/EXGAS`。
- `Assets/Plugins/JKFrame`：底层工具与框架候选；是否成为正式运行时底座要按俯视角开放世界职责审查。

## 输入、世界与表现边界

- 输入层只产生玩家意图，不直接修改世界状态。
- 世界层消费意图、交互和事件，推进可保存的状态。
- 表现层只订阅状态和事件，负责 Animator、Sprite、音效、特效和相机反馈。
- 交互、战斗、采集、制作和背包不得把核心规则写死在 UI 回调或单个场景实例里。

## 联机预留边界

- 不提前绑定 NGO、Mirror 或其它网络框架。
- 未来若进入联机评估，先区分输入来源、控制权、阵营、对象归属、世界状态和表现事件。
- 小规模联机优先考虑房主权威或轻量会话；不按 MMORPG 服务器架构预设当前代码。

## 禁止误用

- 不把素材包 demo 脚本、demo 场景或旧恢复 Prefab 当作正式运行时入口。
- 不把 `dark-corridor` 的横版玩家控制器、横版相机、横版测试场景迁入正式框架。
- 不为空目录堆架构；只有能力进入正式范围时才创建对应目录和代码。
- 不让玩法代码散落直接依赖第三方插件 API；需要项目侧门面或服务边界。
