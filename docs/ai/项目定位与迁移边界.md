# 项目定位与迁移边界

## 当前定位

- 游戏类型：俯视角开放世界像素游戏。
- 核心体验：高自由度探索、交互、采集/制作、角色成长、战斗、物品与世界状态积累。
- 联机方向：候选功能，只考虑几人小规模联机；不以 MMORPG 为目标。
- 当前阶段目标：先完成工程地基、AI 规范、工具链迁移和目录重整，再决定玩法系统迁移顺序。

## 不继承的旧目标

- 不继承旧 `FantasyWorld` 恢复任务的用户故事、单场景换装验收、旧主线剧情或旧任务阶段。
- 不继承 `dark-corridor` 的横版平台动作定位、横版玩家控制器、横版相机和横版测试场景。
- 不把旧 `task_plan.md`、`findings.md`、`progress.md` 中的阶段状态当成当前任务目标。

## 可以复用的内容

- `dark-corridor` 的 AI 规范分层、AIBridge 接入方式、工程门禁、参考矩阵方法、目录治理方法。
- 旧 `FantasyWord` 工程中仍适合俯视角开放世界的资产、像素素材、装备/换装实验、数据结构线索。
- 旧恢复文档中的事实线索，例如哪些旧资源损坏、哪些插件曾被依赖、哪些路径曾被验证过。

## 迁移原则

- 先迁工程地基和规范，再迁插件，再迁代码目录，再迁场景和资源。
- 可直接复制的规范和工具链优先复制，但必须改成 `FantasyWord` 的产品口径。
- 旧代码只在职责仍成立、文本健康、依赖明确、不会把旧用户故事带回来时才进入当前正式链路。
- 旧插件按“依赖核验”处理；只有插件行为要决定正式功能设计时，才升级为参考矩阵。
- 联机只做架构预留，不先引入大规模网络框架或复杂同步方案。

## 当前迁移顺序建议

1. 建立 `AGENTS.md` 和 `docs/ai/`。
2. 替换旧 UnityMCP 为当前 AIBridge。
3. 归档旧恢复文档和旧自动化脚本。
4. 重整 `Assets` 顶层目录，区分正式资源、第三方资源、实验资源和历史恢复残留。
5. 重新定义俯视角玩家、相机、地图、交互和数据系统的参考面。
