# 素材处理工具入口

## 适用范围

- 本文记录 `FantasyWord` 当前和后续可复用的像素素材处理工具入口、使用边界和验证方式。
- 当前项目还没有正式沉淀通用 SpriteSheet 编辑器工具；已有重点是 MiniFantasy 素材、装备换装数据和未来俯视角角色导入流程。
- 不继承 `dark-corridor` 的横版 Swordmaster 专项工具入口。

## 使用顺序

- 需要判断素材目录和导入规则时，先读 `素材与表现规范.md`。
- 需要处理角色 SpriteSheet、方向动画和装备层时，再读 `角色素材处理工作流.md`。
- 需要把某个处理流程沉淀成工具时，先在本文登记工具目标、输入、输出和验证方式。

## 当前工具候选

- 工具：装备/换装数据与 UV 处理工具
- 当前落点：`Assets/Scripts/Presentation/EquipmentSystem/Editor`、`Assets/Scripts/Presentation/EquipmentSystem/Tools`
- 适用场景：装备帧数据、动画序列、像素皮肤映射、MiniFantasy UV 数据追溯和装备表现数据维护。
- 当前状态：随换装表现模块晋升为正式工具入口，后续仍按具体资产处理流程补验证。
- 验证方式：迁移完成后做菜单入口、ScriptableObject 数据闭包、Prefab/Scene 引用和编译检查。

- 工具：第三方素材包原始导入链
- 当前落点：`Assets/Art`、`Assets/ArtRes`、`Assets/Minifantasy_NPCs_Assets`、`Assets/Sprites`
- 适用场景：保留原始像素素材、动画、Prefab 和导入设置。
- 当前状态：第三方素材包原始结构整体保留，包含 demo 场景和示例脚本；它们是迁移来源，不得擅自挪出原目录。
- 验证方式：静态路径/GUID 检查，Unity 导入后检查 Console 和缺失引用。

## 后续工具沉淀标准

- 工具必须说明输入资产、输出资产、是否改 `.meta`、是否生成新资源。
- 正式工具应优先支持批处理、可重复执行和可静态审计。
- 一次性修复脚本不能直接变成长期菜单入口；除非它对人工也有明确价值且低误点风险。
- 任何会改动 Sprite、AnimationClip、AnimatorController、Prefab 或 ScriptableObject 的工具，都要有回读验证方式。

## 不适用内容

- 不把素材包 demo scene 的 manager 当作项目素材处理工具。
- 不把旧恢复任务中的 batchmode 日志或 smoke 脚本恢复成当前正式工具。
- 不为还没进入正式范围的联机、地图生成或角色编辑器预先创建工具入口。
