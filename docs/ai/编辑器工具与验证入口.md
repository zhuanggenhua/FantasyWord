# 编辑器工具与验证入口

> 本文记录 `FantasyWord` 的 Unity Editor 工具、AI 自动化入口和验证边界。本文不记录当前任务进度。

## 适用范围

- 人工会在 Unity Editor 菜单、Inspector 或窗口中主动使用的工具。
- AI 通过 AIBridge 调用的后台自动化入口。
- 一次性迁移、排查、截图、批量修复脚本的去留规则。

## 入口分层

- `HumanMenu`：人工菜单入口。只保留人类能理解、会主动使用、误点风险低的正式工具。
- `AutomationOnly`：AI 自动化入口。测试、验证、批量迁移、结构扫描默认属于这一类，不默认暴露顶部菜单。
- `InternalTemporary`：一次性或阶段性入口。任务完成后必须删除、归档或转成正式入口。

## 当前状态

- 当前正式自动化通道是 `AIBridge`：`.codex/skills/aibridge` 与 `Packages/com.aibridge.unity`。
- `Assets/Editor` 当前没有正式工具文件；后续新增前必须先声明入口类型和 owner。
- 旧 UnityMCP 安装器、旧连接配置和旧 MiniFantasy UV smoke 脚本已退出正式入口。

## 新增工具规则

- 不为了让 AI 调用而默认新增顶部 `MenuItem`。
- 一次性探针不得长期留在 `Assets/Editor`。
- 只读验证入口不得在验证过程中补建、保存或重写正式资产。
- builder / verifier / authoring utility 要职责分开：构建只构建，验证只验证，Inspector 只编辑资产。
- 只服务单个文件或单次排查的 helper，不得包装成公共 API。

## 验收方式

- 文档和目录调整：静态搜索确认入口不存在或已登记。
- 包和 ProjectSettings 调整：必要时用 AIBridge 查询 Editor 状态和 Console。
- 场景、Prefab、资源写入：先静态确认引用，再按最低充分原则升级到 Unity 验证。
