# 2D移动与场景组织找参考清单

> 本文是给后续找新参考时用的短清单。
> 只回答三件事：现在到底缺哪几类参考、什么样的源码一看就合格、什么样的一看就不用继续看。

## 适用范围

- 只服务当前 `FantasyWord` 在 **2D 移动** 与 **场景组织** 上的参考筛选。
- 不代替 `2D移动与场景组织缺口矩阵.md`；那边是完整台账，这里是快速筛选单。
- 不讨论业务功能，不允许因为“看起来能跑”就先写空壳。
- 不覆盖开放世界模拟层本身；区域/Cell、队伍、派系、AI 日程、经济和局部模拟仍是另一层长期架构任务。

## 先看这 4 个一级缺口

| 缺口 | 现在要找什么 | 一句话判断 |
| --- | --- | --- |
| 单机/本地 2D 导航 Provider | 2D 运行时代码，能回答导航能力、落点合法性、停止半径、导航取消 | 找“正式移动真相”，不是找 UI 点击脚本 |
| 2D 点击移动执行闭包 | 2D 点击寻路代码，能回答点地、挡 UI、目标修正、路径取消、停止距离 | 找“完整点击移动链”，不是只找鼠标射线 |
| 单机/本地场景实例宿主参考 | 单机都能成立的实例模板/实例运行时宿主 | 找“实例怎么组织”，不是找副本传送门 |
| 单机/本地出生点分流宿主参考 | 能按入口/模板/条件分流出生点，并有默认回退 | 找“出生点路由宿主”，不是找散落 if/else |

## RTS / 3D 参考口径

- RTS 参考只有在提供**可脱离 3D NavMesh 与 RTS 业务**的完整运行时代码时，才可能闭合当前移动缺口；若只能提供命令链、职责拆分或局部规则，它就只算职责证据或架构样板。
- 3D RTS 参考也可以看；若核心是网格、图搜索、流场或维度无关的移动执行，可以考虑映射到当前 2D 闭包。
- 如果参考强绑 `NavMeshAgent`、3D 射线、3D Collider、CharacterController 或高度语义，它仍有职责样板价值，但不能单独证明当前 2D `Rigidbody2D + Sprite` 路线已经可以直接搬。
- 当前项目确定会做有限联机，但当前阶段不实现联机；参考是否绑定 Mirror/服务器权威仍是判退点，因为那会把移动真相绑到网络生命周期，而不是当前单机闭包。

## 每个缺口最低要看到什么

### 1. 单机/本地 2D 导航 Provider

至少要看到：

- 当前角色是否能导航
- 当前是否在移动
- 目标点是否可落地
- 不可落地时如何修正到最近合法点
- 停止半径怎么定义
- 手动输入或其它动作如何取消旧导航
- 玩家和 NPC 是否共用同一导航真相

直接排除：

- `Mirror`
- `NavMeshAgent`
- `CharacterController`
- 只支持 3D 地面
- 只有接口，没有运行时代码

### 2. 2D 点击移动执行闭包

至少要看到：

- 鼠标/触摸点如何命中地面
- 点到 UI 上时如何拒绝落地
- 目标点如何修正到最近合法落点
- 旧路径如何被 WASD/摇杆/新点击取消
- 到达判定是否支持停止半径
- 目标指示器是不是正式链的一部分，还是纯表现

直接排除：

- 只有 `ScreenPointToRay`
- 只有 3D 平面射线
- 只有 demo 视频，没有源码
- 只有 “点击后 MoveTowards/lerp” 这种无路径闭包

### 3. 单机/本地场景实例宿主参考

至少要看到：

- 实例入口挂在哪
- 实例归属怎么表达
- 实例边界怎么定义
- 实例内出生点怎么挂
- 离场清理归谁
- 实例运行时位置怎么稳定重建

直接排除：

- 只是一对传送门
- 只是“创建/查找副本后把人传进去”的入口脚本
- 只是在传送脚本里写场景名
- 强绑队伍副本、网络实体清理、Interest 管理
- 强绑 3D 边界和 `NavMeshSurface`

### 4. 单机/本地出生点分流宿主参考

至少要看到：

- 分流规则挂在哪个正式宿主
- 入口类型有哪些：地图入口、角色模板入口、条件入口
- 找不到专用出生点时如何回退
- 分流失败时如何处理
- 是否能和默认出生点共存

直接排除：

- 把分流写在传送门脚本里
- 把分流写在角色 Prefab 初始化里
- 把分流散在多个地图脚本 if/else 里
- 强绑 `Mirror` 出生点或角色创建流程

## 当前已知候选，先别误判

| 来源 | 现在能证明什么 | 现在不能证明什么 |
| --- | --- | --- |
| `uMMORPG Movement.cs` | 移动/导航/传送/出生点合法性应拆开；停止半径是正式合同 | 不能提供当前项目可直接搬的 2D 导航 Provider |
| `uMMORPG PlayerNavMeshMovement.cs` | 点击目标应先修正到最近合法落点；手动输入应取消旧路径 | 不能提供当前项目可直接搬的 2D 点击移动闭包 |
| `uMMORPG PlayerCharacterControllerMovement.cs + CharacterController2k.cs` | 只能证明 `uMMORPG` 还有一套 Mirror 本地玩家 + 3D CharacterController 移动体系 | 它不是当前项目要的 2D 导航 Provider，也不是 2D 点击移动闭包 |
| `uMMORPG Instance.cs` | 实例宿主至少要显式承载入口、归属、边界、实例内出生点和清理策略 | 不能直接作为当前单机场景实例宿主实现 |
| `uMMORPG PortalToInstance.cs` | 只能证明“副本入口脚本”应把创建/查找实例与传送到实例入口串起来 | 它不是实例宿主本身，不能替代单机/本地实例宿主参考 |
| `uMMORPG GetStartPositionFor(...)` | 出生点分流应有正式宿主，找不到专用入口时应回退默认入口 | 不能直接作为当前项目出生点分流实现 |
| `Assets/Plugins/AStar 2D Grid Pathfinding` | 2D 网格 A*、world/grid 映射、点击取格和路径点跟随可以脱离 `NavMeshAgent` 单独成立 | 不能直接作为当前项目导航 Provider 或点击移动闭包，因为它仍停在 demo 单例、旧 `Input` 测试脚本和 `MoveTowards` 跟随层 |
| `2DRPGEngine NodeCanvas Pathfinding` | 只能证明 `NavMeshAgent` 任务常见写法会用 `stoppingDistance`、`SetDestination` 和 `ResetPath` | 它仍是 3D `NavMeshAgent` 包装，不是当前项目要的 2D 导航/点击移动正式闭包 |
| `TopDown MouseDrivenPathfinderAI3D.cs + CharacterPathfinder3D.cs` | 路径点击职责应集中到正式路径执行层 | 当前只有 3D NavMesh 样板，没有 2D 点击寻路正式闭包 |
| `TopDown GoToLevelEntryPoint.cs + GameManager.StorePointsOfEntry(...)` | 只能证明“跨场景入口索引”最好先存到正式宿主，再在目标场景按入口点解析 | 它仍强绑 `GameManager.Instance`、场景切换和单玩家入口流，不能直接作为当前出生点分流宿主 |
| `TopDown LevelManager.cs + CheckPoint.cs` | 单场景出生点、检查点顺序、重生延迟、边界、Points of Entry 应有显式宿主 | 不能补实例宿主，也不能补单机/本地出生点分流宿主 |
| `TopDown MultiplayerLevelManager.cs` | 只能证明“多玩家可以各自从一组 CheckPoint 生成”，以及分屏/群组相机模式如何切 | 它不是实例宿主，也不是出生点分流宿主；只是 `LevelManager` 的多人本地生成扩展 |
| `RTS Starter Kit` 当前路径 | 已确认真实源码位于 `Assets/InsaneSystems/RTSStarterKit`；能证明输入/选择、订单对象、单位订单队列、组下发和阵型落点是一条成熟命令链 | 不能直接补 2D 导航 Provider；其移动执行强绑 3D `NavMeshAgent`、3D 射线、旧 `Input` 和 RTS 业务。当前只算职责证据与架构样板，不是可直接搬的正式移动闭包 |

## 你后面给我参考时，最少带这 6 项

1. 参考路径
2. 命中的一级缺口
3. 直接命中的源码文件
4. 你觉得能直接搬的那几个方法/类
5. 它绑了什么，不一定能搬
6. 你想让我判断的是：`直接吸收` 还是 `只登记`

## 当前不该继续找的东西

- 3D 鼠标寻路 demo
- 只讲设计思路的视频
- Mirror/MMORPG 副本体系
- Mirror + 3D `CharacterController` 玩家移动体系
- `NavMeshAgent` 任务包装层
- 只负责“建副本后把人传进去”的入口脚本
- 只有传送门，没有实例宿主
- 只有出生点数组，没有分流宿主
- 只有输入脚本，没有导航真相
