# 2D移动与场景组织下一步入口

> 用途：把这条线压成最短可执行入口。
> 只回答 4 件事：项目里现在到底有没有正式移动闭包、还缺什么、本机参考池现在处于什么状态、下一步该怎么做。

## 先定任务性质

当前这条线的主任务不是补新控制器，也不是继续追端到端验证，而是：

1. 参考裁决
2. 缺口登记
3. 文档和 spec 收口

补充口径：

- formal scene 最小 PlayMode smoke 已经补过，当前不再把“场景还没重跑”当成总阻塞。
- 这不等于 4 个一级缺口已经闭合，也不等于现在可以绕过参考直接进入实现。

## 当前不是“项目里没有控制器”

当前项目内已经有正式移动闭包：

- `Assets/Scripts/GameCore/Runtime/Entities/Movable.cs`
- `Assets/Scripts/GameCore/Runtime/Entities/Movable.MotionRuntime.cs`
- `Assets/Scripts/GameCore/Runtime/Controllers/PlayerController.cs`
- `Assets/Scripts/GameCore/Runtime/Controllers/PlayerController.NavigationRuntime.cs`
- `Assets/Scripts/GameCore/Runtime/Game/Systems/InputSystem.cs`

当前已经存在两种正式移动模式入口：

1. `Directional`
2. `ClickToMove`

这代表：

- 现在缺的不是“先造一个控制器”
- 而是“补齐还没有正式参考的那几块真相”
- 点击移动当前已经有基础链路：`InputSystem` 转发输入，`PlayerController.NavigationRuntime` 负责 UI 遮挡、屏幕点转世界点、最近合法落点修正和 `MoveTo(..., stoppingDistance)` 直线靠近

## 当前只剩 4 个一级缺口

1. 单机/本地 2D 导航 Provider
2. 2D 点击移动执行闭包
3. 单机/本地场景实例宿主参考
4. 单机/本地出生点分流宿主参考

依赖这 4 个一级缺口的二级缺口，当前仍只登记：

- 控制对象与世界穿越目标统一
- 超距后自动靠近再施法/交互
- 传送入口条件

## 本机参考池当前结论

### `uMMORPG`

当前只算局部源码证据源：

- 能补移动合同、停止半径、最近合法落点、手动输入取消旧路径这类规则
- 能补“实例宿主/出生点分流宿主至少该负责什么”这类职责证据

不能直接搬的部分：

- `Mirror`
- `NavMeshAgent`
- 3D `CharacterController`
- MMORPG 角色创建流
- 副本归属与网络实例生命周期

### `Assets/Plugins/AStar 2D Grid Pathfinding`

当前能证明：

- 单机/本地 2D 网格 A*、world/grid 映射、路径点跟随可以独立成立

当前不能直接关闭缺口，因为还缺：

- 正式导航状态
- 停止半径正式合同接线
- 路径取消
- UI 遮挡
- 与 `Movable / PlayerController` 的正式整合

### `TopDownEngine`

当前只得到：

- 3D pathfinder 样板
- 2D/3D 共用的网格步进/占格系统样板
- 单场景入口索引与检查点样板
- 局部 respawn / 选角 / 场景跳转薄脚本

当前没有拿到：

- 可直接搬的 2D 点击寻路正式闭包
- 可直接搬的单机实例宿主
- 可直接搬的单机出生点分流宿主

### `RTS Starter Kit`

当前只适合作为：

- 输入/选择 -> 订单对象 -> 单位订单队列 -> 移动执行 的架构样板
- 追加命令、停止命令、组下发、阵型落点的职责证据
- 开局生成点路由样板

当前不能直接搬成当前项目正式移动真相，因为它强绑：

- 3D `NavMeshAgent`
- 3D `Physics.Raycast`
- 旧 `Input`
- RTS 对局业务

## 当前正确动作

当前正确动作只有两类：

1. 继续登记新参考
2. 只在已有源码证据已经足够时，吸收最小规则/合同补强

当前不该做：

- 不再回头把本机旧参考重复翻一遍
- 不新建 `NavigationProvider`
- 不新建 `ClickMoveController`
- 不新建 `InstanceHost`
- 不新建 `SpawnRoutingHost`
- 不因为“还差一点”就先补并行实现

## 你后面给我新参考时，最少带这 6 项

1. 参考路径或 URL
2. 命中的一级缺口
3. 直接命中的源码文件
4. 你怀疑能直接搬的类或方法
5. 它强绑了什么
6. 你要我判断的是：`直接吸收` 还是 `只登记`

## 后续处理顺序

1. 先看 `docs/ai/2D移动与场景组织现态速查表.md`
2. 再看 `docs/ai/2D移动与场景组织找参考清单.md`
3. 再按 `openspec/changes/define-fantasyword-foundation-framework/movement-scene-reference-intake.md` 填 intake
4. 最后只做 3 种裁决之一：
   - `直接吸收`
   - `只登记`
   - `放弃`
