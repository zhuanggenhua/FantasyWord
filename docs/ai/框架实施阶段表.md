# 框架实施阶段表

> 用途：把 `FantasyWord` 当前地基从“裁决正确”推进到“执行顺序正确”。
> 本表不回答“现在哪些代码已经存在”，只回答“接下来什么该先做、什么该后做、什么现在绝对不能硬做”。
> 若需要先看“这个模块到底属于直接替换、正式融合还是暂不动”，先读 `框架正式动作清单.md`；本表只负责时间顺序。

## 使用规则

- 阶段顺序服从 `设计模式 / 软件工程 / 易用` 三项裁决，不服从“现在仓库里先有什么”。
- 每个阶段只做该阶段定义的 `直接替换 / 正式融合 / 暂不动` 动作。
- 任何阶段若命中 4 个一级缺口，就先停在缺口取证，不得绕过。

## 阶段总览

| 阶段 | 目标 | 主动作 | 当前状态 |
| --- | --- | --- | --- |
| `S0` | 锁定唯一正式地基与目录边界 | 撤出旧自造地基，锁定 `GameCore/Editor/Plugins` 边界 | 已完成静态收口 |
| `S1` | 完成必须直接替换的薄弱模块 | 对象池、武器执行、动作阻断、旧兼容地基退场 | 已完成主体收口，后续只补局部深化 |
| `S2` | 完成必须正式融合的一层 | 地图表现配置、受击表现、存档文件层、输入重绑定、前台角色边界 | 已完成主体收口，仍有反馈/UI 后续项 |
| `S3` | 卡住一级缺口前不得越线的动作层后续 | 点击移动、自动靠近、实例宿主、出生点分流先补参考 | 未完成，当前真实阻塞点 |
| `S4` | 开放世界模拟层正式开工 | 区域/Cell、队伍、派系、AI 日程、经济/局部模拟逐个建规格 | 未开始 |

## S0 地基锁定

### 本阶段必须成立

- 正式生命周期只保留 `GameManager + AGameSystem + GameConfig`
- 正式目录边界只保留：
  - `Assets/Scripts/GameCore/Runtime`
  - `Assets/Editor/GameCore`
  - `Assets/Plugins/*`
- 旧 `Bootstrapper/RuntimeContext/ModuleInstaller/EventBus` 不得再作为正式入口

### 本阶段不允许做

- 不允许恢复旧自造地基
- 不允许新增 `Compatibility/Adapter/Wrapper/Facade/FoundationSupport`
- 不允许把 `TopDownEngine` 或 `YokiFrame` 生命周期抬成正式总入口

### 验收口径

- 静态门禁通过
- 旧入口搜索结果为 0
- 目录裁决已写进正式文档

## S1 直接替换阶段

### 目标

把三项标准已经明显胜出的薄弱模块直接换掉，不再保留“双轨试用期”。

### 本阶段该替换什么

| 系统 | 胜者 | 正式动作 | 当前口径 |
| --- | --- | --- | --- |
| 对象池 | `YokiFrame` | 项目侧浅池退场，统一改 `GameObjectPoolService` | 已完成主体收口 |
| 武器执行层 | `TopDownEngine` | `2DRPG` 薄攻击执行退场，改成 TopDown 风格武器状态机 | 已完成主体收口 |
| 动作阻断模型 | `TopDownEngine` | 分散的 `CanFire/Can/IsPushed` 退场，统一改权限合同 | 已完成第一段收口 |
| 旧兼容地基 | 无保留价值 | 旧自造入口彻底退场 | 已完成静态收口 |

### 本阶段不允许做

- 不允许保留“新旧两套攻击执行先并跑”
- 不允许为了保险再补一层包装入口
- 不允许把第三方 manager 一起搬进来

### 验收口径

- 项目侧重复浅实现搜索结果收口
- parity / 门禁不再登记旧入口为正式实现
- 新正式入口都回到 `GameCore` 或稳定工具入口

## S2 正式融合阶段

### 目标

把“真相源必须留一套，但某些能力明显该吸收另一边”的系统收成单一正式入口。

### 本阶段该融合什么

| 系统 | 真相源 | 吸收来源 | 当前口径 |
| --- | --- | --- | --- |
| 地图、检查点、传送、重生 | `2DRPG MapSystem` | `TopDown Level/Checkpoint` 的边界、出生点、重生延迟、相机样板 | 已完成基础配置收口 |
| 生命数值与受击表现 | `RPG Stats` | `TopDown` 的击退、无敌帧、反馈样板 | 已完成主体收口，反馈仍待深化 |
| 存档 | `2DRPG SaveDataBlock` | `YokiFrame SaveKit` 文件承载 | 已完成当前融合 |
| 输入 | `GameCore InputSystem` | `YokiFrame InputKit` 重绑定工具 | 已完成当前融合 |
| 背包真相与角色操作目标 | 全局 `InventorySystem` | 当前控制角色边界 | 已完成当前收口 |
| 前台角色回退规则 | `PlayerSystem` | 各 UI/表现/拾取调用点统一回收 | 已完成当前收口 |

### 本阶段不允许做

- 不允许把 `TopDown Health` 升成生命真相
- 不允许把 `SaveKit` 升成世界状态模型
- 不允许为 UIKit 提前建两套 UI 栈适配层

### 验收口径

- 正式入口只有一套
- 相关调用点不再散落 `?? PlayerInstance` 或旧静态别名
- 插件边界门禁保持为 0

## S3 一级缺口阻塞阶段

### 目标

明确哪些动作现在不能靠“先写一个能跑的版本”推进。

### 当前 4 个一级缺口

1. 单机/本地 2D 导航 Provider
2. 2D 点击移动执行闭包
3. 单机/本地场景实例宿主参考
4. 单机/本地出生点分流宿主参考

### 被这些缺口卡住的动作

| 动作 | 为什么不能先写 |
| --- | --- |
| 点击移动 | 没有正式导航 Provider 和点击执行闭包，先写只会把寻路、输入、到达判定散进控制器 |
| 超距后自动靠近再施法/交互 | 依赖“导航移动 + 到达半径 + 续接动作”一整条正式入口 |
| 控制组穿越/实例入口 | 没有正式实例宿主和出生点分流宿主前，只会制造第二套世界穿越规则 |
| 当前控制角色直接替代世界穿越目标 | 控制对象语义和世界穿越目标语义还没在实例/出生点层锁定 |

### 本阶段正确动作

- 继续找正式参考
- 继续登记到缺口矩阵
- 继续做局部源码取证

### 本阶段错误动作

- 新增 `ClickMoveController`
- 新增“先能跑”的测试控制器/测试场景并把它当正式闭包
- 先写一套项目侧实例入口再说

### 验收口径

- 新候选参考能明确命中 4 个一级缺口之一
- 明确可直接搬部分、强绑定部分、正式落点和验收方式

## S4 开放世界模拟开工阶段

### 进入条件

- 不再继续扩张 `GameManager.*` 静态快捷入口
- 至少确定对应能力的正式拥有者、保存语义和验收场景
- 不把“世界层”写成空壳目录或空类

### 必须逐个建立的能力

| 能力 | 第一正式问题 |
| --- | --- |
| 区域/Cell 注册表 | 离开区域后的对象状态怎么保存和恢复 |
| 队伍与控制权 | 当前控制组、跟随/待机/工作命令怎么持久存在 |
| 角色世界身份 | 角色死亡、离线、失踪、被俘、区域外存在怎么表示 |
| AI 日程/行为包 | NPC 不靠触发器时如何按时间、地点、条件行动 |
| 派系关系 | 同一世界事件如何影响敌友、犯罪、通行权和态度 |
| 经济/基地生产 | 离开区域后工作站、库存和生产 tick 怎么降级运行 |
| 世界事件与任务绑定 | 任务如何绑定动态角色、地点和物品，而不是写死对象引用 |

### 本阶段不允许做

- 不允许先建空 `WorldSystem/WorldManager/WorldContext`
- 不允许把这些能力重新塞回 `NotificationSystem` 或 `GameManager.*`
- 不允许直接把 `TopDown AI`、`Unity Behavior`、`DOTS` 当世界状态真相

### 验收口径

- 每个能力有单独规格
- 每个能力有明确拥有者、保存语义、正式入口和第一验收场景

## 当前优先顺序

1. 沿 `GameplayFeedbackSet` 继续补相机/屏幕反馈
2. 为 4 个一级缺口继续补正式参考，不硬做点击移动/实例入口
3. 在真实调用者出现前，不预留 `CharacterRegistrySystem`；多角色世界语义后续仍以 `PlayerSystem` 和正式世界规格为入口
4. 进入开放世界玩法时，再按 `S4` 逐个开规格
