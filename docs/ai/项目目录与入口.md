# 项目目录与入口

## 适用范围

- 本文只负责说明 `FantasyWord` 的目录职责、正式入口和待整理目录。
- 旧恢复任务目录不自动成为当前正式目录合同。

## 当前工程根目录

- `Assets/`
- `Packages/`
- `ProjectSettings/`
- `docs/`
- `.codex/`
- `AIBridgeCache/`
- `docs/archive/legacy-recovery/`
- `Tools/`

## 当前正式入口

- AI 主入口：`AGENTS.md`
- 文档入口：`docs/ai/文档索引.md`
- 包配置：`Packages/manifest.json`
- Unity 版本：`ProjectSettings/ProjectVersion.txt`
- 输入配置：`Assets/InputSystem_Actions.inputactions`
- URP 设置：`Assets/Settings/`、`Assets/UniversalRenderPipelineGlobalSettings.asset`

## Assets 目录判定

- `Assets/Scripts/Items/EquipmentSystem`：当前可读的装备/换装框架候选，属于需要继续审查和迁移的项目成果，不按遗留垃圾处理。
- `Assets/GameData/EquipmentSystem`：当前装备/换装相关 ScriptableObject 数据候选，已从旧 `Assets/Data` 迁入并保留 `.meta`。
- `Assets/ThirdParty/MiniFantasyUV`：MiniFantasy UV 资源/来源链候选，默认先作为参考与资源来源保留。
- `Assets/Art`、`Assets/Minifantasy_NPCs_Assets`、`Assets/ArtRes`：像素素材和旧导入资源，重整前先保留。
- `docs/archive/minifantasy-demo-assets`：MiniFantasy 素材包 demo 场景归档；不作为正式场景入口。
- `Assets/Plugins`：第三方插件落点，当前包含 GAS、JKFrame、NaughtyAttributes、UniTask；BroAudio 由 Package Manager 通过 Git URL 管理。
- `docs/archive/legacy-rpg-assets/Assets/Database`、`docs/archive/legacy-rpg-assets/Assets/Prefabs`：旧 RPG 数据库和 Prefab 资产归档；因大量脚本引用缺失，不再作为当前 Unity 正式导入入口。
- `Assets/Editor/com.IvanMurzak`：旧 UnityMCP 安装器已删除，不作为正式编辑器工具入口。
- `Assets/Resources/Unity-MCP-ConnectionConfig.json`：旧 UnityMCP 配置若再次生成，说明当前 Unity Editor 仍有旧插件会话残留；应删除并刷新包解析。
- `Assets/_Recovery`：旧 Unity 恢复场景已删除；历史线索只保留在 `docs/archive/legacy-recovery/`。
- `Assets/Editor`、`Assets/Resources`、`Assets/Scripts/test`：若为空，不保留空目录占位；需要正式入口时再按规范创建。

## 目标目录合同草案

- `Assets/Scripts/GameCore`：俯视角开放世界核心框架、世界状态、系统入口。
- `Assets/Scripts/Characters`：玩家、NPC、怪物和可交互角色。
- `Assets/Scripts/World`：地图、区域、采集点、场景对象和世界交互。
- `Assets/Scripts/Items`：物品、装备、背包、掉落和制作。
- `Assets/Scripts/Combat`：俯视角战斗、伤害、技能、状态效果。
- `Assets/Scripts/Presentation`：角色表现、动画、相机、视觉反馈。
- `Assets/Scripts/Networking`：仅在联机进入正式范围后建立；当前不预先堆空壳。
- `Assets/GameData`：ScriptableObject、配置、数据库资产和可 diff 设计数据。
- `Assets/Prefabs`：正式 Prefab；当前为空或未建立时不要用旧 RPG Prefab 顶替。
- `Assets/Scenes`：正式场景和测试场景。
- `Assets/Editor`：正式编辑器工具。
- `Assets/Tests`：Unity Test Framework 测试。
- `Assets/ThirdParty` 或 `Assets/Plugins`：第三方插件、外部框架和需要保留来源结构的资源。

## 待整理原则

- 目录重整前，先确认当前引用和 `.meta`/GUID 关系。
- 可移动资源优先用 Unity/AssetDatabase 或保留 `.meta` 的文件级迁移方式。
- 不把空目录、旧乱码恢复目录和旧测试场景当成正式结构。
