# ClickMoveTest 固定步脱墙

原版依据为 Unity `31629d53a110dd4c87d4c85e6ad5a387fbafb931`。
`Movable.FixedUpdate` 在控制器之后、普通移动和推力之前处理墙内重叠。
`Movable.MotionRuntime` 按近到远的 16 圈找第一处空位，单圈按原世界
`+Y、+X、-Y、-X、东北、东南、西南、西北` 顺序检测。
两个实际角色都继承启用移动的 `0_CharacterActor_Base.prefab`。
`GameConfig.asset` 指定最大搜索距离 5、地形掩码 7752、排除触发器；
继续使用各自的正式碰撞体及偏移。检测不修改地图，不把重叠测试发作玩法碰撞。

正常项目入口的主角与训练假人都在同一步先脱墙，再执行既有路径和推力。
本步的位移计算使用找到的空位，但在 Godot 物理服回写前，不把场景节点的
外部可见位置伪报为已经同步。不取消正确的路径或推力，不触发原独立
`TeleportTo` 的通知；在距离内找不到空位时不移动到替代点。
这里只迁移实际角色的固定步脱墙，不接通一般出生点搜索、主动传送、
原 Unity 警告打点及任意配置的物理体。

定向检验：从正常入口启动同一主角和同一活动训练假人，为每个实际身体注入
一块测试地形，无移动命令也从第二圈先按原 +Y 脱墙；原角色身份、相机与命令数量
不变。原生物理测试另外验证同一步路径和推力、找不到空位、没有虚假碰撞通知，
以及真实身体位置何时生效。证据是 Godot 物理行为，不是 Unity 原窗口运行、
刚体回写时序一致性、所有地形接缝或双引擎画面对照。
