# 武器填充深度与遮盖迁移边界

## 锁定范围

- Unity 真相提交：`31629d53a110dd4c87d4c85e6ad5a387fbafb931`。
- Godot 起点：`ed270e31c3b7e9170c7688d876b17d5d9ebe84c1`。
- 对象：`EquipmentUV.shader` 第三步武器填充和随后北向背包覆盖，止于程序描边之前。
- 原位置：`Assets/Scripts/Gameplay/Runtime/Presentation/EquipmentSystem/Shaders/EquipmentUV.shader`，1183–1265 行；采样成功条件另见 420–432、459–521 行。
- 目标：`gameplay/presentation/equipment_weapon_fill.gd` 的 CPU 合同和自动回归。不修改 Unity 场景、预制体、配置、原素材，也不推断新的视觉设计。

## 同职责对照

| 原实现事实 | 迁移入口与判据 |
|---|---|
| 人物颜色与独立 charAlpha 是不同值 | `character.color` 与 `character.coverage` 分别传入；覆盖不能取底图颜色的 alpha |
| 武器采样成功已包含启用、有效坐标和 alpha 严格大于 0.5 | 槽必须显式提供 `sampled`、`color`、`depth_mode`、`hand_in_front`；成功标记的颜色 alpha 必须超过截止值 |
| 后景深度严格小于 0.5，主手先、副手后 | 原人物覆盖小于等于 0.5 才写 RGB；重叠时副手来源 8 胜出 |
| 后景被人物遮住仍贡献 alpha | 始终与成功后景武器 alpha 取最大值，不把覆盖更新放进颜色条件内 |
| 前景深度严格大于 0.5，副手先、主手后 | 重叠时主手来源 7 胜出；不使用透明混色 |
| 手是否挡武器按各槽配置 | 任一手蒙版且该槽 `hand_in_front > 0.5` 才挡；被挡前景不写颜色，也不贡献覆盖 |
| 注释提脚，但填充谓词实际上没有脚 | 不添加脚遮挡；左右脚回归明确要求武器仍显示 |
| 深度正好 0.5 | 不进入后景或前景分支，不重解释为枚举中的任一侧 |
| 最后再次覆盖北向背包 | 只在 `body_in_front > 0.5` 且 `enable_bag > 0.5` 时调用当前 bodyUV.rg 采样回调；texel alpha 严格大于 0.5 则写 RGB、来源 10、覆盖与 1 取最大值 |
| 北包覆盖没有额外部位条件 | 不增加躯干、手脚、头部、人物覆盖或 BodyUV alpha 限制；也不把南向躯干内背包条件搬到这里 |
| 完成填充后写回 alpha | 最终颜色 alpha 写为独立覆盖；保留最大覆盖而不是最终 RGB 来源的纹理 alpha |

## 输入与失败边界

人物输入可直接取现有身体/头部合成结果，但调用顺序应位于肤色映射之后。槽的 `sampled` 是上游 `TrySampleWeapon` 等价采样的成功结果，不是装备存在或启用开关。没有实现此上游过程时，不能仅凭非透明测试颜色声称武器素材已接入。

背包回调只负责当前编码身体 UV 的 texel，包含实际 alpha；本层复现 `TrySampleEquip` 的截止条件。不再次推导采样 UV、不生成背包素材、不要求整图读取，也不额外把覆盖限制到 [0,1]。输入处于上游合同之外时不兜底猜配置。
