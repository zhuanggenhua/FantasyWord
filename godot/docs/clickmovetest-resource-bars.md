# ClickMoveTest 原 HUD 生命与魔力条

原版依据：Unity `31629d53a110dd4c87d4c85e6ad5a387fbafb931` 的 `ClickMoveTest.unity` 中 UISystem 实例化 `Assets/Prefabs/UI/User Interface.prefab`；其中屏幕画布引用 `Assets/Prefabs/UI/HUD/HUD.prefab`，其资源组持有两个 `Resource Bar.prefab` 实例。这不是测试控制面板上的生命显示。

- 原画布按高度缩放。资源组左上 (20,20)，两行各 600×64。横向布局不给子项拉伸尺寸，剩余 16 点均分到两个布局单元；各单元再居中，实际名称框为 (24,20,200,64)、生命滑条 (232,36,384,32)，魔力行向下 64 点。九切框基于实例原图 `-646921389` 外扩 6 点，填充采用原 `1274501863` / `-811945282` 图块按比例拉伸，不替换图集。
- `UIStatBar.cs` 从实际角色读当前和上限，滑条比例单独限定为 0–1。锁定版 GameConfig 没有任何术语绑定，两个原名称均是 `[INVALID_SHORTNAME]`；以原 RPGSystem 字形按 TMP 64 点左上排版，按宽度断为三行并保留 Overflow。数字同图集 28 点，采用原内容拟合框和居中枢轴。文字溢出不扩大原 GraphicRaycaster 矩形。滑条是显示件，拦截地图点击，但不提供玩家可修改的数值。
- 实际主角的正式属性初始化生命 100/100、魔力 40/40。实际伤害链的生命变动刷新资源栏；仅生命下降触发生命滑条（底、填充、框、数字，不含名称）的原摇动：缩放秒、振幅 5、X/Y 频率 30/25、0.2 秒复位，连续下降先复位再开始。当前角色解除后解绑，清空数字和填充，保留名称及框；重新选中先读实际状态、不摇动。
- 仅覆盖正常 F5 启动的当前主角以及本场景的已迁移损血。尚未实现动态耗蓝/回复、改变上限、属性修饰、存档重载；没有实现原输入系统对非交互 Slider 的自定义选择焦点。私有原始图集和字体复用 `FORMAL_PAUSE_SOURCE`，没有入仓。源参数与 Godot 原生采样不等于 Unity 原窗口像素或实机对照。
- 定向验收 `test_source_resource_bars.gd`：正常启动、原图格正式 Fire 接触伤害两次、原生渲染取样、点地经过实际输入路由、抖动发起/重启/归位、角色解绑和恢复。无私有源的干净基线明确跳过原图试验。

## 资源条与失败提示独立装配

按原 `HUD.prefab` 装配 Resource Bars 与 Ability Message：两者均不依赖暂停
技能面板的私有布局。正常 F5 提供已锁定的原界面图集和字体即可显示，真实技能栏
仍只在技能布局与攻击原图都通过验证时启用；没有提供就不新增空槽或点击区。
无原界面合同的启动范围保持不变；提供错误合同不会降级为近似界面。

最小配置与完整技能、背包配置均从正常入口验证：原主角生命/法力初值、真实火地
掉血后生命变化、原空技能槽提示、资源条与提示的命中区、打开关闭暂停后的 HUD
持有和提示时钟，以及控制目标的解绑和重新读取。本批仍使用原生命属性通知，
不迁移或验证动态耗蓝、存档、Continue、物品使用、Unity 双端画面对照。
