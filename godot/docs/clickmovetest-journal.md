# ClickMoveTest 初始日志

正常 F5 进入原场景，暂停菜单的 Journal（动作 2）打开共享注册项 EMenu 4。退出回到暂停菜单原先的 Journal；再次返回才恢复世界输入和已有移动命令。初次运行没有正在做或待交付的任务，因此没有焦点行、编辑器示例说明或滚动条。没有假造任务，也没有实现非空任务列表、接取、进度、完成、存档与菜单的手柄验收。

画面读取锁定 Unity `31629d53a110dd4c87d4c85e6ad5a387fbafb931` 的 UIJournal 嵌套预制体、实际背景、四张分栏底图边框绘制与标题。关键版式：安全区居中的两栏，每栏 832×768；原 VerticalLayoutGroup 即使不控制子高度也会分配额外空间，标题下预留 8 个参考像素，所以两个主体框从 y308 开始；原裁剪区域不会绘制 Mask 图案。整体按高度匹配，栏目居中而底部按钮说明各自靠外。底部设备键位图标和 Unity 字体像素对照未验收。

使用 `tools/extract_clickmovetest_journal.py` 在固定 Unity 提交提取私有布局契约，复用经过校验的菜单源图集和字体。不将源素材或契约数据入仓；缺少布局契约时不以其他界面替代。运行 `tests/test_source_journal_entry.gd` 可从实际主场景复核输入、布局、原生像素和回退；无私有资产时显式跳过。
