# 装备阴影 CPU 合同边界

## 锁定对象与入口

来源锁定 Unity 提交 `31629d53a110dd4c87d4c85e6ad5a387fbafb931`，`EquipmentRenderer.cs` 的 `UpdateShadowHeight`（1540–1655）与 `EquipmentUV.shader` 的阴影判据（531–650）、片元阴影门控（1423–1473）。目标仅为 Godot 独立 CPU 模块与合成测试，不是正式 Actor、材质或着色器接入。基础迁移提交为 `1b6d4b44cf003703100b31f94edcd567eda3eabf`。

## 接口与原行为

- `height_writes` 接作者顶原点脚像素（`Vector2i` 数组）、地面行与帧尺寸，只返回本次写入。动画缺省尺寸用 32×32；调用者有实际动画时必须传真实尺寸。无材质返回空；缺帧数据、缓存帧或双脚为空仅写 `mode=-1`。不生成停用字段。
- `apply_writes` 复制旧参数并应用增量；不会重置未写的旧基线、尺寸或阴影启用状态。
- 高度差取地面行减双脚最小 Y，阈值依次为 ≤0、≤2、≤9、其余。Mode1 用脚的 X 总极值并保留缺侧 ±999 哨兵；Mode2 比较各侧最小 Y，同高取左脚最大 X，否则右脚最小 X；不是双脚均值。Mode3 取帧中心。X 不加半像素，基线 Y 有半像素。
- `mask` 与 caster 回调都使用帧内底原点 UV。尺寸和旧参数由调用者明确提供，不替其补默认值。Mode0 复用 `equipment_outline_coverage.gd` 的 `caster_alpha`（把已有覆盖率回调包成返回该字段即可）：身体及装备并集、静态武器，不含背包或序列武器；保留分数 alpha。
- Mode0 基线行两个三点探针（五列但中心重复采样），下一行一个三点。每个探针只筛 X 的 [0,1]，不筛 Y、不先排除探针中心。Y 外沿含边界；分行严格小于 -0.5 像素。caster 判据严格 >0.001。
- Mode1 为闭区间矩形；Mode2 的 X 范围 -1 至 +2 不对称，去除严格半像素界外四角；Mode3 是闭边界十字。模式采用原始实数区间 <0.5、<1.5、<2.5，其余，不能取整。
- `apply_shadow` 显式接独立 `final_alpha`，仅在其 ≤0.5、启用 >0.5、遮罩命中且阴影颜色 alpha>0 时整色替换。不是混色。最终顶点/材质乘色不在本模块。

## 静态语义不等于运行到达

源码注释把 mode=-1 称为“无阴影”，但片元实际仍因 mode<0.5 进入 Mode0。模块保留这个事实，不擅自修正。它会使用上次留下的帧尺寸和基线。

正常 `Refresh` 在缺 frameData、动画、缓存帧或 Body/Head UV 时会先返回，未必调用 `UpdateShadowHeight`。因此直接函数的缺帧测试只证明函数合同，不能据此断言正常刷新必然写 -1。有效帧脚数组为空则不同，不能假定永远不可达。预览默认值会启用阴影，不能从 -1 推导停用；是否实际触发仍须真实入口、动作切换和帧序列验证。

本轮只使用合成输入测试。真实作者帧审计由独立私有验证负责；不发布原始素材、帧数据或截图。没有运行 Unity GameView，也没有取得原版与 Godot 原生画面的完整动态对照；不能称迁移整体完成。

## 验证

`tests/test_equipment_shadow_coverage.gd` 覆盖高度阈值、双脚极值与同高偏向、缺侧哨兵、增量写入、所有模式边界、Mode0 点位顺序与截止值、旧轮廓 caster 回调组合、片元颜色门控。运行 `GODOT=/path/to/godot bash godot/tests/run.sh` 执行包括既有模块的全套测试。仍未验收正式渲染器调用、浮点硬件/纹理采样精度一致性及真实 GameView。

本次新鲜结果：Godot 4.7.2 全套 69 个测试套件通过，新增阴影套件 214 项断言；日志无错误、警告或泄漏提示；`spec-lint passed`。独立协调线程另以私有作者输入核对 96 帧、98,304 个几何判据位置（含原底图、Body/Head UV 与头发/胡须 caster），并检查真实空脚动作元数据与上一帧参数保留序列。这些是离线合同证据，不是原版 Actor 运行到达或 GameView 截图证据。
