# 换装刷新顺序与双 UV 门禁

依据锁定 Unity `31629d5` 的 `EquipmentRenderer.Refresh` 和 `EquipTypeConfig`。这个模块不实现新的动作状态、换装资源或 Shader，只把调用方提供的帧、UV、装备槽与现有渲染入口按源顺序调度。

- 原精灵直显优先：重置装备状态、禁用生成的武器渲染器、应用原材质。没有 CharacterFrameData 是另一条分支：报警并重置。
- 有帧数据但缺动作/帧、Body UV 或 Head UV 中任一项：重置装备，清除两张 UV，处理独立武器，按注册顺序仅恢复当前动作有独立序列帧的 Sprite 类型装备。不能让旧帧头部或身体数据残留；也不能把颜色装备或静态图当成独立序列。
- 输入完整：阴影高度、重置装备、写双 UV、当前帧受击描边、身体深度、武器、外观，再按已有配置遍历 Sprite 与 Color 装备。注册表中的武器项不重复调用，None 不渲染。

当前测试使用原生 ShaderMaterial 证明两张纹理独立绑定并实际清空，用回调轨迹证明调用顺序；测试 Shader 没有外观逻辑，不用于角色。正式材质、GPU 画面、真实武器渲染和外观叠加仍未验收。

`equipment_frame_runtime.gd` 接收已解析的实际动作键，优先取同名帧数据，仅保留 Unity 原有的 Wait→Idle 及三类死亡表现的有序回退。回退只选择帧数据，独立装备序列仍按原请求动作键查询。切动作先写两个独立 UV；若随后取不到装备帧或双图不齐，刷新时清除两个。原生测试驱动真实 AnimationPlayer 和 AtlasTexture，证明标签 0 / 1 不被误认为第 0 / 1 列，按实际稀疏区域索引，覆盖有无双图、静态层和独立序列边界。它是可接的表现逻辑，不等于已接最终角色材质；还需迁移正式动作键选择中的 Animator 布尔参数旧分支、正式角色绑定和 GPU 图层。
