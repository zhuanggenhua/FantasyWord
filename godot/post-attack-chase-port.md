# ClickMoveTest 攻击后追击验收接口

对应锁定源 `31629d5` 的 `Assets/Editor/GameCore/Automation/ClickMoveTestPostAttackChaseValidator.cs`。这是验收工具，不是追击控制器。

- 原场景先找到实际受控玩家和带调试探针的 AI 角色，将 NPC 放在玩家 Unity +Y 方向 0.72，再设置正式战斗目标。这个来源的脚本注入目标，不证明自然侦测；两件事要分别验证。
- 实际观察到玩家当前动画键是精确的 `Dmg` 才进入下一阶段。随后沿远离 NPC 方向请求 2.6 世界单位，用原路径终点并要求距离至少 2.0；首选失败才按右、左、上、下和四个对角尝试。没有可行图路径时沿用原请求点，不能声称该点可达。
- 攻击与追击分别有 240 帧窗口；追击窗口严格超过 240 帧才给定论。要求看到真实 Dmg 进入、最终离开 Dmg、NPC 可移动、有战斗目标，且 NPC 位移至少 0.2 或最终距离不超过 1.45。源脚本的最终目标条件是非空；另可记录是否仍指向玩家，不能把单次注入等同自然持续选敌。
- 独立测试验证上面判据，不代替实际原场景验收。HP 下降只证明命中，不当作 Dmg 动画播放，也不把 Polygon 测试替身或评分向量水平位移当作正式玩家与 NPC 的追击证据。

## Godot 原生联测

`tests/test_clickmovetest_post_attack_chase.gd` 从同一正式 Entry 观察实际玩家受击动作，
按上面的实际地图路径挑选拉开点，并由引擎正常处理过程帧与固定步，观察假人恢复移动。
布置使用原来的 +Y 0.72，但不调用 Unity 验收器的强制设敌或重设目标；Godot 测试要求
原生检测自然挂住同一玩家，受击后的安全阶段只处理一次中断，并且实际假人身体移动。
固定 60 FPS 上限只用于让 240 个过程帧有可复现的物理步窗口，不改变项目配置。

仅当明确提供源地图规则、两角色正式动作与独立双 UV 材质、授权图集时运行原素材变体；
未提供时使用分开标注的匿名测试。测试宿主的 RNG 样本与属性入口不是正式游戏宿主，
本结果不代表多 NPC、原版 Unity 截图或完整主场景已经验收。
