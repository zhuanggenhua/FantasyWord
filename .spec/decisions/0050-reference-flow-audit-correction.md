# 0050-参考流程审计结论纠偏边界

- 日期：2026-07-16
- 状态：已采纳
- 背景：
  - 本轮 GameManager 调用面审计曾把“改成 `TryGetSystem<T>()` 安全查询”“禁止单例直读”“必需/可选依赖分类”当成主要判断标准。
  - 这个口径是错误的：2DRPGEngine 同职责正式流程本来就大量通过 `GameManager.XxxSystem`、`GameManager.Player` 和 `GetSystem<T>()` 访问项目级系统宿主。
  - `TryGetSystem<T>()` 的存在只说明 GameManager 查询 API 需要能表达“系统尚未就绪时返回 false”的语义；它不说明所有调用点都应该改成非抛错查询。
- 决策：
  - 审计结论必须先回答“参考同职责流程怎么做”，再回答“FantasyWord 当前差异是什么”，最后判定差异是参考一致、当前项目必要增强、业务适配，还是退步/误改。
  - `GameManager.XxxSystem / GetSystem<T>()` 不是单例违规，也不是待消灭的代码味道；在正式结果写入链、存档链、死亡/复活链、背包/任务/地图等需要暴露配置错误的流程中，直接使用正式系统入口是允许且应优先保留的。
  - `TryGetSystem<T>() / HasSystem<T>() / GameManager.Exists()` 只能用于确有“未就绪时不改变正式结果”的查询或表现流程，例如 HUD 订阅、菜单上下文解析、条件预览、表现反馈、调试面板、保存引用解析和编辑器/测试诊断。
  - 不得因为一段代码用了 `TryGetSystem<T>()` 就判定它更规范；也不得因为一段代码用了 `GameManager.XxxSystem` 就判定它违反架构。两者都必须回到同职责流程和失败语义判断。
  - 后续门禁不得新增“必须出现 TryGetSystem”或“禁止 GameManager.XxxSystem”的访问形式规则；只能检查具体流程合同，例如“销毁状态不得被吞掉”“死亡背包转移不得跳过”“当前控制角色菜单解析失败不得误退默认队伍背包”。
- 影响：
  - 0042 仍只作为 GameManager 查询 API 自身的健壮性合同：`HasSystem/TryGetSystem` 缺实例返回 false，`GetSystem` 缺正式系统抛可定位异常，重复系统注册抛异常。
  - 0042 不再被解释为调用点迁移建议，不得作为“把正式结果链改成 Try 查询”的依据。
  - 43-50 的旧审计项只能保留其具体流程合同和已被 0046/0050 纠正后的结论；旧的“安全查询/单例违规”理由作废。
  - 下一阶段审计优先查正式结果写入链是否还存在静默跳过，而不是按 `TryGetSystem` 文本命中批量改代码。
- 替代关系：
  - 本决策补充并收紧 0046，明确 0042 的适用范围。
  - 本决策取代本轮所有把 `TryGetSystem<T>()` 作为默认重构方向、把 `GameManager.XxxSystem` 作为默认违规项的口径。
