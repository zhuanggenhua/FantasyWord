# 0039-区域音频系统就绪边界

- 日期：2026-07-15
- 状态：已采纳（系统访问形式判定已由 0046 取代）
- 2026-07-16 状态说明：
  - 本文保留“区域音频缺少可执行前提时跳过本次切换并暴露可定位错误”的失败语义。
  - 文中关于直读 `GameManager.PlayerSystem / AudioSystem` 或必须换成查询 API 的表述，不再作为独立审计标准；当前以 `0046-参考流程优先的 GameManager 系统访问审计边界` 为准。
- 背景：
  - `AudioRegion` 是触发区域背景音切换的运行时入口，需要判断进入者是否为当前受控角色，并记录目标通道之前播放的音频。
  - 旧实现直接读取 `GameManager.PlayerSystem` 和 `GameManager.AudioSystem`；如果触发器早于系统初始化、系统被停用或场景配置不完整，会把区域音频问题表现成全局系统空引用。
  - 区域音频不应在系统未就绪时通过查找、默认角色或默认通道兜底；未就绪代表该次区域音频切换不能安全执行。
- 决策：
  - `AudioRegion` 判断玩家时必须先确认 `GameManager` 和 `PlayerSystem` 就绪，并成功取得当前受控角色。
  - 进入区域前必须先确认 `AudioSystem` 就绪，再读取目标通道最近播放的音频。
  - 缺少 `AudioClipResolver` 或 `AudioSystem` 时直接报可定位错误并跳过本次区域音频切换；不得用运行时查找、默认通道或静默兜底替代。
  - 音频静态门禁必须验证 `AudioRegion` 在区域音频切换前具备可执行前提：能识别当前受控角色、能解析目标通道、缺少解析器或音频系统时能暴露可定位失败；门禁不得仅因 `GameManager.XxxSystem` 或 `TryGetSystem<T>()` 访问形式判定通过/失败。
- 影响：
  - 区域音频触发早于正式系统启动时不再抛全局空引用。
  - 区域音频的失败原因能定位到缺少解析器、缺少音频系统或当前受控角色未就绪。
  - 不改变 `AudioClipResolver -> GameRuntimeEvents -> AudioSystem -> AudioChannel` 的音频主链。
- 替代关系：
  - 本决策补强 `0004-音频运行时 owner 边界` 和 `0026-音频播放生命周期 owner 边界`，只收紧区域音频入口的系统就绪合同。
