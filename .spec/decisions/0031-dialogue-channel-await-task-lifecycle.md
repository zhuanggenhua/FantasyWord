# 0031-对话通道等待任务生命周期 owner 边界

- 日期：2026-07-15
- 状态：已采纳
- 背景：
  - `DialogueChannel` 用 `TaskCompletionSource<bool>` 把对话播放队列暴露给命令、交互和系统调用方等待。
  - 旧实现中，空对话树、无入口节点或通道禁用/销毁都可能让等待方一直等待；完成任务也使用非幂等 `SetResult`。
  - 对话通道是这些等待任务的唯一运行时 owner，必须在正常完成、失败、取消和生命周期结束时明确给出结果。
- 决策：
  - `DialogueChannel.AddToQueue()` 遇到空对话树时直接返回已完成的 false 任务，并记录可定位错误。
  - 对话树缺少入口节点时不得悬空等待；应完成该任务并返回 false。
  - 通道禁用或销毁时必须取消当前对话等待任务并清空队列，所有等待方都得到 false。
  - 正常对话完成继续返回 true；所有完成动作使用 `TrySetResult`，避免重复完成抛异常。
  - 新增对话运行时静态门禁，禁止该通道回退到非幂等 `SetResult` 或缺失失败/生命周期完成路径。
- 影响：
  - 命令、交互和任务奖励等待对话时，不会因为坏数据或通道生命周期结束而永久挂起。
  - 对话通道的队列、当前播放状态和等待任务完成语义归同一个组件管理。
  - 对话系统上层仍只通过 `DialogueSystem` 调用，不新增全局 owner 或场景依赖。
- 替代关系：
  - 本决策补强 `0008-命令异步执行 owner 边界` 中“可等待命令必须有明确完成语义”的对话播放子链路。
