# 0058-库存多步交易合同边界

- 日期：2026-07-16
- 状态：已采纳
- 背景：
  - `2DRPGEngine` 的商店、制作、宝箱和消耗品流程能在 UI、实体或资产对象里直接调用 `RemoveMoney/AddToBag/RemoveFromBag/AddMoney`，成立前提是唯一玩家背包、宽松库存写入和较少 owner 失效面。
  - FantasyWord 已经把库存扩展成队伍、角色、容器、尸体、商店、制作台等多 owner；同一笔交易或初始化可能同时触碰金钱、物品来源、物品目标、材料、产物和容器库存。
  - 只在 UI、制作站或物品效果里补“先验证 owner / 先检查物品”会让交易顺序合同散在调用方，后续每增加一个入口都要重新记住同一套扣款、扣料、入包和反馈顺序。
  - 本轮复核后的问题不是 `GameManager.InventorySystem` 访问形式，也不是单例或接口问题；问题是“库存结果写入的多步顺序”没有集中到库存真相源。
- 决策：
  - `InventorySystem` 作为库存真相源，负责商店买入、商店卖出、制作和宝箱首次掉落初始化这类多步库存写入的完整顺序。
  - UI 只负责解析当前交互 owner、调用库存交易接口、播放反馈、刷新显示；不得在商店 UI 内手写“扣钱 -> 加物”或“删物 -> 加钱”。
  - `CraftingStation` 只保留制作站配置、价格计算和配方入口；不得手写“扣钱 -> 扣材料 -> 加产物 -> 加额外产物”，必须请求 `InventorySystem` 执行已验证制作交易。
  - `Chest` 只保留动画、对话、打开状态和容器菜单入口；不得在宝箱实体里逐条验证并写库存，必须请求 `InventorySystem` 先验证全部掉落配置再写入容器物品和队伍金钱。
  - 玩家可理解的失败，例如钱不够、材料不足、物品不在来源背包、物品不可卖，返回 `InventoryOperationResult` 给 UI 显示反馈。
  - 配置错误，例如空商店、空物品、空配方、无效 owner、无效配方材料或产物、无效宝箱掉落或负数金钱，继续抛出可定位异常；不得伪装成普通交互失败。
  - 本决策不新增第二套库存 owner，不引入通用交易系统或 DI/service 包装层；它只是让既有 `InventorySystem` 变深，把调用方重复维护的多步交易实现收回库存 Module 内部。
- 影响：
  - 商店买入由 `InventorySystem.ExecuteShopPurchase(...)` 先验证目标背包和资金，再扣钱并入包。
  - 商店卖出由 `InventorySystem.ExecuteShopSale(...)` 先验证可卖和来源背包持有物品，只有物品真实移除后才加钱。
  - 制作由 `InventorySystem.ExecuteCraftRecipe(...)` 先验证配方、资金和材料，再统一扣钱、扣材料和写入产物。
  - 宝箱首次开启由 `InventorySystem.ExecuteChestLootInitialization(...)` 先验证全部掉落条目和金钱，再写入容器物品与队伍金钱；`Chest` 在事务成功后才播放揭示动画、音效并排入对话。
  - `UIShop`、`UICraft` 和 `Chest` 仍承担菜单反馈、对话、动画和刷新，但不再拥有库存多步写入顺序。
  - 库存门禁新增“商店/制作/宝箱必须使用库存交易或初始化接口”的结构检查，防止以后回退成调用点散写。
- 替代关系：
  - 本决策补充并收紧 `0055-背包结果写入参考流程边界`：0055 先确认了半完成状态问题；0058 将同类修复从调用点 guard 升级为库存交易合同。
