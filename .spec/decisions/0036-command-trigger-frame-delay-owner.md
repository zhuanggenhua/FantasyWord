# 0036-场景命令触发器帧延迟 owner 边界

- 日期：2026-07-15
- 状态：已采纳
- 背景：
  - `CommandTrigger` 是对话、场景触发、碰撞、交互和生命周期命令的正式入口之一。
  - 旧实现用组件自身协程承载 `m_frameDelay`，延迟期间如果触发器所在对象被禁用或销毁，命令执行语义容易和 Unity 协程生命周期混在一起。
  - 0008 已要求事件式命令入口必须显式后台执行并上报异常；帧延迟同样应该属于命令入口语义，而不是由触发器对象的协程状态隐式决定。
- 决策：
  - `CommandTrigger` 帧延迟不再使用 `StartCoroutine` / `yield return null`。
  - 延迟改用 UniTask PlayerLoop 的帧等待，并以触发器销毁令牌作为取消边界。
  - 延迟结束前触发器被销毁时不再执行命令；触发器只是被禁用但未销毁时，已排入的生命周期命令仍按原触发语义执行。
  - 命令运行时门禁扩展 `CommandTriggerFrameDelayUsesPlayerLoop`，防止帧延迟回退到组件协程。
- 影响：
  - 场景命令触发器的即时执行、条件判断、玩家上下文和异常上报流程不变。
  - 本轮不改变 `OnUpdate` / `OnFixedUpdate` 的重复触发语义，只收口已有帧延迟的 owner。
- 替代关系：
  - 本决策细化 0008-命令异步执行 owner 边界，专门约束 `CommandTrigger` 的帧延迟实现。
