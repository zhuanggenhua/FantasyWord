# 0027-宝箱首次开启防重入边界

- 日期：2026-07-15
- 状态：已采纳
- 背景：
  - `Chest.TryOpen()` 的首次开启流程会播放动画、初始化容器掉落、发钱、排入对话，然后等待对话队列播放完成。
  - 旧实现直到对话播放完成后才把 `m_opened` 置为 true；在这段等待期间再次交互会重新进入首次开启流程，可能重复初始化掉落、重复加钱或重复排入对话。
  - 掉落图标揭示动画由宝箱自身协程轮播，也需要跟随宝箱禁用、销毁和读档恢复清理。
- 决策：
  - 宝箱首次开启流程必须有 `m_opening` 防重入守卫；开启中再次交互直接返回失败，不再重复执行首次掉落逻辑。
  - 首次掉落和对话入队完成后、等待对话播放前，必须提交 `m_opened = true`，让存档和后续交互都承认该宝箱已消耗首次开启。
  - `m_opening` 必须在 `finally` 中清理，读档时也必须重置为 false。
  - 内容揭示协程必须被记录，并在重新播放、禁用、销毁和读档时停止。
  - 宝箱专项静态门禁必须覆盖防重入、opened 提交时机和内容揭示协程生命周期。
- 影响：
  - 玩家在宝箱首次开启对话未播完时重复点击，不会重复发放容器物品或金钱。
  - 读档或禁用宝箱时，旧内容图标轮播协程不会继续写 SpriteRenderer。
- 替代关系：
  - 本决策补强 `0005-存档与数据库稳定身份边界` 中容器库存 owner 的运行时一次性初始化语义。
