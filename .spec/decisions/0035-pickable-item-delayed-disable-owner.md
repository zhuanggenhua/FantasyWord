# 0035-拾取物延迟禁用 owner 边界

- 日期：2026-07-15
- 状态：已采纳
- 背景：
  - `PickableItem` 吸收了 TopDown PickableItem 的拾取条件、反馈和拾取后禁用流程，但库存、金钱和正式拾取者仍归 GameCore。
  - 旧实现把“延迟禁用当前对象”和“延迟禁用目标对象”都挂在拾取物自身协程上。
  - 当拾取物成功后立刻禁用自身时，挂在它身上的目标延迟禁用协程可能无法启动或无法跑完，导致目标对象禁用流程丢失。
- 决策：
  - 拾取物延迟禁用不再使用拾取物自身协程，改用项目已采用的 UniTask PlayerLoop 延迟。
  - 延迟任务使用拾取物销毁令牌作为取消边界；拾取物被禁用但未销毁时，拾取后的目标禁用流程仍应继续。
  - 延迟禁用目标对象时必须在启动时捕获目标引用，并在延迟结束后重新判空。
  - 新增 Loot 运行时静态门禁，防止 `PickableItem` 回退到自身协程和 `WaitForSeconds` 延迟。
- 影响：
  - 拾取成功后，当前拾取物可以按配置立即隐藏或禁用，同时仍能按配置延迟禁用另一个目标对象。
  - 本轮不改变拾取条件、当前受控角色判定、物品入包、金钱入账或反馈播放 owner。
- 替代关系：
  - 本决策补强项目从 TopDown PickableItem 吸收的禁用流程，只收口延迟 owner，不引入 TopDown InventoryEngine 或全局协程 manager。
