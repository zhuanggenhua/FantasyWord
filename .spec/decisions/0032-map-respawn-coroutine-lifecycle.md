# 0032-地图复活延迟协程生命周期 owner 边界

- 日期：2026-07-15
- 状态：已采纳
- 背景：
  - `MapSystem` 是当前地图、检查点、传送和玩家复活节奏的运行时 owner。
  - `RespawnPlayer()` 会启动一个复活延迟协程，但旧实现只在协程自然走完或失败分支中清理句柄。
  - 当系统停止、对象禁用或销毁时，复活协程继续挂在旧系统实例上没有明确语义，可能在退出运行、切换流程或对象生命周期结束后继续执行传送/复活逻辑。
- 决策：
  - `MapSystem` 必须在 `OnSystemStop`、`OnDisable` 和 `OnDestroy` 中停止当前复活协程。
  - 停止复活协程时必须清空 `m_respawnCoroutine`，使后续复活请求可以重新启动。
  - 复活协程自然退出、缺少有效检查点或缺少穿越角色时仍必须清空句柄。
  - 新增地图运行时静态门禁，覆盖复活协程启动、停止和句柄清理合同。
- 影响：
  - 地图系统停止或对象生命周期结束后，不会留下旧复活延迟继续触发传送或 `Revive()`。
  - 玩家复活节奏仍归 `MapSystem`；本轮不改变检查点、出生点、地图加载或世界穿越目标语义。
- 替代关系：
  - 本决策补强地图系统中已经吸收的 TopDown 重生延迟样板，只收口协程生命周期，不改变地图/检查点 owner。
