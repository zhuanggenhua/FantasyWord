# 0060-库存奖励写入合同边界

- 日期：2026-07-16
- 状态：已采纳
- 背景：
  - `2DRPGEngine` 的怪物死亡奖励在 `Monster.Kill()` 中直接遍历掉落并写入唯一玩家背包，再加经验和金钱；该流程依赖单背包和宽松库存写入。
  - FantasyWord 已经把背包写入坏配置升级为可定位异常，并把掉落接收者扩展为实际击杀来源或主玩家角色。
  - 如果击杀奖励仍在 `CharacterActor` 内逐条 `AddToBag`，当后续掉落配置为空物品或非法数量时，前面的有效掉落可能已经写入，形成半完成奖励。
  - 本问题不是 `GameManager.InventorySystem` 访问形式问题；问题是一次击杀奖励中的库存物品和金钱写入没有在库存真相源内先整体验证。
- 决策：
  - `InventorySystem` 负责 `ExecuteLootReward(...)`，先验证本次实际命中的掉落列表、目标 owner 和金钱奖励，再统一写入物品和队伍钱包。
  - `CharacterActor` 仍拥有死亡流程、奖励接收者选择、经验奖励、死亡命令和表现反馈；它只把已经按等级、条件和掉率解析出的掉落交给库存系统提交。
  - 负数金钱奖励、空掉落列表对象、空物品或非正数量属于配置错误，直接抛出可定位异常。
  - 本决策不改变参考工程“怪物死亡奖励直接给正式背包”的职责内核，只把 FantasyWord 新增的多 owner 和严格库存写入失败面收回到库存系统。
- 影响：
  - 击杀奖励物品和金钱由 `InventorySystem.ExecuteLootReward(...)` 一次性提交。
  - 经验奖励仍由 `CharacterActor.AddExperience(...)` 写角色状态，不进入库存系统。
  - 库存门禁新增“击杀奖励必须先整体验证掉落再写物品或金钱”的结构检查。
- 替代关系：
  - 本决策补充 `0058-库存多步交易合同边界`：0058 处理交易/初始化；0060 处理击杀奖励这类多条库存结果写入。
