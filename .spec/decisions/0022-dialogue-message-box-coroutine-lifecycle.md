# 0022-对话消息框跳字协程生命周期 owner 边界

- 日期：2026-07-15
- 状态：已采纳
- 背景：
  - `UIDialogueMessageBox` 负责对话文本逐字显示，并用自身协程推进跳字和播放对话 blip 音效。
  - 该协程原先只在隐藏、替换文本或跳过时终止；如果消息框组件被禁用或销毁，生命周期边界不够显式。
  - 对话 HUD 已经把主对话监听迁到启用/禁用生命周期，消息框内部协程也应跟随同一条 UI 生命周期。
- 决策：
  - `UIDialogueMessageBox` 必须在 `OnDisable` 和 `OnDestroy` 中终止当前跳字协程，并清空跳字状态。
  - 隐藏、替换文本和跳过仍必须终止旧协程，避免旧文本继续驱动 UI 或重复触发完成回调。
  - UI 静态门禁必须覆盖消息框协程的隐藏、替换、跳过、禁用和销毁清理合同。
- 影响：
  - 禁用对话消息框或销毁 HUD 时，旧跳字协程不会继续写文本、播放 blip 音效或延迟触发选项显示。
  - 对话消息框的协程 owner 收口到自身组件生命周期，不依赖父级 HUD 间接调用 `Hide()` 才安全。
- 替代关系：
  - 本决策补强 `0015-对话 HUD 监听生命周期 owner 边界` 中未单独覆盖的消息框内部协程生命周期。
