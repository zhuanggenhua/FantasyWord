# System Rules（系统硬红线）

本文件只写强制红线：必须、只能、不得。具体做法放在 `.spec/knowledge/standards/` 或对应 skill。

## 沟通与汇报

- 必须始终使用中文沟通、写文档和写总结。
- 对用户汇报排查结果时，必须使用听得懂的中文；确实需要提内部字段、日志标签、数据库列名或代码符号时，先说明现实含义，再给原始符号作证据。
- 解释聊天机器人链路时，必须说明“历史记录”指真实平台聊天记录、传给模型的上下文、数据库保存记录、审计日志，还是插件/临时缓存；不得混称为 history。

## 前提锁定

- 修改代码、配置、数据、资源、场景、状态或执行会改变外部结果的动作前，必须锁定四项前提：问题对象、真相来源、目标入口/环境、验收口径。
- 四项任一缺失时，只能继续定位、补证据或问最小问题；不得先实施。
- 不得把用户口头转述、简称、情绪、相似案例、邻近记录或历史印象直接脑补成具体对象后开改。
- 准备修 bug 前，必须保留用户原始症状的关键限定词和数量范围；证据未命中同等症状时，必须说明“当前没有复现到你描述的这个症状”。

## 修复与验收

- 止血、降噪、限流、跳过、吞异常、兜底返回、避免崩溃、暂时绕开依赖，只能称为止血、缓解或临时保护；不得称为根因已解决。
- 完成、修好、通过等声称前，必须有新鲜验证证据。
- Bug 修复必须回到原始现实结果验收，不得用日志安静、页面不报错或局部现象消失替代。
- 子 agent 或工具报告“成功”不算验收证据；必须看真实 diff、输出、测试、场景、数据或用户可见结果。

## Git 与工作区

- 不使用 `git reset`、`git revert`、强制 `git checkout` 到旧提交等回滚/撤销历史操作；确需撤销先说明目标、影响和最小风险方案，等待用户确认。
- 未经用户当轮明确许可，不创建、切换、重建或删除分支、tag、worktree。
- 未经用户当轮明确许可，不提交、不推送、不发布。
- 不得回滚或覆盖用户已有改动；发现与当前任务冲突时先停下说明。

## Unity 与项目边界

- 当前项目不是旧 `FantasyWorld` 恢复任务延续；旧恢复记录只作为历史参考，不承载新游戏目标。
- 当前阶段不接入网络框架，不创建网络空壳。
- 不得把横版平台动作、MMORPG、账号服、专用服务器持久世界、大规模 AOI、多人经济或全图多人同步当成当前默认目标。
- Unity Editor 自动化默认优先通过项目接入的 UnitySkills 插件；只有插件无法覆盖、项目专项流程更贴合，或需要沿用既有 AIBridge 验证链时，才叠加 AIBridge。
- 第三方插件源码、插件编辑器界面、插件内置样式、插件示例文档或插件生成器本体，未经用户当轮明确许可不得直接修改。
- 接入或重构第三方插件、参考工程、原有系统时，必须先识别原设计入口、数据来源、加载时机、缓存策略、保存/刷新语义和验收位置。

## 引用与兜底

- 正式运行链路不得用 `FindObjectOfType`、`Object.Find*`、`GameObject.Find`、按名字/Tag/路径搜索等运行时查找作为依赖引用方式。
- 必需引用必须通过序列化字段、构造/初始化注入、显式配置资产、稳定 ID 映射或原系统正式入口提供。
- 必需引用缺失时必须直接报错并中断当前动作，错误信息要说明缺的是哪个现实对象、在哪个入口配置；不得静默兜底、自动找一个“看起来像”的对象、自动新建替代对象或继续执行。
- 兼容旧数据或一次性迁移脚本需要临时查找时，必须只在编辑器/迁移/诊断路径使用，写清用途和退出条件，不得进入正式运行路径。
- 禁止用兜底成功掩盖预期和表现不一致；如果预期引用不存在，验收结论必须是配置缺失或接入失败，而不是“已自动恢复”。

## 图片与视觉交付

- AI 读取本地图片、截图、JPG/PNG/WebP、OCR 裁图或图集切片前，必须先做上下文预算门禁；不得连续读取多张大图或把 atlas、整页截图、高清裁图直接反复丢给模型。
- AI 自己读图/核图不得自动打开到 PureRef；PureRef 是用户验收交付通道，不是 AI 读图通道。
- 用户要求“打开图片、给我看图、截图呢、我看看”等语义时，必须使用 `D:\codex-home\skills\show-image-to-user\SKILL.md`。
- 用户要求“设计稿、效果稿、生图、出图、视觉稿”时，默认交付位图图片，不得用网页、HTML、SVG 或代码稿冒充设计稿，除非用户明确要求。
- 实现导向设计稿必须服从当前前端/Unity 能力约束；不能复刻的图只能标为概念气质参考。

## 规范治理

- 新增规则、更新规范、新建或修改 skill 前，必须先判断落点：全局 AGENTS、项目 AGENTS、全局 skill、项目 skill、任务/用户故事/专项文档。
- 不得把本该进 skill 的具体 SOP、参数、命令顺序、验收清单直接塞进全局或项目根 AGENTS。
- `.spec` 结构、知识索引、skill 路由有改动时，必须同步相关索引和说明。
- 反复错误第二次进入 `.spec/knowledge/lessons.md`，第三次左右稳定复用时升级为正式规范、硬红线或 skill。
