# Dispatch（派活与审查提示骨架）

本文只定义 FantasyWord 的派活与审查交接骨架。具体任务仍必须先按 `.spec/skills/before-you-code` 锁定前提；代码、资源、场景或规范改动完成前必须按 `.spec/skills/verification-before-completion` 拿到新鲜验证证据。

## 适用场景

- 主 agent 要把已拆清楚的任务交给子 agent。
- 需要 reviewer 隔离审查完整交付。
- 多个任务可能并行，但文件集、场景、资源或规范落点必须先判定是否重叠。
- 用户要求 review、审查、复核或独立判断。

## 派发前提

派发前必须写清：

- 目标：本次子任务完成什么，不顺手扩范围。
- 可改范围：允许修改的文件、目录、资产或规范文档。
- 不可改范围：第三方源码、并行任务文件集、未授权 worktree/分支/提交等。
- 必读上下文：根 `AGENTS.md`、`.spec/AGENTS.md`、`.spec/rules/system.md`、`.spec/knowledge/README.md` 和任务专项文档。
- 真相来源：本仓文件、Unity Editor 状态、日志、测试输出、用户指定路径或外部参考。
- 验收口径：必须回到哪里验证，以及哪些证据算完成。

## 子 Agent 派发模板

```text
模型配置：gpt-5.4 + high
不得降级模型，不得改用其他模型。
不得再派生子 agent。

【任务目标】
<一句话说明完成什么>

【可改范围】
<路径 / 目录 / 资产 / 文档>

【不可改范围】
<路径 / 第三方 / 并行文件集 / 未授权操作>

【必读上下文】
<规范、skill、任务卡、真相来源>

【验收口径】
<命令、截图、Unity 自动化、日志、diff 或文档结构校验>

【交回物】
1. 改动清单。
2. 验证证据：命令与关键输出。
3. known gaps。
4. 是否需要知识沉淀或后续决策。
```

## Reviewer 触发模板

```text
模型配置：gpt-5.4 + high
不得降级模型，不得改用其他模型。
不得再派生子 agent。

【审查级别】
快审 / 深审 + 原因

【审查对象】
<任务目标、完整 diff、交付报告、验证证据>

【审查依据】
<用户原始目标、项目红线、专项规范、验收口径>

【范围外】
<并行在途文件集、未授权范围、只登记不处理的问题>

【输出要求】
放行 / 退回；问题按严重度排序；每条问题说明现实影响、证据位置和建议修法。
```

## 串并行边界

- 文件集、场景、Prefab、ScriptableObject、规范落点或生成源重叠时必须串行。
- 未经用户当轮明确许可，不创建、切换、重建或删除 worktree、分支或 tag。
- 并行只允许发生在任务目标、可改范围、验证入口都互不重叠时；合流后主 agent 必须复查完整 diff 和全局验证。
- 子 agent 或 reviewer 报告“成功”不算完成证据；必须看真实 diff、命令输出、测试、截图、场景状态或文档结构校验。
