# 第三方插件接入清单

> 本文记录当前工程已接入、已导入或作为参考源保留的第三方插件与外部框架。
> 这里的“接入”只说明工程中存在或包依赖存在，不自动代表它已经成为正式玩法真相源。

## 使用原则

- 第三方插件本体默认保留原目录和 `.meta` / GUID，不擅自移动、删改或重组。
- 已导入且能编译的插件默认可以使用；遇到插件已经覆盖的职责，优先使用插件原能力或公开扩展点，不要另造一套项目侧替身。
- 正式玩法入口优先落在 `Assets/Scripts/GameCore`；这表示项目业务语义和组合入口归 GameCore，不表示要重写插件已经提供的底层能力。
- 同职责系统只能有一个真相源。真正禁止的是“插件已能承担职责，却又新增 `Compatibility`、`Adapter`、`Wrapper`、`FoundationSupport` 或项目侧重复实现来并行承载同一职责”。
- 当插件承担某个正式职责时，只需要写清楚项目从哪个正式入口调用它、它替代了哪套项目侧重复实现、怎么验证没有第二套状态；不需要为“能不能用插件”再单独开许可。
- 只为编译依赖或工具依赖引入的包，不等于项目已采用对应完整方案。
