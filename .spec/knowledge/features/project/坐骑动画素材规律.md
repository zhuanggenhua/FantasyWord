# 坐骑动画素材规律

> 目的：处理坐骑接入、坐骑动作映射、坐骑资产生成器和验收时，先确认素材结构，再决定代码对接方式。

## 当前素材审计结论

- 当前坐骑素材根目录：`Assets/Art/坐骑/迷你幻想_坐骑_v1.0/迷你幻想_坐骑_素材`。
- 当前工程扫描未找到真实龙/Dragon/Drake/Wyvern 坐骑素材；只有 TableForge 示例数据命中 Dragon/Drake。后续若导入龙素材，必须按本文规则重新审计，不能把当前结论冒充已看过龙。
- 坐骑包分两类：
  - `新 坐骑`：同时包含坐骑本体、骑手层，部分目录还含历史阴影素材，例如 War 马、独角兽、自行车、魔法地毯、独木舟。
  - `骑手 图层 用于 其他 迷你幻想 动物`：只提供其他动物的骑手层，例如北极熊、大象、座狼、熊猫、巨型蜗牛、巨型蟾蜍；动物本体需要从对应动物素材包另行对齐。
- 每个动作通常是一张 PNG SpriteSheet，不是一个 Unity Animator 状态。画布仍按 32x32 帧格切分，宽高差异反映“帧数 × 方向行数”。
- 同一坐骑动作的坐骑本体和骑手层必须同动作、同方向、同帧索引同步播放，不能单独改偏移或挂点当作接入前提。阴影当前不进入坐骑动作分类；普通角色阴影由换装 Shader 根据帧数据生成。
- 本轮扫描了 783 张坐骑相关 PNG，归并出 160 个“坐骑/动作”组合；阴影文件单独归类为排除项，不参与动作统一性判断。

## 抽样规律

| 坐骑/骑手层 | 动作文件夹或文件 | 尺寸规律 | 结论 |
| --- | --- | --- | --- |
| War 马 | 本体：待机 384x128、行走 128x128、受伤 128x128、死亡 352x32；骑手层同待机/行走/受伤/骑乘上/骑乘下 | 32x32 帧格；待机多帧四行，行走/受伤四行，死亡单行 | 本体和骑手层可用同一帧索引同步；阴影不作为动作分类依据。 |
| 独角兽 | 本体：待机 384x128、行走 128x128、受伤 128x128、死亡 384x32；骑手层同待机/行走/受伤/骑乘上/骑乘下 | 结构与 War 马接近 | 可复用同一坐骑动作语义和播放器。 |
| 自行车 | 本体：站立 160x32、待机 384x128、移动 128x128、受伤 128x128；骑手层：待机/移动/受伤/骑乘上/骑乘下 | 素材叫“站立/移动”，不叫角色 Walk | 需要把角色 Idle/Walk 映射成坐骑 Stand/Move，而不是要求同名。 |
| 魔法地毯 | 本体：待机 128x128、飞行 128x128、受伤 128x128、死亡 576x32；骑手层：待机/飞行/受伤/骑乘上/骑乘下 | “飞行”本质是移动语义 | Move 语义下允许素材动作名是飞行。 |
| 独木舟 | 本体：停泊 32x128、待机 576x128、冲浪 192x128、受伤 128x128、沉没 384x32；骑手层：待机/冲浪/受伤/沉没 | 有水上特化动作名 | Stand/Move/Hurt/Die 语义足够承载常规播放，沉没映射 Die。 |
| 北极熊骑手层 | 待机 608x128、行走 192x128、攻击 160x128、受伤 128x128、骑乘上/骑乘下 160x32 | 帧数比马更多 | 通用播放器不能假设每个动作帧数一致。 |
| 大象骑手层 | 待机 384x128、行走 192x128、受伤 128x128、骑乘上/骑乘下 160x32 | 无攻击层 | 验收要按该坐骑支持集检查，不得要求所有坐骑都有 Attack。 |
| 巨型蜗牛骑手层 | 爬行 128x128、受伤 128x128、InShell/OutShell 160x128、骑乘上/骑乘下 160x32 | 有壳状态特化动作 | 特化动作走自定义扩展，不进入基础移动爆炸。 |
| 巨型蟾蜍骑手层 | 待机 512x128、攻击 256x128、跳跃 128x128、受伤 128x128、骑乘上/骑乘下 160x32 | 跳跃可作为移动或技能动作 | 按语义映射，不为每种动词新增 Animator 状态。 |

## 动作分类裁决

| 分类 | 扫描命中 | 帧结构 | 裁决 |
| --- | --- | --- | --- |
| Stand | 待机、站立、停泊；28 个坐骑/动作组合 | 多数四向，1/4/5/11/12/16/18/19 帧都存在；自行车站立是 5x1，独木舟停泊是 1x4 | 统一成 Stand 语义；播放器必须支持可变帧数和单行/单列素材。 |
| Move | 行走、移动、飞行、冲浪、爬行；27 个组合 | 全部四向，常见 4x4 或 6x4 | 统一成 Move 语义；飞行、冲浪、爬行只是作者动词，不新增全局动作状态。 |
| Hurt | 受伤；28 个组合 | 全部 4x4 | 可作为基础通用语义，但只按坐骑支持集播放。 |
| Die | 死亡、沉没；5 个组合 | 全部单行，常见 11x1、12x1、18x1 | 统一成 Die 语义，但播放规则必须支持单行动作、非循环和播完回退/停留。 |
| MountUp | 骑乘上；21 个组合 | 全部 5x1 | 统一成上下坐骑流程动作，不由 Idle/Walk 自动触发。 |
| MountDown | 骑乘下；22 个组合 | 全部 5x1 | 统一成上下坐骑流程动作，不进入普通移动状态循环。 |
| Attack | 北极熊、座狼、狮/虎/母狮、犀牛、巨型蟾蜍等；7 个组合 | 四向，4/5/8 帧都有 | 作为可选通用语义；不能要求所有坐骑都有 Attack。 |
| Jump | 巨型蟾蜍跳跃；1 个组合 | 4x4 | 特殊覆盖。可以由技能/状态请求，也可以作为该坐骑 Move override，但不能全局把 Jump 等同 Move。 |
| SpecialPose | 蜗牛 InShell/OutShell、熊猫趴下/站立上/睡眠；5 个组合 | 四向，3/5/6 帧都有 | 特殊覆盖或自定义动作键，不能塞进 Stand/Move 基础语义。 |

结论：可以做统一动作系统，但统一的是“语义 + 播放器能力”。基础语义为 `Stand / Move / Hurt / Die / MountUp / MountDown`；`Attack` 是可选通用语义；`Jump / ShellIn / ShellOut / LieDown / StandUp / Sleep` 等按坐骑资产特殊覆盖。

## 具体动作相似度

这里的“共用动作”必须分三层说清楚：

| 层级 | 能否共用 | 说明 |
| --- | --- | --- |
| 播放器/状态 | 能 | 例如所有 Move 都走同一个“按方向行 + 帧索引循环”的播放器。 |
| 播放模板 | 部分能 | 同为 4x4 或 6x4 的动作可以共用帧数、循环和方向规则；4x4 马行走不能直接当 6x4 河马行走模板。 |
| 具体 Sprite 帧 | 不能跨坐骑通用 | 每个坐骑仍取自己的本体帧和骑手层帧；AnimationClip 若绑定具体 Sprite，就不能一份通吃。 |

按人类骑手层的有色像素位置比较，当前可得到这些结论：

- War 马、普通马、独角兽的骑手层在 `待机 / 行走 / 受伤 / 骑乘上 / 骑乘下` 上是同一组具体帧；可以共用同一份骑手帧数据。
- 母狮和老虎在 `待机 / 行走 / 受伤 / 攻击` 上是同一组具体帧；狮子与它们非常接近，但不是完全同一像素。
- 马和河马不是同一套具体动作：马行走是 4x4，河马行走是 6x4；待机也是马 12x4、河马 16x4。它们只能共用 Move/Stand 播放器，不能共用同一份具体行走帧或固定 4 帧模板。
- 河马和骆驼的受伤动作运动变化接近，但像素位置有整体差异；可共用 Hurt 播放器，不应直接共用 Sprite 帧。
- 上下坐骑动作大多是 5x1，适合共用同一个流程播放器；但马和河马的骑手像素位置仍不同，具体帧不能直接互换。

## 正式对接规则

1. 玩法装备槽位已经有 `EEquipmentType.Mount`；坐骑资产应占用这个玩法槽。普通换装表现枚举 `EquipmentType` 不需要新增 Mount，因为坐骑不走服装/头盔/武器那套 UV 合成表。
2. 坐骑运行时不复用普通角色 Animator Clip，也不生成“动物 × 动作 × 方向”的 Animator 状态组合。
3. 正式结构是“角色动作输入 -> 坐骑动作语义 -> 坐骑资产逐帧数据 -> 本体/骑手基础层 SpriteRenderer”：
   - 角色 `Idle/Wait` 输入映射为坐骑 `Stand`。
   - 角色 `Walk/Run/Move` 输入映射为坐骑 `Move`。
   - 角色 `Attack/SlashAttack/ChargedAttack` 输入映射为坐骑 `Attack`。
   - 角色 `Dmg/Dmg2` 输入映射为坐骑 `Hurt`。
   - 角色 `Die/SpinDie/SoulDie` 输入映射为坐骑 `Die`。
   - 上下坐骑走 `MountUp/MountDown`，由上下坐骑流程主动请求，不从普通 Idle/Walk 推断。
4. 每个坐骑资产只声明自己支持哪些语义；不支持的语义按资产默认动作回退，但报告必须可见，不能说成该动作已真实接入。
5. 素材文件夹名可以是待机、站立、停泊、行走、移动、飞行、冲浪、爬行、攻击、受伤、死亡、沉没、跳跃、InShell/OutShell、趴下、站立上、睡眠；这些是作者素材名，不是运行时代码必须同名的动作合同。
6. 骑手层不是普通站立角色 Sprite。无普通装备时按作者骑乘姿态 Sprite 原版直显；有普通装备时仍使用同一张作者骑手 Sprite 作为当前帧，并基于该坐骑的骑乘 `CharacterFrameData`、Body/Head UV 复用现有换装合成。
7. 四向动作默认必须分别提供 SE/SW/NE/NW；只有作者明确提供单向共用动作时，资产才能显式选择 `SharedSouthEast`。缺方向不得静默借用 SE。
8. 本体和骑手都有帧时数量必须一致；只有上/下坐骑、死亡等确实缺少某一层的动作，才能显式选择“保持上一帧”或“隐藏图层”。
9. 非循环动作必须明确播完后停最后一帧、回到角色动作或卸下坐骑；自定义动作必须保留 `Jump/Sleep` 等精确键，不能让所有特殊动作命中第一个 Custom。

## 设计结论

- 可以做通用动画，但通用点不是“一个通用 Animator Clip”，而是“一个通用逐帧播放器 + 每个坐骑自己的 Sprite 数据 + 动作语义映射”。
- 这样新增坐骑时只增加数据，不增加角色 Animator 状态数量；新增特殊动作时优先作为该坐骑支持集或自定义语义，不让所有坐骑跟着爆炸。
- 验收必须覆盖该坐骑支持的语义、四向和本体/骑手基础层；每个“动作 × 方向”至少对照资产验证第 0 帧和下一帧，不能只检查 Sprite 非空。阴影不作为坐骑动作接入门槛。最终视觉交付仍必须回到真实 GameView 完整截图，动作时序问题必须补真实 GameView GIF 或连续帧证据。
