# 素材与表现规范

## 适用范围

- 像素素材、Sprite、动画、Sprite Library、Shader、材质、Prefab 表现层。
- MiniFantasy 正式美术资源、装备换装素材和俯视角开放世界地图表现。

## 当前素材边界

- `Assets/ThirdParty/MiniFantasyUV`：MiniFantasy UV 资源/来源链证据，默认保留。
- `Assets/Art`、`Assets/ArtRes`、`Assets/Minifantasy_NPCs_Assets`、`Assets/Sprites`：MiniFantasy 与当前像素资源主来源集合。MiniFantasy 是正式美术基线；目录重整前先保留并审查引用。
- `Assets/GameData/EquipmentSystem`：当前装备/换装相关 ScriptableObject 数据候选，已从旧 `Assets/Data` 迁入并保留 `.meta`。
- `docs/archive/mini-fantasy-uv-evidence`：MiniFantasy UV 迁移证据，不是框架本体，不当作临时垃圾删除。
- `Assets/Database`、`Assets/Prefabs`：旧 RPG 业务数据库和业务 Prefab，当前保留在 `Assets` 入口，作为后续迁移与重构来源。
- `Assets/Art/MINIFANTASY - Crafting and Professions I/Scenes`、`Assets/Art/MINIFANTASY Creatures - Super Low Res 2D Pixel Art by Krishna Palacio/Scenes`：MiniFantasy 素材包自带 demo 场景，当前保留原目录结构，只作为来源证据、导入设置和接线参考；正式玩法场景要另行建立。
- `Assets/Plugins/TopDownEngine` 及其它参考工程自带的图片、Tile、Prefab、场景和音频，只能作为参考工程随带资源或插件依赖资源；不得作为 FantasyWord 正式美术素材来源，也不得替代 MiniFantasy 的角色、地图、怪物、道具或换装规格。

## 迁移规则

- 移动 Unity 资产时必须保留 `.meta`，避免 GUID 断裂。
- 没有确认引用关系前，不移动场景、Prefab、Sprite Library、Animator Controller 和 ScriptableObject。
- 第三方素材应保留来源结构或在文档中记录来源、授权、导入设置和用途；当前正式美术优先以 MiniFantasy 为主来源。
- 第三方素材包、自带 demo 场景和示例脚本，默认保留在原目录结构中；未经用户明确允许，不得擅自移出、归档或并入项目自定义目录。
- 参考工程素材进入项目只能服务“看结构、看接线、看导入设置”的参考目的；没有用户明确确认前，不得被场景、Prefab、装备或角色表现链当成正式美术资产。
- 缺少正式素材时必须向用户确认或等待用户提供；不得 AI 自绘、生成、从图集中临时切占位、从参考包借图，或把调试辅助图当成正式素材接入玩法链路。
- 如果用户明确允许临时占位，文件名、目录、配置和文档必须标明 `Placeholder` / `占位`，并且不得作为正式验收通过依据；占位资源进入正式链路前必须替换为正式素材。
- 只有非第三方的项目业务资源，才允许在保留 `.meta` 和引用闭包的前提下按新项目结构迁移。
- 正式角色表现要区分数据、素材、运行时渲染器和编辑器工具，不把所有内容继续塞进一个实验目录。

## 正式命名

- 正式进入玩法链路的项目侧表现资产必须优先中文命名，包括角色/怪物/道具 `Prefab`、角色数据 `ScriptableObject`、技能/装备/表现相关 SO、`Sprite Library`、动画相关派生资产、正式场景实例名和正式测试场景入口名。
- 新增或重命名 SO 时，资产文件名、`CreateAssetMenu` 默认文件名、菜单路径和 Inspector 显示名都优先使用中文；需要稳定 ID、外部协议键或跨工具 ASCII 键时，把英文键放在字段或资源键中，不用它替代面向作者的中文资产名。
- 第三方素材包原始目录、原始文件名和来源证据可保留原名；这不等于项目正式落点也继续沿用英文占位或参考名。
- 若正式资产需要稳定 ID、外部协议键或跨工具兼容键，可继续使用 ASCII；但它必须表达当前项目语义，例如 `player_main`，不能继续保留 `hero_devon` 这类历史占位含义。
- 正式美术链一旦切到 MiniFantasy，就不再把 TopDownEngine、2DRPGEngine 或其它参考工程自带图片命名成正式角色名义。

## 表现目标

- 俯视角像素角色应优先支持方向、动作、装备层、基础交互反馈。
- 开放世界地图表现优先支持 Tilemap、场景对象、采集点、交互提示和区域切换。
- 不继承横版平台动作的相机、地面检测和平台动作表现规则。

## 验证方式

- 静态阶段：确认资源路径、GUID、引用和导入设置。
- Unity 阶段：必要时用 AIBridge 刷新资源、查询 Console 和运行定向测试。
- 可视阶段：只有用户要求当前画面或静态证据不足时，才截图或进入 PlayMode。
- 地表、植被、覆盖层和元素反应的视觉验收必须验证真实 Tilemap 层级关系：例如“烧掉草露出土壤”只能由草覆盖/植被层被移除后露出原本存在的土壤底层证明，不得用新盖一张 Dirt/焦土 Tile 当作通过。草层是可销毁、可再生的覆盖层；底层土壤才是地表本体。

- 图集、SpriteSheet、扫描图和整页截图的核对必须区分总览与细节：总览只判断布局、行列和区域关系；具体文字、帧边界、索引、角色层级和导入结论必须回到关键分块或单对象裁图。
- 为素材核对生成的裁图、OCR 图、标注图和对照图默认是排查辅助证据，不等于正式资源；不得放入正式 `Assets` 资源链，也不得替代原始素材、`.meta` 引用闭包或正式导入设置。
