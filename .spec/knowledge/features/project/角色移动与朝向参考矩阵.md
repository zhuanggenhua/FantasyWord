# 角色移动与朝向参考矩阵

> 本文专门解决“移动、转向、朝向、瞄准、动画方向被混在一起”的问题。
> 以后改玩家朝向、AI 追击转向、战斗游走、攻击前对准、武器瞄准或四向动画前，先读本文。

## 当前结论

- 转向行为的参考不止 `duolafashi`。`duolafashi` 命中 AI 状态级转向和战斗游走；`TopDownEngine` 命中 2D 朝向/旋转能力拆分；`uMMORPG` 命中战斗中看向目标；SunnyValleyStudio 命中 2D context steering 与“移动输入/指向目标”分流；GDQuest、gdx-ai、OpenSteer、UnitySteer 和 Unity 教学源码进一步证明 `Face / LookWhereYouAreGoing / MatchOrientation / Wander` 是可组合的独立行为，不是一个移动求解器里的默认副作用；当前项目还要对齐自己的 `Movable / CharacterMovement / AIController / CharacterAbilitySet / DirectionalSpriteLibraryDriver` 正式闭包。
- 之前留档确实不够清晰：`参考源映射.md` 和 `代码参考矩阵.md` 把它们压在“移动”“AI 控制”“ContextSteering2D 适配”里，没有把“身体朝向”和“移动求解”拆成独立职责。
- `ContextSteering2D` 只能决定移动建议和避障结果；它不能自动替代身体朝向、攻击目标方向、武器瞄准方向或动画方向。
- 玩家方向输入必须先更新身体朝向，再进入物理移动和碰撞处理；因此撞墙或被挡住时也能转身。
- AI 是否面向目标、面向移动方向、攻击前等待对准、或游走时保持目标朝向，必须按状态和开关显式裁决，不能靠移动向量顺手决定。当前 `AIController` 已把追击身体朝向和战斗游走身体朝向做成显式模式，`CharacterSteeringRuntime2D` 不再隐式改身体朝向。
- 参考没有的行为不能编造；参考已有的职责不能因为之前没登记就忽略。

## 术语边界

| 中文职责 | 现实含义 | 当前项目主要落点 |
| --- | --- | --- |
| 移动意图 | 玩家输入、点击移动或 AI 想往哪里走 | `CharacterMovement.HandleDirectionalMove(...)`、`Movable.SetMovementDirection(...)`、`CharacterSteeringRuntime2D.ApplyLatestResult(...)` |
| 移动求解 | 根据目标、避障、距离和邻居算出安全移动方向 | `ContextSteering2D`、`AIController.BehaviourRuntime` |
| 身体朝向 | 角色当前实际面向哪里，四向动画和换装表现读它 | `Movable.SetLookAtDirection(...)`、`Movable.GetLookAtDirection()` |
| 目标方向 | 技能、交互或武器当前要指向哪里 | `Movable.SetTargetDirection(...)`、`CharacterAbilitySet` |
| 武器瞄准 | 武器或投射物自己的瞄准方向，可和身体朝向不同 | `CharacterHandleWeapon`、`CharacterAbilitySet`、GAS 输入上下文 |
| 动画方向 | 把身体朝向映射到动画参数、SpriteLibrary 或装备层方向 | `FollowTargetDirection`、`BidirectionalAnimationStrategy`、`PolydirectionalAnimationStrategy`、`DirectionalSpriteLibraryDriver` |

### 不采用原因分类

- `同类更好`：同一职责已有更贴近当前项目的参考。例如人形 2D 朝向优先看 TopDownEngine、duolafashi、gdx-ai，而不是 OpenSteer 车辆模型。
- `职责不匹配`：参考提供的是移动求解、车辆局部坐标或教学示例，不能证明身体朝向、战斗锁脸或攻击前对准。
- `产品/引擎不匹配`：参考绑定 Godot、Java、Mirror、3D NavMesh、MetaWorld 或车辆/飞行器产品假设。
- `质量不足`：教程样本、旧库或热路径分配明显，只能佐证职责，不能作为正式架构 owner。
- `证据不足`：注释代码、未启用行为、只出现名称或阶段记录，不能支撑正式实现。
- `当前已有正式 owner`：当前项目已有 `Movable / CharacterMovement / AIController / CharacterAbilitySet / DirectionalSpriteLibraryDriver / ContextSteering2D`，不得新增第二套同职责入口。

## 外部公开参考补充裁决

- `Face` 的现实含义是“面向目标位置”：GDQuest、gdx-ai 和 Unity 教学源码都先用目标相对位置算目标朝向，再委托角向到达/对齐行为。
- `LookWhereYouAreGoing` 的现实含义是“面向当前运动方向”：gdx-ai、GDQuest 和 Unity 教学源码都用线速度计算目标朝向；没有速度时不应凭空选一个新方向。
- `ReachOrientation / MatchOrientation / Align` 的现实含义是“只负责转向，不负责移动”：它们输出角向加速度或角向旋转结果，线性移动保持为零。
- `Wander` 的现实含义是“随机游走移动意图”：libGDX 明确给出两种实现路线，`Seek + LookWhereYouAreGoing` 或 `Face + 当前朝向前进`；其中 `Face` 在独立朝向模式下才显式开启，不是默认必然。
- `SunnyValleyStudio/Unity-2D-Context-steering-AI` 的现实含义是“2D context steering 教程闭环”：移动方向来自 `ContextSolver`，目标指向来自 `EnemyAI` 的 pointer 事件，二者在参考中就是两条输出；它不能证明游走或角向到达，只能证明移动求解不应冒充完整身体朝向。
- `OpenSteer / UnitySteer` 的车辆式默认是速度对齐朝向；这适合车辆、飞行器或纯 steering agent，不能直接覆盖当前项目的玩家输入朝向、战斗锁脸、四向动画和武器瞄准职责。
- 参考源码里确实存在 `alignment_tolerance / deceleration_radius / targetRadius / slowRadius` 这类角向到达算法参数，但它们只能作为 `ReachOrientation / MatchOrientation / Align` 行为自身的参数证据，不能被拿来给 AI 状态层随便新增“阈值门槛”。

## 后续改代码前必须回答

任何涉及转向/朝向的代码改动，先写清下面 5 项：

1. 改的是哪一类职责：移动意图、移动求解、身体朝向、目标方向、武器瞄准、动画方向。
2. 命中的参考来源是哪一个文件或节点；若参考没有该行为，明确写“参考没有，不做”。
3. 当前项目正式 owner 是哪一个文件；不得新增并行控制器或把临时脚本当正式入口。
4. 该行为是否可选；如果参考是可选模式，项目侧也必须保持可选，不得默认强开。
5. 验收回到哪个原始入口：玩家输入、AI 追击、攻击前对准、游走、技能瞄准或四向动画。

## 禁止误用

- 不得再把 `ContextSteering2D` 的安全移动方向叫作“完整转向逻辑”。
- 不得用新阈值、新平滑参数或新随机状态替代参考里不存在的行为。
- 不得把外部参考里的角向到达参数，偷换成当前 AI 状态层的新阈值；只有实现 `ReachOrientation / MatchOrientation / Align` 同职责行为时，才允许按该行为自身参数裁决。
- 不得把 OpenSteer / UnitySteer 的车辆式“速度对齐朝向”默认套到当前 2D 人形角色；它们只证明车辆模型可以这么做，不证明战斗敌人应该永远笔直朝移动方向冲。
- 不得再把 SunnyValleyStudio 藏在一次性 `openspec` 里当“已记录”。凡是它影响当前 `ContextSteering2D`、AI 移动或朝向裁决，必须在本文和 `参考源映射.md` 这种正式入口里可见。
- 不得把教学源码里 `AddSharedBehaviors()` 会加 `LookWhereYouAreGoing`，扩大成所有追击、攻击、游走都必须面向移动方向；教学源码同时也有 `StartFace(...)`，说明面向目标是另一个显式行为。
- 不得因为 `duolafashi WanterNode` 里目标转向调用被注释，就推导出“所有游走都不能看目标”；只能说明该节点本身没有启用目标转向。
- 不得因为 `TopDownEngine` 有 `FacingModes.Both`，就把身体朝向、武器瞄准和动画方向长期混成一条真相。
- 不得用 `uMMORPG` 的 Mirror、3D NavMesh 或 CharacterController 实现来替代当前 2D `Rigidbody2D + Sprite` 闭包。
- 不得把“已有测试证明玩家输入能转身”扩大成“AI 追击转向也已经完成”；AI 追击转向必须看到 `m_targetPursuitFacingMode` 这类状态层显式裁决和 `SetSteeringMovementDirection(...)` 不改身体朝向这两条证据。

## 当前缺口

- AI 追击身体朝向已按状态显式裁决：默认 `FaceTarget`，可选 `FaceMovement` 或 `KeepCurrent`；后续若改默认值，必须回到参考矩阵说明原因。
- AI 攻击前对准已补为独立状态门禁：默认要求身体朝向进入 5 度完成角后才触发 GAS；若某类敌人不需要等待，可显式关闭 `m_requireTargetFacingBeforeAttack`。
- 战斗游走身体朝向已做成明确配置，默认 `KeepCurrent`；若要游走时锁脸目标，必须显式选择 `FaceTarget`，不能从 `WanterNode` 注释代码自动推出。
- 现有 `参考源映射.md` 仍是总入口，本文是角色移动/朝向专项入口；二者冲突时，以本文对该专项职责的拆分为准。
