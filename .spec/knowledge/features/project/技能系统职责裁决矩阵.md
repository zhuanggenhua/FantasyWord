# 技能系统职责裁决矩阵

> 本文只回答一件事：`FantasyWord` 的技能系统里，每个职责当前应该参考谁、为什么、现态能不能直接进正式真相。
> 本文按职责裁决，不按“哪套框架整体胜出”裁决。

## 使用规则

- 具体吸收谁，唯一依据是同职责参考里谁实现得最好。
- 不预设 `EX-GAS`、`2DRPGEngine`、`duolafashi`、Kybernetik Platformer Game Kit 任何一个整体胜出。
- 同一职责只能有一个正式真相；编辑面可以有多个候选，但运行时语义和资产真相只能有一个。
- 当前基础攻击可跑，只代表开发技术链可继续；不代表策划正式作者流程已经成立。
- 本文只裁决技能系统职责，不确认职业、技能树、默认技能内容或玩家正式构筑模型。
- 本文若写“当前最佳候选”，只表示该职责下当前证据最充分的候选，不表示整个技能系统已经裁定总赢家。

## 职责裁决

### 1. 技能身份真相

- 职责含义：
  - 技能的稳定 ID、名字、描述、授予来源、引用的执行资产、引用的规则映射从哪里读。
- 候选参考：
  - `2DRPGEngine AbilitySheet`
  - `EX-GAS AbilityAsset`
- 当前最佳候选：
  - 对正式技能，`EX-GAS Ability` / Ability Code 胜出。
- 原因：
  - 正式技能的稳定 ID、名称、描述、授予、装备槽、触发、保存、运行实例和规则绑定都已经以 GAS Ability Code 为主键。
  - 继续让 `AbilitySheet` 承担同一份身份真相，会制造第二套技能身份、第二套作者入口和第二套旧存档解释路径。
- 为什么不是其他候选：
  - `2DRPGEngine AbilitySheet` 只保留旧存档反序列化和存量资产升级线索；不能再作为正式技能身份 owner。
  - `duolafashi` 没证明自己适合做技能身份真相。
  - Kybernetik 不处理技能身份层。
- 正式结论：
  - 正式技能的正式身份入口必须是 EX-GAS Ability / Ability Code。
  - `AbilitySheet` 不能再作为正式技能的正式身份、图标、输入、执行、规则、表现或装备入口。
- 现态与缺口：
  - 基础攻击已按 EX-GAS Ability Code 进入菜单、装备槽、授予/撤回、压制、读档恢复、运行实例和规则绑定。
  - 旧 `AbilitySheet` 字段只用于未迁移技能和旧数据兼容；正式基础攻击旧表进入旧字段时必须被过滤或拒绝。
  - 正式基础攻击的 `MeleeAttackAbilitySheet` 现在只保留旧数据反序列化壳；它不能再从旧执行资产、旧蓝耗或旧冷却生成说明文本，正式说明只允许从 EX-GAS Ability / Timeline / GameplayEffect 派生。
  - 项目侧校验器也不能再把 `MeleeAttackAbilitySheet` 解释成“应绑定 `MeleeAbilityExecutionAsset`（已删除）、应实例化 `MeleeAttackAbility`”的正式结构；正式普攻的执行资产和运行组件入口必须从 EX-GAS Ability Code / `exgas.abilityGameCore` 解析。
  - 旧 `AbilitySheet` 资产本体不得残留 `m_formalGasAbilityCode` 这类已删除 GAS 身份字段；如果要表达 GAS 技能，必须写入正式 EX-GAS Ability 配置或明确的 GAS code 字段，不能靠旧表 YAML 残留承载身份。
  - `20002` 变形替换 smoke 已在 EX-GAS Ability / `exgas.abilityGameCore` / Timeline 中表达，旧 `测试-变形替换能力.asset` 不再保留，避免同一技能同时存在 GAS 表身份和旧 `AbilitySheet` 资产身份。
  - 旧执行资产自定义 Inspector 不再保留；冲刺、投射物、召唤等后续能力如果迁移，作者入口也必须落在 EX-GAS Ability / Timeline / GameplayEffect / Cue，而不是恢复项目侧旧执行资产编辑器。

### 2. 规则真相

- 职责含义：
  - 资源消耗、冷却、标签、属性修改、持续状态、Granted Ability、伤害/治疗等规则结果由谁定义和结算。
- 候选参考：
  - `EX-GAS GameplayEffect / Cost / Cooldown / Tags`
  - `2DRPGEngine` 旧 `IEffect` 体系
- 当前最佳候选：
  - `EX-GAS` 胜出。
- 原因：
  - 规则结果需要可叠层、可审计、可组合、可存档、可扩到复杂法术体系。
  - `EX-GAS` 在属性、标签、效果和持续状态上证据更完整。
- 为什么不是其他候选：
  - `2DRPGEngine` 的旧能力族足够做轻 RPG 技能，但对完整法术体系的规则强度不够。
  - `duolafashi` 不是规则系统参考。
- 正式结论：
  - 规则真相应收口到 `EX-GAS`。
- 现态与缺口：
  - 当前基础攻击与基础投射物的命中后伤害已不再并行保留 `IEffect` 规则表达，正式扣血链已经收口到 `GameplayEffect`。
  - 但近战/投射物的命中扫描与执行时序仍是项目侧执行壳，因此不能把当前现态表述成“整个技能执行闭包已经完全 GAS 原生化”。
  - 后续必须持续消灭同职责的非 GAS 规则重复表达。

### 3. 执行真相

- 职责含义：
  - 技能施放时序、动画窗口、命中扫描、投射物生成、区域生成、召唤生成、命中反应调用由谁执行。
- 候选参考：
  - `2DRPGEngine` 运行时技能族
  - `duolafashi` 时间轴内容生产流
  - `EX-GAS TimelineAbility / TargetCatcher`
- 当前最佳候选：
  - 对基础攻击这类正式技能，EX-GAS Timeline / Task / TargetCatcher 胜出。
- 原因：
  - 基础攻击已跑在 `Ability -> ALTimeline -> TaskApplyEffects -> TargetCatcher -> GameplayEffect -> Cue` 主链路上。
  - 普攻命中时序、动画 Cue、目标捕获和规则结算都已从旧近战执行资产迁出。
  - 保留项目侧 `ActiveAbilitySheet` / 旧执行资产执行路径会与 EX-GAS Timeline 争夺同一份执行真相；旧执行资产路径已经删除。
- 为什么不是其他候选：
  - `2DRPGEngine` 和 TopDownEngine 只能作为行为节奏、权限和反馈触发点参考，不能把它们的 `AbilitySheet` / `CharacterAbility` / `Weapon` 模型混回正式运行时。
  - `duolafashi` 仍可作为复杂投射物和表现拼装参考，但不能替代当前正式普攻的 EX-GAS 执行 owner。
- 正式结论：
  - 正式技能的执行真相必须收口到 EX-GAS Ability / Timeline / Task / TargetCatcher。
  - 项目侧只允许保留必要的 GameCore 生命周期桥、输入桥、资源桥和 2D TargetCatcher 扩展，不再保留同职责旧执行资产路径。
- 现态与缺口：
  - 基础攻击已迁入 EX-GAS Timeline；未迁移投射物、召唤、冲刺等旧技能仍是兼容范围，不代表 `AbilitySheet` 可继续承担正式技能职责。
  - 独立特效 Cue 需要等素材拆出后继续接入 EX-GAS Cue 路径。

### 4. 表现真相

- 职责含义：
  - 动画、特效、音效、震屏、飘字、命中反馈等项目侧表现从哪里配置、由谁分发。
- 候选参考：
  - `GameplayFeedbackSet`
  - `EX-GAS GameplayCue`
  - `duolafashi` Prefab / Timeline 表现挂点
- 当前最佳候选：
  - 项目侧 `GameplayFeedbackSet` 胜出，`GameplayCue` 只作为触发入口。
- 原因：
  - 用户已经明确要求单一真相，项目里现有反馈系统不能和 Cue 并行竞争。
  - `GameplayCue` 适合做“规则触发表现”，不适合做第二套项目反馈模型。
- 为什么不是其他候选：
  - 直接把表现真相放到 `GameplayCue` 会制造第二套反馈系统。
  - `duolafashi` 证明的是表现挂点组织，不是项目反馈真相边界。
- 正式结论：
  - 表现真相留在 `GameplayFeedbackSet` 或其唯一正式替代者。
  - `GameplayCue` 只负责触发/转发，不拥有规则或反馈主模型。
- 现态与缺口：
  - 方向已明确。
  - 仍要继续清理任何把项目表现字段再复制一份到其他资产里的倾向。

### 5. 近战命中框作者面

- 职责含义：
  - 策划如何可视化编辑基础攻击、蓄力攻击、背刺这类近战技能的命中窗口和命中形状。
- 候选参考：
  - Kybernetik Platformer Game Kit
  - 当前 `AbilitySheet` Inspector
  - `EX-GAS` 原生时间轴与 TargetCatcher
- 当前最佳候选：
  - EX-GAS `AbilityTimelineEditor + TaskApplyEffects + TargetCatcher` 作为正式 owner。
- 原因：
  - 当前仓库内 EX-GAS 已提供时间轴、轨道、TaskClip、帧预览、AbilityTask 编辑器预览钩子。
  - `TaskApplyEffects` 已能调用 `TargetCatcher.OnEditorPreview()`。
  - `CatchAreaBox2D` 已能预览 2D 盒形范围。
  - 这比继续扩大项目自造时间轴更符合单一真相。
- 为什么不是其他候选：
  - Kybernetik 只证明命中框作者体验要求，不提供当前项目可直接落地的数据/运行闭包。
  - 项目自造 `MeleeAbilityTimelineWindow` 与 GAS Timeline 争夺同一时间轴和命中框真相，不能继续作为正式 owner。
  - 普通 `AbilitySheet` 只能算旧数据兼容和升级线索；项目侧 `MeleeAbilityExecutionAssetEditor` 已删除，不再作为任何技能的迁移辅助作者面。
- 正式结论：
  - 近战命中框正式作者面应收口到 GAS 时间轴与 TargetCatcher。
  - Kybernetik 继续作为可视化体验验收参考，而不是正式数据 owner。
- 现态与缺口：
  - 基础攻击已迁入 GAS `XParamTimeline` 主链路。
  - GAS 时间轴编辑器已完成基础攻击可读窗口和回归验证，但后续独立特效 Cue 仍等待素材拆分后接入。
  - 当前普攻正式 owner 是 EX-GAS；旧执行资产和旧 Inspector 不能再作为制作入口。

### 6. 投射物 / 区域 / 命中反应执行面

- 职责含义：
  - 火球、陨石、闪电链、环绕剑、区域伤害、命中地面、命中单位后的执行和挂点怎么组织。
- 候选参考：
  - `duolafashi`
  - `2DRPGEngine ProjectileAbility`（只作为历史参考，不作为当前项目运行时 owner）
  - `EX-GAS TimelineAbility`
- 当前最佳候选：
  - `duolafashi` 的内容生产流在“执行面组织方式”上领先。
- 原因：
  - 它已经证明 `Prefab + Timeline + Config` 对飞行物和表现拼装高效。
  - 这更符合后续复杂技能的大量内容生产需要。
- 为什么不是其他候选：
  - `2DRPGEngine` 能做基础投射物，但内容生产面不如 `duolafashi` 鲜明。
  - `EX-GAS` 还没证明自己在投射物/区域执行作者面上是最佳方案。
- 正式结论：
  - 这一职责应优先吸收 `duolafashi` 的组织思想，但仍必须接回项目统一执行语义和规则真相。
- 现态与缺口：
  - 当前项目还未把这条作者链正式做完。
  - 复杂法术阶段前必须先把运行时壳与规则边界定义稳。

### 7. 时间轴作者面

- 职责含义：
  - 技能表现编排、时序事件、生成挂点、表现触发点等时间轴层作者体验怎么做。
- 候选参考：
  - `duolafashi`
  - `EX-GAS TimelineAbility`
- 当前最佳候选：
  - EX-GAS `AbilityTimelineEditor` 领先。
- 原因：
  - 它已经在当前仓库内提供可运行的时间轴窗口、帧预览、TaskClip 数据、AbilityTask 运行时和编辑器预览接口。
  - 它能与 `TaskApplyEffects`、`TargetCatcher`、`GameplayCue` 直接闭合，维护成本低于项目侧重造。
- 为什么不是其他候选：
  - `duolafashi` 仍可作为内容生产流参考，但不能直接承接当前项目的 GAS 规则和 TargetCatcher 闭包。
  - `2DRPGEngine` 只作为易用性参考，不拥有当前正式时间轴数据。
  - 项目自造时间轴会形成第二套真相。
- 正式结论：
  - 时间轴作者面正式 owner 改为 EX-GAS `AbilityTimelineEditor`。
  - 缺口优先补 GAS 编辑器，而不是新建项目侧并行时间轴。
- 现态与缺口：
  - 当前项目还没有把基础攻击迁入 EX-GAS Timeline，不能交给策划作为完整正式流程。
  - 普通 Inspector 和项目自造时间轴都不得伪装成正式时间轴编辑器。

### 8. 玩家炼金 / 配方表达层

- 职责含义：
  - 玩家自己拼火球、法阵、触发、命中反应、元素条件时，运行时表达层该长什么样。
- 候选参考：
  - 无单一成熟本地参考直接胜出
  - 只能综合 `EX-GAS` 规则层 + `duolafashi` 触发/编排启发
- 当前最佳候选：
  - 暂不裁死具体编辑 UI，只裁定“必须共用正式规则合同”。
- 原因：
  - 当前没有一个成熟本地参考同时证明“玩家可配置触发逻辑 + 正式运行时单一真相”。
  - 先裁 UI 只会把数据模型裁歪。
- 为什么不是其他候选：
  - 纯属性表不够表达触发反应。
  - 直接上节点图也没有本地成熟闭包可直接照搬。
- 正式结论：
  - 这一层暂时只允许定义为“能力/效果/触发/目标/消耗/表现配置合同上的配方层”。
- 现态与缺口：
  - 当前还不能开始正式实现玩家法术配方编辑器。
  - 必须等规则合同先稳定。

## 当前项目现态总判断

### 已裁实的职责

- 正式技能身份真相：`EX-GAS Ability / Ability Code`。
- 规则真相：`EX-GAS` 方向可留。
- 基础攻击执行真相：`EX-GAS Timeline / Task / TargetCatcher`。
- 基础攻击近战命中框作者面：`EX-GAS AbilityTimelineEditor + TaskApplyEffects + TargetCatcher`。
- 基础攻击时间轴作者面：`EX-GAS AbilityTimelineEditor`。
- 表现真相：`GameplayFeedbackSet` 方向可留，`GameplayCue` 只做触发。

### 未裁实的职责

- 投射物 / 区域 / 命中反应执行面未裁实。
- 玩家炼金 / 配方表达层未裁实。

### 因此当前能不能说“已可正式给策划开工”

- 不能。
- 当前只能说：
  - 基础攻击技术链可跑。
  - 正式基础攻击的身份、执行、规则、命中和触发主链路已经收口到 EX-GAS。
  - 开发继续重构有依据。
  - 但正式音效、独立特效 Cue 和未迁移技能仍未完成。

## 当前实现哪些可留，哪些必须继续重构

### 可留

- EX-GAS Ability / Timeline / GameplayEffect / Cue 作为正式技能的正式入口。
- `AbilitySheet` 只作为旧存档和存量资产升级线索保留；`AbilityExecutionAsset`（已删除） 已删除。
- `EX-GAS` 作为规则真相层的方向。
