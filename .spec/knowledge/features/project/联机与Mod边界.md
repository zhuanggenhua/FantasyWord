# 联机与 Mod 边界

## 当前裁决

- `FantasyWord` 仍是单机优先项目，但联机是确定目标；单机流程、存档、Mod 内容和核心玩法完成度优先于联机实现。
- 联机方向确定为有限人数主机权威合作。
- 首选评估框架为 FishNet；Mirror 仅作为参考和备选，不作为当前正式首选。
- 当前阶段不接入 FishNet 包、不创建 `Assets/Scripts/Networking`、不写网络 SDK 抽象、不生成网络模块资产。
- 不做 MMORPG、专用服务器持久世界、账号角色资产、多房主共同存档、全地图同步或多人 RTS 指挥。

## 产品边界

- 房主机器是唯一世界真相，房主存档是唯一正式世界存档。
- 访客可以拥有完整角色操作权：移动、战斗、技能、拾取、丢弃、装备、卸装、开容器、治疗、搬运、偷窃、触发犯罪和与对象交互。
- 访客不拥有世界所有权：不独立保存世界、不管理全局任务真相、不控制多个队伍、不改全局经济、不绕过房主改世界状态。
- 访客掉线后，受控角色必须能回到 AI、原地等待或由房主接管；规则必须由房主裁决。
- 开放世界联机只同步附近区域和相关对象，不做全地图全量同步。

## FishNet 口径

- FishNet 是确定有限联机目标下的首选评估框架，因为它更贴主机权威、对象所有权、客户端预测、服务器校正和观察者同步。
- 当前不购买或依赖 FishNet Pro。延迟补偿、网络 LOD、代码剥离等 Pro 能力只能作为后期发布或性能需求明确后的专项评估。
- 玩法代码不得直接以 FishNet 为真相源。FishNet 只作为远程输入和主机裁决结果的传输层。
- 未来接入时，默认形状是：访客输入进入 FishNet RPC，房主调用同一套单机规则入口，房主同步裁决结果。
- 不允许 Mod 直接注册 FishNet RPC、网络对象、同步字段或网络权限规则。

## 单机代码要求

- 当前不为了确定会做的联机目标写空框架，但单机规则必须有清楚入口。
- 本轮角色、背包、能力和 RTS 命令链重构需要带上联机兼容边界，但不接入联机实现。必须明确命令入口、角色控制权、对象归属、物品归属、装备/使用物品裁决、伤害/状态裁决、存档写入边界和输入来源区分；不得因此新增 FishNet 包、网络目录、RPC、同步字段、网络对象或网络 SDK 抽象。
- 会改变世界的行为应收束到正式规则入口，例如移动、攻击、交互、装备、物品转移、伤害、犯罪和派系关系变化。
- UI、动画、音效、特效只消费裁决结果，不直接修改世界真相。
- 输入来源要可区分本地玩家、AI、远程玩家；但当前实现仍以单机输入和 AI 为主。
- 角色控制权、对象归属、物品归属、阵营关系、任务触发和存档写入不得散落在场景脚本或 UI 回调里。

## Mod 兼容

- Mod 是内容层，不是网络层。
- Mod 通过稳定 ID、数据表、资源键、数据库条目和正式规则扩展点进入游戏。
- 联机房间必须以房主 Mod 清单为准，至少比对 `modId`、`version`、`contentHash` 和 `loadOrder`。
- 访客缺失或版本不一致时，不允许进入依赖该 Mod 的房主世界或牌局。
- 联机同步稳定 ID 和裁决结果，不同步 Mod 文件本体。
- 初期优先支持物品、装备、技能、状态效果、NPC、怪物模板、派系、掉落表、商店、对话、卡牌和美术替换。
- 初期不支持 Mod 自定义 C# 网络逻辑、自定义 RPC、自定义网络对象、任意文件读写、外部联网或改写核心权限规则。

## 卡牌对战模式

- 类昆特牌的小游戏必须是独立局内模式，不复用开放世界运行时作为牌局真相。
- 牌局可以读取玩家长期收藏、卡牌数据库、奖励出口、音频、UI 和 Mod 内容表。
- 牌局状态由独立 `ModeRuntime` 或同级宿主持有：牌库、手牌、弃牌、场上单位、回合、分数、效果栈、随机种子和结算结果。
- 牌局联机是回合制/离散操作同步：出牌、弃牌、选择目标、结束回合和结算结果。
- 牌局结束后只把奖励、损耗、剧情结果或世界标记写回开放世界。
- 卡牌对战是未来联机能力的低风险试点，优先级可高于开放世界实时角色合作。

## 禁止误用

- 不把 FishNet、Mirror、NGO 或任何网络框架写进当前单机核心真相。
- 不用“联机确定要做”作为提前新增网络目录、网络抽象或包依赖的理由。
- 不把 `uMMORPG` 的 Mirror、MMORPG、3D NavMesh、队伍副本或网络出生点体系当作 FantasyWord 的联机基线。
- 不把“访客角色操作权接近房主”误解成“访客拥有世界所有权”。
- 不让 Mod 直接决定网络同步、控制权、存档写入或房主裁决规则。
