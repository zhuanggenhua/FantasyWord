# 换装动画与资源流程对照

> 目的：遇到“换装流程是否比参考更好”“SpriteLibrary / Animator / Yoki 该谁负责”“资源路径硬编码是否允许”这类问题时，先读本文件。
> 本文只裁决流程与 owner，不替代具体视觉验收矩阵。
> 坐骑原版素材接入不套用本文的 UV/Shader 局部装备结论；坐骑本体和骑手基础层按作者原版 Sprite 直显验收，阴影不进入坐骑动作接入门槛，最终验收图必须回到当前真实 GameView 的 ScreenCapture 完整画面。

## 裁决标准

本模块按 `.spec/knowledge/standards/workflow.md` 的多参考源标准判断：

1. 原生能力优先：Unity 已提供的 `Animator`、`SpriteLibrary`、`SpriteResolver`、序列化引用和 `AssetDatabase` 优先使用。
2. 职责内核优先：先看参考工程解决的 owner、保存、刷新、资源来源，不照搬类名或目录。
3. 最薄可行抽象：能由现有 owner 直接持有引用的，不新增包装资产、manager 或二次路径层。
4. 单一真相源：作者源数据、派生资源、运行时状态、工具配置和门禁报告不能互相代持。
5. 约束匹配：当前 MiniFantasy 四向像素素材、普通局部装备的 UV/Shader 合成、坐骑原版 Sprite 直显和工作台生成流程优先于“看起来更通用”。
6. 证据边界：2DRPGEngine 只能证明它实际覆盖的流程；Yoki 只能证明工具层加载能力，不自动成为换装作者数据 owner。

## 2DRPGEngine 参考流程

| 阶段 | 真实流程 | owner | 对 FantasyWord 的意义 |
| --- | --- | --- | --- |
| 装备定义 | `Equipment` 资产直接持有装备槽位、属性、能力和 `SpriteLibraryAsset visualOverride` | 装备资产 | 运行时视觉不靠资源路径查找，而靠资产引用。这个原则应继承。 |
| 装备状态 | `Hero` 持有 `EEquipmentType -> Equipment` 字典 | 角色装备状态 | 装备真相在角色，不在渲染器或 UI。这个原则已由 `CharacterEquipment` 继承。 |
| 背包交易 | `InventorySystem` 编排背包与角色装备之间转移 | 背包系统 | 交易流程归规则层，不应放入换装表现层。 |
| 保存恢复 | 保存数据库稳定引用，读档时重新走装备流程 | RPG 存档语义 | 存档保存装备数据引用，不保存运行时 SpriteLibrary 路径。 |
| 视觉覆盖 | `EquipmentSpriteLibraryUpdater` 在需要时把装备的 `SpriteLibraryAsset` 赋给角色 `SpriteLibrary` | 角色表现组件 | 证明 SpriteLibrary 是原生可用的视觉覆盖机制，但它只覆盖整套库，不解决 UV 局部装备叠加。 |
| 多方向动画 | `PolydirectionalAnimationStrategy` 用方向字典映射到 `SpriteLibraryAsset`，可配置 `flipSprite` 和优先级 | 动画策略组件 | 证明“动作状态不乘方向，方向切 SpriteLibrary”是参考核心；不证明必须照搬 8 向字典。 |
| 编辑器资产查询 | 编辑器工具用 `AssetDatabase.FindAssets / GUIDToAssetPath / LoadAssetAtPath` 扫资产 | Editor 工具层 | Editor 可以按项目约定找资产，但不应把运行时视觉资源做成路径加载。 |

## FantasyWord 当前流程

| 阶段 | 当前流程 | owner | 判断 |
| --- | --- | --- | --- |
| 作者源数据 | `CharacterFrameData` 记录帧数据、UV、挂点、装备遮挡等作者信息 | 帧数据资产 | 正确。它是换装作者数据，不应再持有派生出来的方向库。 |
| 动作集合 | `AnimationTypeDatabase` 定义动作键 | 动作数据库 | 正确。动作键是共享时序和装备序列的共同语言。 |
| 派生生成 | `EquipmentWorkbenchAnimatorControllerTool` 从工作台目录、动作库和帧数据生成共享动作片段、共享 Controller、每角色四向 SpriteLibrary | Editor 生成器 | 方向乘动作状态已收口为“动作状态 + 方向库”，方向更接近参考；生成路径、帧率、循环动作和 fallback 策略已由 `EquipmentSystemGenerationSettings` 承载，方向索引/缩写/向量由 `CharacterAnimationDirections` 承载。 |
| 运行时动作 | `CharacterActionAnimatorDriver` 只播放纯动作 Animator 状态 | 动作控制器 | 比旧“动作 × 方向状态”更好，也更贴近参考流程。 |
| 运行时方向 | `DirectionalSpriteLibraryDriver` 监听移动朝向并切 SE/SW/NE/NW 四个 SpriteLibrary | 方向变体驱动 | 方向职责从 Animator 移出是正确的；但方向名称和向量应集中为领域常量或配置，不应散落硬编码。 |
| 运行时装备表现 | `EquipmentRenderer` 用当前动作帧、方向、装备视觉、UV/Shader 参数合成局部装备 | 换装渲染器 | 这是 2DRPGEngine 没覆盖的能力；不能退回整套 SpriteLibrary 替换。 |
| 坐骑运行时表现 | `MountedCharacterPresentation` 同步动作、方向和帧索引，直显作者原版坐骑本体和骑手基础层 Sprite | 坐骑表现组件 | 坐骑不是普通局部装备叠加；阴影不作为坐骑动作接入门槛。 |
| 工作台预览 | 工作台目录直接持有角色选项和派生方向库引用 | 工作台目录 | 当前可用，但派生方向库不应回写到作者源 `CharacterFrameData`；直接挂在工作台角色选项比新增包装资产薄。 |
| 工作台字体与后处理 LUT | Runtime UI 预制体持有 TMP 字体引用，RendererFeature 持有 HQ4x LUT 引用 | 预制体 / RendererFeature 资产 | 运行时不得再按 `Resources` 字符串路径查找；缺引用时报告配置错误。 |
| 静态门禁 | PowerShell 按项目路径检查方向片段、旧脚本、四向库完整性和架构回退 | 门禁脚本 | 约定路径在门禁里允许存在，但应与生成器共享同一配置语义，不能双份漂移。 |

## 当前流程是否更好

当前流程不是全局都更好，只是在几个关键点上比旧状态和参考直接照搬更适合当前项目。

| 对比点 | 参考流程 | 当前流程 | 裁决 |
| --- | --- | --- | --- |
| 动作和方向关系 | 动作不乘方向，方向切 SpriteLibrary | 已改成共享动作状态 + 四向库 | 当前更接近参考，方向从 Animator 状态移出是正确的。 |
| 装备视觉粒度 | 装备 `visualOverride` 偏整套 SpriteLibrary 覆盖 | UV/Shader 局部叠加，支持装备层、遮挡、挂点、描边 | 当前更适合 MiniFantasy 局部换装；不能退回整套覆盖当主链。 |
| 资源 owner | 装备/组件持有 `SpriteLibraryAsset` 引用 | 运行时主链使用序列化引用；生成器用路径生成派生资产 | 运行时 owner 方向正确；字体、LUT、UI 预制体也必须走显式引用，不用 `Resources.Load`。 |
| 方向配置 | 方向字典 + priority + flip | 固定 SE/SW/NE/NW 四字段 | 当前素材只有四向且不使用 `flipX` 时，四字段不是错误；若未来支持八向或镜像，才需要数据化字典。 |
| 单方向素材 | 参考可按字典缺省或优先级选择方向覆盖 | 生成器把第一份可用方向复制到缺失方向库 | 对单方向动作应无视觉破坏，但应在配置/日志中显式标为 fallback，不能静默冒充四向作者数据。 |
| 资源路径 | 参考运行时不用路径，Editor 可扫资产 | 当前 Editor 路径散落，运行时主链不按路径加载 | 需要改的是 Editor 配置集中化，不是把运行时引用改成 Yoki 字符串 key。 |

结论：

- **比参考更好的部分**：当前 UV/Shader 局部换装表现更适合本项目装备叠加、武器遮挡、肤色、描边和逐帧挂点。
- **坐骑例外**：坐骑本体和骑手基础层已经由作者提供同画布、同帧、同方向素材；当前验收按原版 Sprite 直显，不为了证明坐骑接入而强行经过普通换装 Shader。阴影按当前项目口径不进入坐骑动作分类。
- **必须继承参考的部分**：动作不乘方向、运行时用资产引用、装备真相不归渲染器、Editor 查询不等于运行时路径真相。
- **当前仍不如参考规范的部分**：生成器已有正式配置 owner，但门禁脚本尚未和该配置同源，fallback 复制方向仍缺少统计报告；这两项不能冒充已完成。

## Yoki / YooAsset 边界

YokiFrame 和当前 `ResourceSystem` 能管理运行时资源加载，但它们不替代 Unity Editor 资产生成流程。

| 场景 | 应用什么 | 原因 |
| --- | --- | --- |
| 生成 `.anim`、`.controller`、`.spriteLib`、重建工作台派生资产 | Unity `AssetDatabase` + 项目生成配置 | 这是 Editor 资产生产，不是玩家运行时加载。 |
| 角色 Prefab、工作台目录、装备视觉资产已经序列化持有引用 | 继续用序列化引用 | 引用比字符串 key 稳，不应为了工具统一改差。 |
| 工作台字体、HQ4x LUT、RendererFeature 辅助资源已经可由预制体或 RendererFeature 持有 | 继续用序列化引用 | 这类资源随资产一起序列化，比运行时 `Resources` 字符串路径更可审计。 |
| 运行时动态加载装备外观、DLC、热更、远端包、按需角色皮肤 | Yoki ResKit / YooAsset `ResourceSystem` | 这才是资源加载工具层职责。 |
| 场景切换、UI 面板加载、资源句柄释放 | Yoki SceneKit / UIKit / ResKit | 属于通用工具层，Yoki 是正式工具 owner。 |
| 存档装备 | `DatabaseEntryReference` 或数据库稳定引用 | 存档保存业务身份，不保存 SpriteLibrary 路径、Yoki key 或 Editor 路径。 |

禁止把“我有 Yoki”理解成“所有资源引用都要改成字符串加载”。Yoki 应替换重复工具，不应把本来稳定的 Unity 资产引用降级成路径约定。

## 应更新的规范

| 项 | 当前问题 | 规范裁决 |
| --- | --- | --- |
| 生成器配置 | 旧问题是路径、帧率、循环动作、方向缩写写死在 `EquipmentWorkbenchAnimatorControllerTool` | 当前生成器必须只消费默认路径的 `EquipmentSystemGenerationSettings`；找到多个设置资产时应失败，不得按路径排序猜一个。设置资产可通过 `Tools/Equipment System/Create Animation Generation Settings` 创建。 |
| 方向常量 | 旧问题是 SE/SW/NE/NW 分散在驱动、生成器和其它工具 | 运行时方向驱动、方向库集合和生成器已接到 `CharacterAnimationDirections`；UI、Drawer、门禁等散点可后续继续收口。 |
| 单方向 fallback | 当前生成器会复制第一份可用方向 | 对真正单方向动作可以保留，但必须可见、可校验、可被门禁统计；不能静默当作真实四向，不能拿全局默认掩盖缺方向素材。 |
| 门禁路径 | 门禁和生成器各写一套路径 | 门禁可以验证约定路径，但应与生成配置同源或至少同名同步。 |
| 表现层运行时资源 | 旧代码允许工作台字体和 HQ4x LUT 通过 `Resources.Load` 字符串路径兜底 | Runtime UI 字体和 RendererFeature LUT 必须显式绑定；新增门禁禁止换装表现运行时代码回到 `Resources.Load`。 |
| Yoki 边界 | 容易把工具层加载能力误升格为换装资源 owner | 规范应写清：运行时动态加载才用 Yoki；Editor 生成继续用 `AssetDatabase`；已有序列化引用不改差。 |

## 推荐后续重构顺序

1. 已补配置 owner：`EquipmentSystemGenerationSettings` 集中生成路径、帧率、循环动作、fallback 策略。
2. 已补方向 owner：`CharacterAnimationDirections` 集中四向索引、缩写和方向向量。
3. 已收紧生成器设置入口：默认设置资产是唯一正式 owner，多余设置资产直接阻断生成。
4. 下一步为单方向 fallback 增加统计报告，明确哪些动作/角色/方向来自复制，而不是真实作者帧。
5. 普通局部换装运行时继续保持动作控制、方向库切换、装备 UV/Shader 合成三段分离；坐骑运行时按原版 Sprite 直显同步动作、方向和帧索引。
6. 只有出现运行时动态外观加载需求时，才把 Yoki ResKit / YooAsset 接进换装资源加载。

## 必须避免的错误

- 不得因为参考工程用 `SpriteLibraryAsset`，就删除当前 UV/Shader 局部装备主链。
- 不得把普通局部换装的 UV/Shader 结论套到坐骑本体和骑手基础层验收上；坐骑本体、骑手基础层必须按作者原版 Sprite 直显证明。阴影不作为坐骑动作接入门槛。
- 不得因为当前有 Yoki，就把稳定序列化引用改成字符串路径。
- 不得把 Editor `AssetDatabase` 路径生成误报成运行时资源硬编码。
- 不得让派生方向库回写进 `CharacterFrameData`，作者源数据不应代持生成物。
- 不得恢复动作 × 方向 Animator 状态、方向片段、OverrideController 或独立包装方向资产。
