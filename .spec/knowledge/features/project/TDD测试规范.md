# TDD 测试规范

## 适用范围

- Unity Test Framework / NUnit 的 EditMode 与 PlayMode 测试。
- 运行时代码、编辑器工具、数据合同和资源结构的测试驱动流程。
- 本文只定义测试方法，不记录当前迁移进度。

## 默认路线

- TDD 不是默认强制流程；只有用户明确要求 TDD，或改动本身具有高回归风险、强合同边界、复杂状态机、存档/序列化兼容、跨系统端到端链路时，才按 TDD 推进。
- 不把每个需求拆成同粒度单元测试；默认不接受“写一份功能，再写一份等量测试代码”的流程。测试预算默认先投向必要端到端 smoke。
- 如果测试设计开始逼近“实现一份，再镜像补一份测试代码”的双倍代码量，默认说明测试选型错了；先删低价值测试点，回到最小真实入口 smoke。
- 非端到端测试是例外，不是惯例。只有端到端 smoke 不能稳定保护真实玩家链路或正式数据合同，才考虑补充；若只是保护 helper、转发函数、目录摆放或简单 API，则不写。
- 默认不建立“需求条目 = 测试条目”的对照表。若已有端到端 smoke 能覆盖风险，优先扩已有 smoke 或沿正式场景链路补最小验证，不再新开一组同粒度测试。
- 如果一轮需求的测试设计会自然演变成“实现一份，再镜像写一份测试”，默认先停下来收缩范围：优先砍掉低价值单测，回到真实入口的最小 smoke，只有无法替代的合同风险才保留。
- 标准循环：`列测试点 -> 选下一条正式合同 -> red -> green -> refactor`。
- 一次只推进一条正式合同，不批量铺未来测试壳。
- 如果红灯来自坏 runner、坏 driver、旧夹具或历史场景污染，先删污染，不把修测试壳当成 green。

## 测试分层

- EditMode：纯逻辑、ScriptableObject 数据、Editor 工具、资源结构、序列化合同。
- PlayMode：跨帧行为、输入到表现、场景对象协作、角色/相机/交互链路。
- AIBridge：补充取证和自动化执行通道，不替代 Unity Test Framework。

## 写测试规则

- 测试只保护用户可观察行为、正式结构合同、正式数据/序列化合同。
- 优先写必要的端到端测试；只有端到端不足以覆盖真实风险时，才补关键合同测试。不要因为新增了一个小 API、入口转发或工具调用，就自动补一组同等粒度的单元测试。
- 非端到端测试若无法一句话说明“它替代不了哪个必要端到端风险保护缺口”，则默认不写。
- 非端到端测试若不能明确对应到“哪个真实玩家流程、哪个真实数据合同、哪个真实存档/引用闭包风险”，则默认删掉，而不是保留成测试库存。
- 不为文件拆分、helper 摆放、简单 getter/setter、当前目录数量写测试。
- 不测试第三方插件自己的能力；只在项目侧有真实业务合同时，验证“项目入口是否正确使用插件能力”。
- 如果静态门禁、编译敏感搜索、已有端到端测试或现有场景合同已经覆盖风险，不新增重复测试。
- 测试体默认按 `Arrange -> Act -> Assert` 组织。
- 单条测试应只有一个主要 Act；需要多段控制流时，先重写测试表达。
- 共享夹具不是默认解，只有多个正式合同确实共享同一份最小准备动作时才保留。

## Unity 约束

- 场景和 Prefab 测试不得偷偷补建正式资产。
- 测试不能为了通过而改写正式项目设置、正式场景或正式资源。
- 需要跨帧时使用 Unity Test Framework 的协程测试；不要自建第二套 runner。
- 批量验证前先完成当前批修改，不对同一批问题高频重复跑 PlayMode。

## 当前项目边界

- 俯视角移动、交互、地图、装备/换装、物品、战斗和存档后续进入正式实现时，默认优先补能覆盖完整玩家链路的端到端 smoke；只有存档、序列化、引用闭包、跨系统边界这类端到端不易稳定定位的风险，才补少量关键合同测试。
- 不为每个小需求、小函数或入口调用逐项补同粒度测试。若现有测试已经变成维护负担，后续重构时优先合并到更少的端到端/合同测试，而不是继续扩张数量。
- 联机是确定目标，但当前不提前为网络同步写空测试壳。
