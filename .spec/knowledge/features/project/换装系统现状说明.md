# 换装系统现状说明

> 目的：先把当前系统事实讲清楚，再讨论坐骑怎么接。本文只描述当前代码和资产职责，不把后续想做的能力说成已经完成。

## 一句话结论

当前 FantasyWord 普通换装不是“给每套装备做一套角色动画”，而是：

1. 角色基础动作仍由共享 Animator 播放。
2. 角色朝向由四向 `SpriteLibraryAsset` 切换。
3. `EquipmentRenderer` 读取当前 Sprite 的动作、方向和帧索引。
4. `CharacterFrameData` 提供这一帧的身体/头部 UV、手脚蒙版、武器锚点和地面基线。
5. `EquipmentUV` Shader 在同一个角色 SpriteRenderer 上合成服装、头部装备、手脚颜色、武器、肤色、描边和像素级阴影。

所以普通换装的核心不是“替换整张角色图”，而是“基础角色图 + 帧标注数据 + 装备贴图/颜色 + Shader 合成”。

## 两层装备类型

当前项目里有两套名字相近但职责不同的装备类型，不能混说。

| 层级 | 现实含义 | 当前事实 |
| --- | --- | --- |
| 玩法装备槽位 | 角色能穿戴到哪个槽位，影响背包、属性、技能和表现刷新 | `EEquipmentType` 已包含 `Mount`，所以玩法层有坐骑槽。 |
| 普通换装表现类型 | 一件视觉装备怎么被 `EquipmentRenderer` 合成到角色图上 | `EquipmentType` 没有 `Mount`，只包含 Gloves/Shoes/Clothing/Cloak/Pants/Helmet/Hat/Mask/Weapon/Shield/Bag。 |

这不是同一件事：坐骑应该占用玩法层 `Mount` 槽，但不应该硬塞进普通 `EquipmentType` 的 UV/颜色/武器合成表里。当前表现层通过 `Equipment.visual is MountRenderData` 单独识别坐骑表现。

## 运行时主链

| 步骤 | 现实动作 | 当前 owner |
| --- | --- | --- |
| 穿戴状态改变 | 角色装备列表变化，触发表现刷新 | `CharacterEquipment` |
| 读取装备外观 | 装备资产提供视觉资源，普通装备是 `EquipmentRenderData`，坐骑是 `MountRenderData` | `Equipment.visual` |
| 普通装备应用 | 表现层把普通装备塞进 `EquipmentRenderer` 槽位 | `CharacterEquipmentPresentation` |
| 坐骑切换 | 表现层发现 `MountRenderData` 后切到骑乘表现，再把普通装备外观应用到骑手换装槽 | `CharacterEquipmentPresentation` + `MountedCharacterPresentation` |
| 动作播放 | 只处理 Idle/Walk/Attack/Dmg/Die 等动作状态 | `CharacterActionAnimatorDriver` |
| 方向切换 | 只切 SE/SW/NE/NW 四向 SpriteLibrary，不创建动作乘方向状态 | `DirectionalSpriteLibraryDriver` |
| 帧同步 | 从当前 Sprite 的 rect 算出行和列，再取本帧标注数据 | `EquipmentRenderer.SyncFromSprite` |
| 合成刷新 | 写 UV 图、装备贴图、颜色、武器、阴影等 Shader 参数 | `EquipmentRenderer.Refresh` |

## 普通装备怎么画

| 装备类别 | 当前做法 | 关键点 |
| --- | --- | --- |
| 服装/裤子/斗篷/背包 | 走 Body 层 UV，把装备贴图按当前帧身体区域采样 | 依赖 `bodyUVMap`，缺 UV 不能冒充完成。 |
| 头盔/帽子/面罩 | 走 Head 层 UV，把头部装备贴到当前头部区域 | 依赖 `headUVMap`，可配置隐藏头发/胡子。 |
| 手套/鞋子 | 不用装备贴图，按帧里的手脚蒙版替换左右颜色 | 依赖 `FrameData.limbMask`。 |
| 头发/胡子/面部装饰/眼睛 | 属于角色外观，不是背包装备 | `CharacterAppearance` 写入 Shader。 |
| 武器/盾牌 | 优先按当前动作序列帧，否则用静态四向贴图 + 作者锚点 | 通过 Shader 参数合成；临时子 SpriteRenderer 不是正式主画面武器渲染。 |
| 肤色/受击描边 | Shader 内按颜色表或帧标记处理 | 不属于装备槽。 |

## 阴影职责

普通换装的角色阴影不是单独动作素材：

- `CharacterFrameData` 只提供地面基线和脚部像素证据。
- `EquipmentRenderer.UpdateShadowHeight` 根据脚部离地高度写入 `_ShadowMode`、`_ShadowLeftX`、`_ShadowRightX`、`_ShadowCenterX`、`_ShadowBaseY`。
- `EquipmentUV.shader` 在最终像素为空的位置按这些参数画阴影。

因此，普通换装验收不需要为每个动作额外找一张阴影 Sprite。坐骑动作分类时也不应把“阴影帧是否齐全”作为动作能否统一的判断依据。当前 `MountRenderData`、`MountedCharacterPresentation`、战马表现资产和统一角色 Prefab 已不再包含 `shadowFrames`、`shadowRenderer` 或独立“坐骑阴影”对象。

## 坐骑和普通换装的边界

坐骑本体不是衣服、帽子或武器，也不是普通角色 Idle/Walk 的另一套装备贴图。坐骑接入要分三件事：

| 事情 | 当前应怎么理解 |
| --- | --- |
| 坐骑本体 | 始终使用作者原版坐骑 Sprite，按坐骑自己的动作表逐帧直显，不使用 `EquipmentUV`。 |
| 未穿普通装备的骑手 | 使用作者原版骑乘姿态基础人形 Sprite 逐帧直显，不使用普通换装材质。 |
| 穿普通装备的骑手 | 仍以作者骑手 Sprite 作为当前帧，但切换到骑乘姿态专用 `CharacterFrameData` 和 Body/Head UV，由现有 `EquipmentRenderer` 合成服装等普通装备。 |

坐骑动作适配的核心问题是：能不能用一套通用逐帧播放器，根据坐骑资产的数据播放“本体 + 骑手基础层”。不是为每只动物建一套 Animator，也不是凭空加“骑手偏移”。

## 坐骑动作判断口径

坐骑动作可以统一的是“播放协议”和“动作语义”，不是每个动作的帧数、文件名或是否四向都完全一样。

| 语义 | 可以统一的范围 | 需要注意 |
| --- | --- | --- |
| Stand | 待机、站立、停泊 | 帧数可能是 1/4/5/12/19，不统一帧数。 |
| Move | 行走、移动、飞行、冲浪、爬行 | 飞行/冲浪是移动语义，不必新增角色 Animator 状态。 |
| Hurt | 受伤 | 通常四向，可作为可选基础语义。 |
| Die | 死亡、沉没 | 常见单行动作，播放器要支持单行/不按四向取行。 |
| MountUp/MountDown | 骑乘上/骑乘下 | 这是上下坐骑流程动作，不从普通 Idle/Walk 自动推断。 |
| Attack | 攻击 | 不是所有坐骑都有，按坐骑支持集覆盖。 |

明显特殊的动作不要塞进基础移动：蜗牛 InShell/OutShell、熊猫趴下/站立上、蟾蜍跳跃等应作为坐骑自定义动作或具体技能/状态覆盖。

## 工作台与玩法装备的边界

- 工作台普通分类是现有视觉换装预览入口，选项直接写入 `EquipmentRenderer` 的普通表现槽；它不是背包装备 UI，不应把不存在的正式 `Equipment` 资产临时补造出来冒充玩法装备。
- 正式背包装备仍以 `CharacterEquipment` 为唯一玩法状态；`CharacterEquipmentPresentation` 会把其中的 `EquipmentRenderData` 同步到同一个渲染器。
- 工作台坐骑选项不同：坐骑有明确玩法槽，因此必须引用正式 `Equipment`，通过 `CharacterEquipment.TryEquip` 写入 `EEquipmentType.Mount`，再由表现层激活骑乘。
- 骑手是否启用普通换装叠加，只读取 `EquipmentRenderer` 最终实际存在的普通表现槽；不再用正式装备列表数量猜测，所以工作台预览和正式背包装备都能得到一致的骑乘渲染结果。

## 当前明确缺口

- 当前正式样板只完成战马 `Stand/Move`；其它动物仍需按各自本体与骑手素材制作 `MountRenderData`。
- `Hurt/Die/MountUp/MountDown/Attack` 和 `Jump/Sleep` 等协议已经可表达，但战马样板资产尚未录入这些作者帧，不能把协议支持说成该资产已经支持这些动作。
- 战马骑乘 Idle/Walk 已有 Body/Head UV；其它坐骑若要叠加普通服装，仍需为自己的骑手动作生成和人工核对骑乘帧数据。
