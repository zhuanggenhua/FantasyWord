# 近战基础攻击命中层配置缺失排查记录

## 症状

- 基础攻击执行资产把 `Target Layers` 从 `Everything` 收窄到正式受击层后，EditMode 命中测试不再扣血。
- `MeleeAttackAbilityEditModeTests.Fire_HitsTargetInsideHitbox_AndUpdatesFormalHealth` 等待 EX-GAS 生命值变化超时。

## 误判风险

- 不能把 `Target Layers` 改回 `Everything` 当成修复；那会重新允许基础攻击误扫场景物件。
- 不能只看角色根节点有 `CharacterBase` 就认为命中可结算；正式受击碰撞体在子物体 `Hitbox` 上时，运行时必须从子碰撞体回溯到所属角色。
- 不能只改测试让角色根节点落在命中层；正式 Prefab 已经有子物体 `Hitbox`，测试应模拟正式结构。

## 真实根因

- 项目配置里 `GameConfig.hitboxLayer` 指向 `Hitbox`，角色基础 Prefab 也有名为 `Hitbox` 的子物体落在 Layer 7。
- 但 `ProjectSettings/TagManager.asset` 里 Layer 6/7 名称为空，`Hitbox` 层名没有正式登记。
- 基础攻击样例执行资产此前 `Target Layers = Everything`，掩盖了层配置缺失。
- 收窄到 Layer 7 后，测试角色只有根节点碰撞体，没有模拟正式 `Hitbox` 子物体；同时近战命中运行时原本只在命中的 collider 本体上找 `CharacterBase`，没有回溯父级角色。

## 修复点

- `ProjectSettings/TagManager.asset`
  - Layer 6 登记为 `Interaction`。
  - Layer 7 登记为 `Hitbox`。
- `Assets/GameData/GameCore/AbilitySamples/AbilityExecutions/测试-基础攻击-执行.asset`
  - `m_targetLayers` 从 `Everything` 收窄到只命中 `Hitbox` 层。
- `Assets/Scripts/GameCore/Runtime/Combat/Abilities/Active/MeleeAttackAbility.cs`
  - 命中 collider 后用 `GetComponentInParent<CharacterBase>()` 回溯正式角色。
- `Assets/Editor/GameCore/Tests/MeleeAttackAbilityEditModeTests.cs`
  - EditMode 角色创建时补 `Hitbox` 子物体与 trigger 碰撞体，模拟正式受击碰撞结构。

## 必查项

- `ProjectSettings/TagManager.asset` 是否真的登记了 `Hitbox`，而不是只有 Prefab 数字层号。
- `MeleeAbilityExecutionAsset.targetLayers` 是否收窄到正式受击层，不应长期保留 `Everything`。
- 近战命中代码是否从子碰撞体回溯到父级 `CharacterBase`。
- 测试角色是否模拟正式子 `Hitbox` 结构，而不是靠根节点碰撞体误通过。

## 验收口径

- `MeleeAttackAbilityEditModeTests` 必须通过，证明基础攻击仍能命中并进入 EX-GAS 伤害链。
- `FormalAbilityAssetValidation.InspectAllAbilitySheets()` 必须通过，证明正式技能资产没有错误或误用警告。
- 当前正式场景不能因为验证残留 dirty。
