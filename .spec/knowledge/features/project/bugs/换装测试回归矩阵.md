## 已确认错误项

| 编号 | 错误行为 | 根因 / 判断 | 当前处理 | 证据 |
|---|---|---|---|---|
| E01 | 角色背后出现巨大色块或横向黑块 | 把运行时装备/盾牌采样矩形改成“可见区域”后，Shader 仍按作者整帧 UV 采样，导致小贴图区域被放大成色块 | 已修复：运行时渲染恢复 `SpriteUtils.GetUVRect`；UI 图标才用可见区域预览 | 失败图：`human-heavyshield-attack/gameview-overview.png`；通过图：`human-heavyshield-attack-fixed/gameview-overview.png` |
| E02 | 圆盾、头盔等装备图标空白 | 原始 32x32 小道具透明区很大，直接塞 UI Image 看起来接近空白 | 已修复：第一帧来源不变，生成 UI 可见区域预览 | `human-heavyshield-attack-fixed/right-equipment-list.png` |
| E03 | 静态盾牌/武器改成独立 SpriteRenderer 后挂点不对 | 独立 SpriteRenderer 按道具自身 PPU / 裁切结果摆放，脱离作者帧内挂点语义 | 已修复：静态武器/盾牌回到 shader 合成路径 | `EquipmentRenderer.cs` 当前 diff |
| E04 | 通过关闭默认描边来让画面“看起来没问题” | 这是止血，不是修复；会违背正式装备系统程序描边能力 | 已禁止：默认描边保持开启 | 运行矩阵：`defaultOutline=1` |
| E05 | 动作列表被固定白名单截断 | 旧 UI 只扫描固定动作键，新增采集/制作动作不完整 | 已修复：装备预览遍历 `visual.animSequences`，运行 UI 动作数为 28 | `EquipmentWorkbenchRuntimeUI.cs`；运行矩阵：`animationCount=28` |
| E06 | 非玩家素材混入玩家动作 | UI、气泡、道具、阴影、动物/怪物不是玩家人形动作 | 已登记排除规则，后续生成/导入不得混入 | `.spec/knowledge/features/project/bugs/换装测试动作来源表.md` |
| E07 | 只有一个种族或非人类消失 | 工作台目录/运行 UI 没有保留 5 种族矩阵 | 已恢复并验收 | 运行矩阵：`characterCount=5` |
| E08 | 为了让视觉测试出现武器动画，计划外向 `战斧.asset` 添加 `SlashAttack` 序列并改动生成/配置数据 | 把“完成测试层”错误扩大成“补写正式内容数据”，没有在发现配置缺口时停下确认 | 已移除战斧计划外序列；已恢复帧数据、生成工具和 84 个 UV/导入文件的真实内容；正式工作台合同新增配置只读边界 | `Assets/GameData/EquipmentSystem` 实际 diff 为空；56 个 LFS UV 与 14 个 `.meta` 已恢复干净；14 个历史普通 PNG 的 `git hash-object --no-filters` 与 HEAD Blob 全部一致，剩余状态提示来自现行 `*.png lfs` 规则与历史 Blob 类型不一致 |
