# 用户故事记录规范

## 适用范围

- 本文定义 `FantasyWord` 新用户故事的记录方法、权威顺序和文件模板。
- 当前项目不继承旧 `FantasyWorld` 恢复任务用户故事，也不继承 `dark-corridor` 的横版用户故事。

## 什么算用户故事

- 用户故事记录玩家目标、入口条件、主流程、失败路径、玩家可见反馈和用户明确确认过的体验约束。
- 代码结构、字段名、目录整理、插件接入和工具链迁移不单独构成用户故事。

## 权威顺序

1. 当前对话里用户最新一次明确纠正。
2. 当前 `FantasyWord` 已核实的用户故事文档。
3. 当前项目已验证的可玩实现。
4. 参考项目或旧恢复记录中的事实线索。
5. AI 推断。

## 记录规则

- 默认文件名：`用户故事_主题_YYYY-MM-DD.md`。
- 同一主题后续纠正优先更新原文件，不随意新建平行版本。
- 旧恢复任务故事只能作为历史参考；若重新成为新游戏目标，必须按当前产品定位重新记录。
- 联机相关故事当前只允许按“有限人数主机权威合作”新方向记录；不得从历史联机设想自动继承。涉及 FishNet、访客控制角色、Mod 联机一致性或卡牌局内对战时，先读 `联机与Mod边界.md`，再记录具体用户故事。
