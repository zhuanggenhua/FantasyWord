# Design: plan-core-framework-roadmap

## Product Pillars

当前核心框架按 3 个行动支柱组织：

- `指挥一支有个性的队伍`：玩家主要是一个人，但可以招募和指挥队友；控制权、命令链、暂停和队友 AI 必须统一。
- `用规则改造战局和世界`：职业、技能树、状态、元素反应、2D 高低差、视野侦查和物体交互都应进入可组合规则层。
- `让世界自己运转`：NPC 有性格、背景、日程、目标和派系；任务、生活系统和局部模拟能从世界状态中产生结果。

一句话版本：玩家在一个会持续运行的开放世界里，指挥队伍、构筑角色，并用可组合规则解决战斗、交互和任务。

## Stage 0: Foundation Baseline

状态：已完成并归档。

产物：

- `GameManager + AGameSystem` 基线。
- `PlayerSystem + PlayerControlGroup` 控制组。
- `PlayerOrderRequest` 正式订单链。
- `CharacterBase + ASC` GAS formal 规则边界。
- UIKit 菜单宿主、Yoki EventKit 事件、基础持久化和静态门禁。

下一阶段不得回头重造地基；如果发现框架缺口，应开新 change 补同一正式闭包。

## Stage 1: Foundational Character Case, Skill Authoring And Character Build

推荐当前立即推进。

目标：

- 建立地基上的基础角色自然实现案例，让一个正式玩家角色完成移动、受击、施放技能、状态变化、资源消耗、装备/职业挂接和正式 UI 反馈。
- 建立技能编辑器，让职业、技能树、能力、消耗、冷却、标签、状态效果和展示数据可被编辑、校验和预览。
- 让 `AbilitySheet / GameplayEffectAsset / CharacterAlterationRule` 这类规则资产形成统一生产流。
- 明确项目当前处于起步期：技能与属性正式链允许直接替换到更优正式实现，不为旧 `Stats/IEffect` 规则残留保留长期兼容层。
- 明确 EX-GAS 2.0 是正式规则底座方向，但不强制照搬它自带的 Excel/Luban 编辑工作流；项目可以保留自己的 `AbilitySheet / AbilityExecutionAsset` 资产入口与作者流。
- 支撑类 DnD / ToME4 式构筑，但不复制具体职业、技能或数值。
- 这一阶段不做敌人 AI 占位；只有在行为树或正式等价 AI 框架进入后，敌人实现才允许进入正式范围。

主要参考：

- ToME4：职业、技能树、复杂状态和构筑扩展性。
- 开拓者：正义之怒：职业构筑、Buff/Debuff 层叠、战前战中策略。
- EX-GAS：属性、标签、冷却、消耗、持续效果和能力授予/压制/替换/撤回。
- TopDownEngine：角色执行、受击、反馈和动作闭包样板。
- EX-GAS 2.0 README：规则底座、TimelineAbility、TargetCatcher 与“可不用官方 Excel/Luban 数据流，改接项目自有数据方案”的分层边界。

验收方向：

- 能用一个正式玩家角色完成技能释放、资源消耗、冷却、状态变化、受击反馈和死亡/失效链路。
- 能编辑一个职业、一个技能树、一个主动技能、一个持续效果和一个状态阻断规则。
- 能在不写业务硬编码的情况下，把技能资产应用到角色并看到 GAS 规则反馈。
- 不会把旧 `Stats/IEffect` 规则残留与 EX-GAS 长期并行保留，也不会为了编辑流强行照搬 EX-GAS 自带 Excel/Luban 工作流。
- 有资产校验，能发现缺标签、缺消耗、缺图标、缺描述、循环引用和非法状态组合。
- 不会为了“先跑起来”而引入没有正式框架支撑的敌人 AI。

## Stage 2: Real-Time With Pause Combat And Tactics Mode

目标：

- 建立可暂停即时战斗框架：暂停、恢复、慢速、命令排队、战斗态时间推进。
- 建立指挥模式：玩家可以对队友下达移动、攻击、施法、交互、撤退或等待命令。
- 战斗移动开始吸收转向行为或等价 steering 思路，避免角色像棋子瞬移或硬折线移动。

主要参考：

- 开拓者：正义之怒：可暂停即时战斗。
- 龙腾世纪：战术模式、队友命令和条件化行为。
- TopDownEngine：角色执行、能力状态、受击、反馈和战斗动作样板。

验收方向：

- 暂停时能下发队伍命令，恢复后按正式订单执行。
- 队友可以由简单战术规则或 AI 接管，不需要玩家每帧操作。
- 战斗暂停不破坏 UI、音频、对话、存档和时间相关状态。

## Stage 3: Vision, Perception, Interaction And Element Rules

目标：

- 建立视野、侦查、隐藏、感知和目标已知性合同。
- 建立 2D 地形高低差合同：高度不是纯渲染排序，而是类似 RTS 地图抬高地形的正式规则输入，影响移动、视线、远程攻击、范围效果、交互、AI 和任务路径。
- 建立涌现式物体交互合同：牢笼、石头、尸体、树木等对象通过标签、重量、体积、材质、状态和角色能力裁决。
- 建立元素反应规则层，让技能、地面、天气、物体材质和状态效果可以通过统一规则组合。

主要参考：

- ToME4：视野、侦查、隐藏目标和复杂状态。
- Red Alert / RTS 地图：即时命令、连续移动、自动经过坡道寻路、抬高地形、高台、悬崖边和地形优势参考。
- 塞尔达旷野/王国类交互：物件、材质、搬运、投掷和环境组合。
- EX-GAS：元素状态、标签、免疫、触发和持续效果规则载体。

验收方向：

- 看不见或未侦查目标不能被普通命令当作已知事实。
- 至少一个地形高度原型能证明高台、悬崖边或坡道影响移动、视线和远程目标裁决。
- 至少一个重物交互样例能按力量和物体数据裁决成功/失败。
- 至少一个元素反应样例证明规则来自统一元素系统，而不是技能脚本互相硬调。

## Cross-Cutting Track: 2D Elevation Model

这个系统目前缺少单一成熟参考，不能按“照搬某个框架”推进。推荐先做参考研究和最小原型，再决定正式数据模型。

候选实现方向：

- `地形层级`：每个规则 Tilemap 单元记录所在低地或高地层级，只作为地图制作与规则查询数据，不改变角色的连续坐标移动。
- `坡道/连接边`：坡道、台阶、悬崖边过渡和特殊跳跃点是显式连接，不靠碰撞器猜。
- `渲染排序独立于规则高度`：Sprite 排序只负责画面，玩法高度由地形/导航数据提供。

必须避免的方向：

- 只用 Unity 2D Sorting Layer 假装高度。
- 在没有验证前直接切到 3D NavMesh。
- 让每个地图物体自己硬写“我挡不挡视线、能不能走、能不能射中”。

首个原型建议：

- 一张小地图，包含低地、高台、坡道和悬崖边。
- 一个角色接收即时点击命令后，能自动绕到坡道并连续移动到高台，不能从悬崖边直接走上去。
- 一个远程技能或视线测试能被高度和遮挡影响。
- 一个 AI 能根据高度连接边找到合法路径。

## Stage 4: World Simulation And NPC AI

目标：

- 建立开放世界模拟 owner：区域、Cell、派系、日程、需求、局部模拟、区域外降级模拟。
- NPC 有性格、背景、派系和目标选择。
- GOAP / Utility AI 只在世界状态、行为代价、目标和存档边界成立后接入。

主要参考：

- Kenshi：队伍沙盒、派系、基地/生产、局部模拟和失败继续。
- Skyrim 类世界：Cell、日程、AI Package 和任务别名思路。
- GOAP / Utility AI：NPC 目标选择和行为规划候选。

验收方向：

- NPC 能按不同目标选择工作、巡逻、休息、逃跑、求援或战斗。
- 世界状态可以在玩家离开后保存或降级模拟。
- AI 决策能解释“为什么这么做”，便于调试和 Mod。

## Stage 5: Life, Quest And Dialogue Production

目标：

- 种植、钓鱼、采集、制作、交易和生活循环进入世界系统。
- 任务系统支持预设任务与需求驱动的生成任务。
- 对话支持剧情式立绘对话和沉浸式头顶短对白，状态气泡消费同一套角色/事件事实。

主要参考：

- 2DRPGEngine：任务、对话、数据库、命令、存档和 RPG 数据语义。
- 用户提到的“奈斯启示录”：暂作为种植、钓鱼和开放世界生活循环参考，具体作品名待确认。
- Kenshi：生产、派系、基地和世界事件驱动任务。

验收方向：

- 一个预设任务和一个生成任务都能读取世界状态、指向角色/地点/物品，并能存档恢复。
- 一段剧情式对话和一段头顶对白消费同一对话/事件事实。
- 生活行为能产出资源、时间推进和 NPC 反应，而不是只播放动画。

## Stage 6: Experimental City, Construction And Destruction

目标：

- 建筑损坏、城市之间火车轨道和建造系统先做可行性验证。
- 只在数据、性能、存档、寻路、AI、任务和表现成本可控后进入正式框架。

验收方向：

- 每个实验项先有最小原型和风险报告。
- 不影响 Stage 1-5 的正式框架推进。
- 失败时能明确归档为不做、延期或降级方案。

## Recommended Next Change

下一阶段建议新开“能力制作地基”方向 change，覆盖 Stage 1；当前正式能力名应收口到 `ability-authoring-foundation`，不再把 `workbench` 当成技能主线术语。

Stage 1 的关键产物不是“做几个技能”，而是把 `正式玩家角色 + 技能编辑 + 角色构筑 + 正式规则资产生产流` 一起做出来，形成地基上的自然实现案例。敌人 AI 只有在行为树或正式等价 AI 框架进入后才开启独立阶段。
