# Terrain Elevation Reference Notes

## 结论

当前没有找到一个能直接覆盖 `俯视角 2D 开放世界 + 红警式地图高低差 + 队伍命令 + AI + 交互` 的完整参考。这个系统应先走组合参考和最小原型，而不是直接照搬某个现成框架。

## 参考候选

| 参考 | 可借鉴点 | 不借鉴点 |
| --- | --- | --- |
| Red Alert / RTS 地图 | 抬高地形、高台、坡道、悬崖边、地形优势和高度可读性 | 不照搬 RTS 基地经营、资源采集或兵种体系 |
| Final Fantasy Tactics / Tactics Ogre | 局部战斗高度判定、高台优势、远程攻击差异 | 不改成回合制格子战斗，不照搬职业/数值 |
| ToME4 | 视野、侦查、隐藏和目标已知性 | 不是高低差参考，只是感知规则参考 |
| Zelda-like world interaction | 物件、材质、搬运和环境组合 | 不要求同等规模物理引擎 |

## 当前外部证据入口

- RTS 地图高低差当前作为主要体验参考：强调抬高地形、坡道、悬崖边和地形优势，而不是多楼层室内切换。
- Final Fantasy Tactics 的 `Ignore Elevation / Ignore Height` 资料说明了单位可以绕过 tile 高度限制，适合作为“离散高度影响移动能力”的次级参考入口。

## 实现假设

- `规则高度` 和 `渲染排序` 分离：玩法只读地形/导航数据，画面只负责表现。
- 地形高度先用离散层级表达：`elevation`、`rampConnection`、`cliffBlocker`。
- 移动不直接靠碰撞器猜高度差；坡道、台阶、悬崖边过渡和特殊跳跃点应是显式连接。
- 视线、侦查、远程攻击和范围技能都必须能查询同一套高度数据。
- AI 寻路必须知道高度连接和代价，否则世界模拟会在高台、坡道和悬崖边场景中失真。

## 首个原型建议

- 场景：低地、高台、坡道、不可直接攀爬悬崖边和地形断层。
- 角色：一个玩家角色、一个敌人或队友。
- 验证：
  - 玩家不能从低地直接走上悬崖。
  - 玩家能通过坡道到达高台。
  - 远程技能和视线受高度/遮挡影响。
  - AI 能通过显式连接边找到合法路线。
  - UI 或调试层能显示当前地形高度和目标高度差。
