# Terrain Elevation Reference Notes

## 结论

当前没有找到一个能直接覆盖 `俯视角 2D 开放世界 + 红警式地图高低差 + 队伍命令 + AI + 交互` 的完整参考。这个系统应先走组合参考和最小原型，而不是直接照搬某个现成框架。

## 参考候选

| 参考 | 可借鉴点 | 不借鉴点 |
| --- | --- | --- |
| Red Alert / RTS 地图 | 即时命令、连续移动、自动经过坡道寻路、抬高地形、高台、悬崖边、地形优势和高度可读性 | 不照搬 RTS 基地经营、资源采集或兵种体系 |
| ToME4 | 视野、侦查、隐藏和目标已知性 | 不是高低差参考，只是感知规则参考 |
| Zelda-like world interaction | 物件、材质、搬运和环境组合 | 不要求同等规模物理引擎 |

## 当前外部证据入口

- RTS 地图高低差是当前唯一移动体验参考：强调即时下达命令、角色沿连续世界坐标移动、自动寻找坡道、悬崖不可直接穿越，以及抬高地形带来的规则差异。
- 当前不再使用回合制战棋作为移动或高度数据参考，避免把格子行动、行动点和逐格高度判定误带入正式方案。

## 实现假设

- `规则高度` 和 `渲染排序` 分离：玩法只读地形/导航数据，画面只负责表现。
- 地形高度先用规则 Tilemap 中的地形层级表达；格子只服务作者编辑、路径采样和查询，不改变实时连续移动。
- 移动不直接靠碰撞器猜高度差；坡道、台阶、悬崖边过渡和特殊跳跃点应是显式连接。
- 视线、侦查、远程攻击和范围技能都必须能查询同一套高度数据。
- AI 寻路必须知道高度连接和代价，否则世界模拟会在高台、坡道和悬崖边场景中失真。

## 首个原型建议

- 场景：低地、高台、坡道、不可直接攀爬悬崖边和地形断层。
- 角色：一个玩家角色、一个敌人或队友。
- 验证：
  - 玩家不能从低地直接走上悬崖。
  - 玩家点击高台后能自动经过坡道并连续移动到达。
  - 远程技能和视线受高度/遮挡影响。
  - AI 能通过显式连接边找到合法路线。
  - UI 或调试层能显示当前地形高度和目标高度差。
