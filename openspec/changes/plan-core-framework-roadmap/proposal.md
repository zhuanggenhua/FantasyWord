# Proposal: plan-core-framework-roadmap

## Why

基础运行时、控制组、RTS 订单链和 GAS formal 合同已经归档，下一步需要把“核心基本框架还要分几阶段完成”说清楚。

用户最新目标已经超过单纯技能编辑：游戏是单人主控、可带队友的俯视角开放世界 RPG；战斗接近《开拓者：正义之怒》的可暂停即时制，指挥模式接近《龙腾世纪》战术模式，角色构筑参考类 DnD 与 ToME4，世界交互参考塞尔达式涌现交互，开放世界 AI 和模拟参考 Kenshi，并包含元素反应、生活系统、任务、对话和若干实验性城市/建造方向。用户进一步纠正后，当前要做的是地基上的自然实现案例，不是最小原型；如果某系统进入实现，就必须连带对应插件/框架一起进入，而不是先写项目侧最小版本。没有行为树或正式等价 AI 框架时，不做敌人 AI。

本 change 的目的不是实现这些系统，而是建立下一阶段路线图和阶段边界，避免下一步只做“技能编辑”时忘掉它在完整框架中的位置。

## What Changes

- 记录核心框架 6 个阶段的推荐顺序。
- 明确当前是 `基础角色自然实现案例 + 技能编辑 + 角色构筑` 的组合入口；敌人 AI 只有在行为树或正式等价 AI 框架进入后才进入实现。
- 把可暂停即时战斗、战术指挥、2D 高低差地形、涌现式交互、世界 AI、元素反应、生活/任务/对话和实验项分别放入阶段，并明确“系统进入实现必须带对应正式框架/插件”的约束。
- 标出每个阶段的主要参考、正式 owner、验收方向和禁止提前实现的内容。

## Scope

本 change 覆盖：

- 阶段路线图。
- 阶段依赖关系。
- 用户故事与参考游戏的系统映射。
- 2D 表现但有高低差的参考搜索方向和实现风险。
- 下一阶段 `基础角色自然实现案例` 的合理入口，以及技能编辑在其中的落点。

本 change 不覆盖：

- 具体技能、职业、物品、NPC、任务、城市、建筑或剧情内容。
- 实现 GOAP、元素反应、建造、轨道、建筑损坏或完整开放世界模拟。
- 新增第三方 AI / 物理 / 建造插件。

## Acceptance Direction

- 路线图必须能解释“为什么当前先做基础角色自然实现案例，以及技能编辑为什么属于它的一部分”。
- 路线图必须明确：没有对应正式框架/插件的系统，不做最小实现占位。
- 每个阶段必须有可验证的框架产物，而不是内容堆砌。
- 实验项必须明确为可行性验证，不得被写成本轮核心必做。
- 参考游戏必须只作为体验和系统设计参考，不作为直接内容复制来源。
