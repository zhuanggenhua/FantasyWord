# Open Questions: define-skill-authoring-workbench

以下问题只聚焦“会改变代码结构和资产模型的最小必要信息”。这轮不问世界观细节、不问具体技能数值，只问会决定正式 schema 的前提。

## 已确认方向

- 当前小阶段先做：基础攻击、动画驱动、碰撞盒命中、属性系统。
- 蓄力攻击、背刺进入下一小阶段；火球术、陨石雨、闪电链、追踪剑、吸血、抽魂等复杂技能再后置。
- 技能运行时优先充分使用 GAS。
- 只有在出现可证明的正式缺口时，才扩展 GAS；不预先造并行能力系统。
- 基础攻击先按主动技能建模。
- 第一小阶段当前只关心 `生命 / 攻击力 / 攻击速度`。
- 第一小阶段目标入口先只做“方向 + 碰撞盒命中的单位”。
- 第一小阶段不做技能栏 UI，基础攻击直接绑定现有 `FireAbility1` 按键测试。
- 基础攻击不额外引入冷却条目，只跟动画/执行节奏走。
- 当前阶段允许使用测试技能资产验证实际链路，但这些资产不是正式技能内容。

## 第一小阶段仍需确认的问题

1. 蓄力攻击与背刺下一阶段是否作为独立技能，以及是否需要独立冷却条目？

## 可暂缓到角色构筑阶段的问题

1. 职业是固定主职业、可多职业，还是允许转职？
2. 技能树是按职业独占，还是允许跨职业共享？
3. 角色构筑是否允许 respec？
4. 技能获取方式在进入正式构筑时首批支持哪些：升级点、职业解锁、装备授予、剧情授予、状态授予？

## 为什么这些问题必须先答

- 这些问题决定角色构筑快照、技能定义 schema、技能树资产关系、运行时挂接点和存档结构。
- 如果不先锁定，后续任何“先写一个默认版本”都会变成隐含拍板，直接污染正式真相。

## 当前默认门禁

- 在第一小阶段问题未确认前，不实现会固化资源池、冷却模型、目标入口或输入槽位结构的正式代码。
- 在角色构筑阶段问题未确认前，不实现正式职业、正式技能树、正式技能内容。
- 在所有未确认问题前，不补默认技能、默认职业、默认流派。
- 在门禁未解除前，只允许推进内容无关的编辑框架、数据合同、校验框架和测试技能资产 smoke。
