# 能力系统参考对照：基础攻击阶段

> 本文件是 `define-skill-authoring-workbench` 在归档时保留的阶段性取证快照。
> 技能系统的长期正式裁决入口已经收口到 `docs/ai/技能系统职责裁决矩阵.md`。
> 若两边口径需要继续更新，以职责裁决矩阵为准；本文件不再承担长期总裁决入口。

本文件只裁决当前小阶段的能力执行方向：基础攻击、蓄力攻击、背刺这类“动画窗口 + 碰撞盒 + 属性效果”的技能。它不定义正式职业、技能树、技能内容或技能栏 UI。

## 对照对象

当前需要比较的不是“是否使用 GAS”这个抽象问题，而是当前已登记参考里，同职责实现到底谁更适合当前项目：

1. **EX-GAS 原生闭包**：`AbilityAsset / AbilitySpec / TimelineAbility / TargetCatcher / GameplayEffect` 同时承担技能资产、命中目标和效果结算。
2. **2DRPGEngine 技能闭包**：`AbilitySheet + Active/Passive Ability` 资产与运行时技能族共同承接技能定义、Prefab 和效果入口。
3. **时间轴/Prefab 内容生产闭包**：以 `duolafashi` 这类 `Timeline + Prefab + Config` 内容流为代表，擅长表现编排和资源拼装。
4. **正式融合闭包**：把不同参考里在不同职责上实现最好的部分收口进同一条正式路径；融合后仍只能有一套公开入口和一套结算结果。

当前已有实现属于 **GAS 规则层混合接入**：`测试-基础攻击` 绑定了 `TimelineAbilityAsset`，但真正命中判定仍由 `MeleeAttackAbility` 的 `BoxCollider2D + Physics2D.OverlapCollider` 与 `EffectDispatcher` 执行。它可以作为 smoke 证据，不能直接当作最终裁决。

## 作者工具参考补充

用户提供的 Kybernetik Platformer Game Kit 公开文档已登记为判定框作者参考，证据页为 `https://kybernetik.com.au/platformer/docs/combat/melee`。

该参考说明近战攻击应围绕动画播放期间激活的命中触发器组织；每帧动画可有独立命中数据以匹配 Sprite 可见效果；`AttackTransition` 持有 `HitData[]` 并在 Inspector 与 Transition Preview Window 绘制额外 GUI；运行时 `HitTrigger` 管 `PolygonCollider2D`，通过触发消息尝试命中对象，并用对象池复用实例。

由此得到的当前结论：

- 当前普通 `AbilitySheet` Inspector 只能算迁移期样例数据入口，不能称为正式判定框编辑器。
- `检查基础攻击测试链路` 这类只读检查只能算开发诊断，不应出现在策划制作/修改基础攻击的主流程。
- 后续如果要实现正式判定框编辑器，至少要先设计“动画帧命中数据、可视预览、运行时碰撞体生成/池化、单一目标快照和单次结算”的参考对齐方案。
- 若不采用 Platformer 这类动画帧命中数据方案，必须证明替代方案在策划编辑效率、动画/碰撞盒可视化、调试可追踪性和运行时稳定性上更好。

## 当前结论边界

当前阶段只能成立的结论不是“某个整体方案已经预设胜出”，而是：

- 规则层当前主要沿 GAS 方向收口，但它不是预设赢家。
- 轻量技能资产流当前可参考 `2DRPGEngine`，但它不是完整法术体系上限。
- 时间轴/Prefab 内容生产流当前可参考 `duolafashi`，但它不能直接充当规则真相。
- 如果最终保留融合方案，也必须建立在“同职责逐项择优”而不是“先定赢家再解释”的证据上。

在这条原则下，当前只允许保留以下已证实判断：

- **基础攻击、蓄力攻击、背刺** 的主要风险在动画窗口、碰撞盒、输入缓冲、攻击速度、背刺方位、击退和反馈；这些职责还没有被纯 EX-GAS 原生闭包证明为最佳。
- **生命、攻击力、攻击速度、成本、冷却、标签、持续状态、后续复杂效果** 的主要风险在规则一致性、属性真相、叠层、存档和可审计；这些职责也还没有被 `2DRPGEngine` 或 `duolafashi` 证明优于 GAS 方向。
- **时间轴/Prefab 内容生产流** 在复杂表现编排上有明显参考价值，但当前没有证据证明它适合充当完整规则真相。
- **2DRPGEngine** 在“单技能资产 + 数据库入口 + 运行时技能族”上有明确参考价值，但当前没有证据证明它就是完整法术体系顶层模型。

## 重构方向

下一批代码不应继续新增正式技能内容，而应先把当前基础攻击从“口径混合”收敛成“有边界的正式融合”：

1. **一手动作真相**：基础攻击命中窗口、碰撞盒、输入缓冲、武器状态和背刺判定继续放在 GameCore 的 TopDown 风格动作闭包中；判定框不挂角色 Prefab 手工子节点，仍由能力/武器实例按资产数据生成或绑定。
2. **一手规则真相**：基础攻击伤害、属性读取、成本、冷却和标签必须逐步改为 GAS 规则资产或 GAS-backed 规则入口；旧 `IEffect` 只能作为迁移期执行壳，不能长期和 `GameplayEffect` 并行表达同一伤害。
3. **GAS 时间轴定位**：当前 `TimelineAbilityAsset` 不再冒充完整执行真相；它要么成为规则/可视化校验资产，要么在后续证明能承载动作执行后再接管对应职责。
4. **防双重结算门禁**：同一次基础攻击只能有一个目标快照和一个伤害结果；不能同时由 `MeleeAttackAbility` 和 `ReleaseGameplayEffect` 各扫一次目标、各扣一次血。
5. **策划工作流**：第一阶段只能把 `AbilitySheet` 的命中盒和命中窗口字段作为迁移期样例数据入口；正式判定框编辑器必须对齐参考后再实现，不能让策划同时维护两份判定框。

## 不采用的方案

- 不采用 **纯 EX-GAS 原生重写** 作为当前基础攻击第一刀，因为它会要求立即补一整套项目侧 GAS AbilityTask/表现桥接/武器状态机轨道，短期不比参考动作闭包更稳。
- 不采用 **纯 TopDown/GameCore 执行** 作为长期方案，因为属性、冷却、标签、持续状态、复杂技能和存档规则必须继续向 GAS 收口。
- 不保留 **当前无边界混合**，因为它让 `TimelineAbilityAsset`、`AbilitySheet`、`IEffect`、`GameplayEffect` 的职责边界不清，后续必然变成两套技能真相。

## 第一批安全重构范围

在不定义正式职业、技能树、技能栏 UI 和复杂技能内容的前提下，第一批重构只允许做：

- 把基础攻击的 GAS 资产定位改成“规则/可视化绑定”，不再在文档或任何旧作者流残留里暗示它已经承载完整命中执行。
- 给基础攻击资产增加静态校验：如果同时配置 GameCore 命中效果和 GAS `ReleaseGameplayEffect` 命中效果，必须报错或阻断，避免双重结算。
- 建立 `IEffect -> GAS GameplayEffect` 的最小迁移台账：当前基础攻击伤害先记录为待迁移规则，不继续扩写新的非 GAS 伤害规则。
- 将只读检查入口从策划主流程降级为开发诊断，并移除“打开基础攻击判定资产”这类会把普通 Inspector 误导成正式编辑器的菜单。
- 当前已有 `ClickMoveTest` / composite PlayMode smoke 通过证据；后续若要把验证范围收窄到“基础攻击命中训练假人扣血”专项，仍需补单独验证器，而不能拿现在这条 broader smoke 冒充更细粒度证据。
