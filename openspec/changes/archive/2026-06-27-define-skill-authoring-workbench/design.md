# Design: define-skill-authoring-workbench

## Current Facts

- `plan-core-framework-roadmap` 已把下一阶段入口定义为“基础角色自然实现案例 + 技能编辑 + 角色构筑”。
- `refactor-character-ability-inventory-composition` 已经说明：角色能力、背包、装备和快捷栏最终都要走角色级 owner 和可审计组合闭包，而不是继续强化单 `Hero` 宿主中心。
- 当前项目规则明确要求：会改变代码结构、资产模型、存档结构或正式入口的前提，如果没有证据锁定，就不能直接实施。
- 当前阶段不允许因为推进速度，擅自补默认职业、默认技能、默认技能树、默认流派。
- 当前阶段没有行为树或正式等价 AI 框架，因此不把敌人 AI 纳入本 change 的实现前提。
- 用户已追加锁定：当前实现子阶段先只完成基础攻击和命中判定；蓄力攻击、背刺、复杂法术和特殊效果进入后续阶段。
- 用户已追加锁定：技能执行优先充分使用 GAS；EX-GAS 推荐闭包默认是首选评估基线，但不是禁止混合的红线，混合也不是违规形态。证明责任在混合方案，只有混合方案被证明比推荐用法更适合当前项目时，才允许进入正式链路。
- 用户已追加锁定：第一小阶段不做技能栏 UI，当前基础攻击直接绑定现有 `FireAbility1` 输入用于测试。
- 用户已追加锁定：第一小阶段当前只关心 `生命 / 攻击力 / 攻击速度` 这组最小属性。
- 用户已追加锁定：第一小阶段目标入口先只做“方向 + 碰撞盒命中的单位”，不提前实现锁定单位或地面目标。
- 用户已追加锁定：基础攻击当前先按主动技能建模。
- 当前代码现态补证：`测试-基础攻击` 已有 EX-GAS `TimelineAbilityAsset`，但真正命中判定仍由 `MeleeAttackAbility` 的 `BoxCollider2D + Physics2D.OverlapCollider` 和 `EffectDispatcher` 执行；这只能算 GAS 规则层混合接入，不是 EX-GAS 原生技能闭包。
- 当前偏离原因补证：此前为了避免 GAS 时间轴与 GameCore 命中盒各自结算一次伤害，先把 GAS 时间轴降成可见参考节点；这只是迁移期保护，不是正式推荐用法完成证据。
- 当前裁决方向补证：基础攻击、蓄力攻击和背刺不预设必须收敛到 EX-GAS 原生闭包，也不预设允许无边界混合；下一步必须比较 EX-GAS 原生闭包、三方参考能力/武器闭包和当前混合闭包。只有比较后证明更优的职责划分，才允许成为对应职责的一手真相源并进入重构。
- 当前裁决留档：详见 `ability-system-reference-verdict.md` 与长期入口 `docs/ai/技能系统职责裁决矩阵.md`。当前只能确认“项目执行壳 + GAS 规则层”的收口方向仍成立；执行真相尚未裁死单一赢家，不能把某个整体框架写成最终胜出。
- 当前作者工具参考补证：用户提供的 Kybernetik Platformer Game Kit 已登记为基础攻击判定框作者参考；其 melee hit boxes 文档证明正式命中盒编辑应围绕动画帧命中数据、Inspector/Preview 可视化和运行时触发器组织。当前普通 `AbilitySheet` Inspector 只能算迁移期样例数据入口，不能称为正式可视化技能编辑器。
- 当前代码残留补证：近战基础攻击的基础 `effects` 仍直接挂在 `AbilitySheet`，背刺额外效果仍挂在 `MeleeAbilityExecutionAsset`。这说明规则真相还没完全从旧效果链和执行资产中迁出。
- 当前编辑器现态补证：`MeleeAbilityExecutionAssetEditor` 现有命中框面板只提供静态迁移预览，不是按动画帧编辑命中数据的正式作者面。
- 当前编辑入口补证：`AbilitySheet`、`ActiveAbilitySheet`、`MeleeAttackAbilitySheet` 已经天然形成“单技能定义资产内分区”的数据骨架，包含 UI 信息、GAS 映射、消耗/冷却、执行权限、反馈、动画触发、碰撞盒和命中窗口。当前缺的不是再拆一套新资产，而是把这些字段收口成统一技能入口，并补一层正式执行数据与可视化编辑面。
- 当前主流方案裁决：详见 `mainstream-skill-editor-verdict.md`。当前不是先做大型技能编辑器，而是先定义配置型规则模型；前一轮 `ProjectileDefinition / ImpactReaction` 过窄，已降级为 Effect 或执行/表现子类型。表现不再作为规则顶层模型。
- 当前表现反馈裁决：GameCore `GameplayFeedbackSet` 是项目侧表现反馈真相源；EX-GAS `GameplayCue` 只作为 GAS 侧表现触发入口。基础攻击当前已把伤害结算收口到正式规则执行入口 `GameplayEffect.Executions -> FormalInstantDamageExecution`，后续技能也不得把伤害结算回退到 Cue。
- 用户已追加锁定：玩家炼金式法术配置不是单纯数值变化，必须能配置触发和反应逻辑。例如火球命中单位、命中地面、进入区域、击杀目标、被元素命中等事件，可以触发不同 GAS 效果、区域、投射物、Cue 或后续反应。

## Problem Framing

技能编辑不是单纯一个编辑器窗口问题，它至少同时触碰 5 层正式合同：

1. 内容资产层：技能定义、职业定义、技能树定义、授予来源、快捷栏配置是否各自独立。
2. 角色构筑层：角色能学什么、何时学到、能否跨职业、能否重置、切换角色时带走什么。
3. 运行时执行层：技能目标、资源消耗、冷却、切换/持续态、装备/状态授予等是否都能被统一表达。
4. 执行数据层：近战时序、命中框、投射物、区域、召唤、命中反应、触发链和表现挂点如何统一表达。
5. 存档与验证层：构筑快照、授予来源追踪、校验错误、空白示例资产 smoke 是否有正式入口。
6. 玩家配方层：玩家是否能像炼金一样组合法术核心、载体、运动、触发、命中反应、附加效果和代价，以及这些配方如何保存、校验和执行。

如果这些问题先天没锁定，就直接实现具体构筑内容，后面会同时牵动编辑器结构、数据 schema、运行时挂接和存档迁移，返工成本很高。

## Rules Architecture Decision

正式方向是配置型规则模型，而不是先做大型编辑器。顶层合同为：

1. `AbilityDefinition`：稳定 ID、名字、图标、描述、分类、标签、来源、等级、授予条件。
2. `CastDefinition`：动作类型、施法/出手时间、距离、可打断、集中、材料/武器/姿态要求。
3. `CostDefinition`：法力、耐力、怒气、充能、冷却、物品消耗、法术位、每日次数和职业资源。
4. `TargetDefinition`：自身、单位、地面点、圆形、锥形、线形、射线、触碰、区域和目标过滤。
5. `EffectDefinition`：伤害、治疗、状态、属性修改、召唤、创建区域、创建投射物、移动、驱散等可执行效果单元。
6. `TriggerDefinition / ProcDefinition`：施放、命中、被命中、击杀、tick、进入区域、状态变化等触发事件、条件、概率、内置冷却和触发结果。
7. `ResolutionDefinition`：攻击检定、豁免、法术抗力、命中/未命中、半伤、免疫、抗性、易伤、叠加规则和持续/集中。

表现引用只记录动画、音效、特效、投射物外观、拖尾、命中表现、区域表现、GameCore `GameplayFeedbackSet` 槽位和 EX-GAS `GameplayCue` 引用；它不是规则顶层真相。

`Projectile`、`Impact`、`Area`、`Summon`、`Aura`、`Damage`、`Heal` 都只是 `EffectDefinition` 或执行/表现子类型，不是顶层架构。

EX-GAS 作为属性、标签、GameplayEffect、Cost、Cooldown、持续状态和 GAS 侧表现触发底座；FantasyWord 规则层负责动作经济、目标模板、触发器、豁免/法抗、职业/专长、来源追踪、叠加规则和存档。EX-GAS `GameplayCue` 不得成为伤害、治疗、资源、状态或位移结算入口。

玩家炼金式法术配置允许配置触发逻辑，但应编译或解释为同一套 Ability / Effect / Trigger / Cost 配置。第一版不直接要求自由节点图；节点图只能作为高级 UI，不是第二套运行时真相。

## Runtime And Authoring Split

正式技能系统应收口为三层：

1. `AbilitySheet` 作为统一技能入口。
   - 负责技能 ID、名字、图标、描述、技能族、授予来源、成本/冷却/GAS 映射、目标入口和执行资产引用。
   - 它回答“这是什么技能”“该怎么被授予和显示”，不直接承载所有复杂执行细节。
2. `AbilityExecutionAsset` 作为统一执行真相。
   - 负责动画时序、命中框窗口、投射物生成、区域生成、召唤、命中反应、触发链和表现挂点。
   - 时间轴编辑与节点图编辑都只是它的不同作者面，不能形成第二套运行时语义。
3. 运行时壳作为通用执行器。
   - 例如 `MeleeAttackAbility`、`ProjectileAbility`、`DashAbility`、`SummoningAbility`、`SelfCastAbility`、`Projectile`。
   - 它们只消费 `AbilitySheet + AbilityExecutionAsset`，不把具体技能逻辑写死在 prefab 或 MonoBehaviour 里。

这三层对应的最终策划流程应是：

1. 新建技能定义。
2. 选择技能族和执行形式。
3. 配规则层。
4. 配执行数据。
5. 绑定通用运行时壳。
6. 直接测试。

中间不应出现“准备链路”“修复接线”“打开内部测试场景”这类人类步骤。

## Authoring Workflow Decision

当前阶段不再把项目侧自造窗口、样例修补逻辑或测试场景补丁伪装成作者入口。

当前正确顺序是：

1. 先以 `2DRPGEngine` 的 `AbilitySheet + DatabaseWindow + AbilitySheetEditor` 作为源码级技能族和职责边界参考。
2. 先以 Kybernetik Platformer Game Kit 的 melee hit boxes 文档作为命中盒编辑体验参考。
3. 在没有新的正式参考依据前，不把任何项目侧自造窗口、预览器、SceneView 手柄或截图桥写成正式作者工具结论。

当前项目当前能成立的只有三条：

- 单一技能定义真相应继续收口到 `AbilitySheet` 体系。
- 单一执行真相需要新增到正式 `AbilityExecutionAsset` 层，而不是继续让 `AbilitySheet`、Timeline、Prefab 脚本和测试场景接线互相抢职责。
- 单一运行时执行语义必须同时服务普通近战、投射物技能和后续玩家炼金式法术，而不是拆成样例链路和正式链路两套。

## Confirmed Stage Slice

当前已经确认的实现顺序是：

1. 当前小阶段：基础攻击、动画驱动、碰撞盒命中、最小属性判定；当前已完成的混合链路只作为 smoke 证据，不直接决定最终真相源，更不能继续暴露旧修补入口。
2. 下一小阶段：蓄力攻击、背刺。
3. 后续复杂技能阶段：火球术、陨石雨、闪电链、追踪剑、吸血、抽魂这类更复杂技能。
4. GAS 扩展门禁：只有当当前或后续小阶段出现“用正式 GAS 闭包无法合理表达”的具体缺口，或混合方案已证明比推荐用法更好但需要补项目侧正式挂接点时，才允许扩展；不允许为了未来可能会复杂而预先自造并行能力框架。未证明混合更好前，不能把混合当默认正式路线，但这不是禁止继续评估混合。
5. 玩家炼金式法术配置阶段：在配置型规则模型之上定义配方合同，允许配置触发和反应逻辑；第一版 UI 可采用槽位式或链式配方，不把自由节点图作为基础阶段必需项。

## User Confirmation Gates

以下问题属于“会改变代码结构和资产模型的最小必要信息”。在用户确认前，不得进入对应的内容相关实现。

### 1. 职业结构

- 问题：职业是固定主职业、可多职业，还是允许后续转职？
- 影响：决定角色构筑快照是单职业槽、多职业列表，还是带职业历史/转换规则的结构。

### 2. 技能树归属

- 问题：技能树按职业独占，还是允许跨职业共享？
- 影响：决定技能树资产是绑定单职业、绑定职业组，还是独立公共树再由职业引用。

### 3. 技能类别

- 问题：当前正式分类是否至少包含主动、被动、切换、持续光环四类？是否还有必须首批纳入的额外类型？
- 影响：决定技能定义资产的执行槽位、状态机、提示文案和校验规则。

### 4. 技能获取方式

- 问题：技能通过升级点、职业解锁、装备授予、剧情授予、状态授予中的哪些路径获得？
- 影响：决定授予来源模型、撤回规则、存档追踪和编辑器录入面。

### 5. 技能目标类型

- 问题：是否正式支持自身、单位、地面、方向、被动无目标这几类？首批还有没有必须纳入的目标类型？
- 影响：决定目标选择合同、输入挂接点、范围预览和空技能 smoke 的测试入口。

### 6. 资源类型

- 问题：首批资源是否包含法力、耐力、怒气、充能、物品消耗？哪些是正式资源池，哪些只是技能局部消耗？
- 影响：决定资源槽数据结构、HUD 入口、消耗校验和恢复规则。

### 7. 冷却形态

- 问题：冷却采用独立冷却、共享冷却，还是按标签组冷却？
- 影响：决定冷却记录 owner、分组键结构、UI 展示和存档快照。

### 8. 技能栏/快捷栏

- 问题：技能栏/快捷栏是否固定槽位？如果固定，是按角色固定、职业固定，还是装备/形态会改槽位？
- 影响：决定快捷栏绑定结构、UI 布局、拖拽规则和切换角色时的保持策略。

### 9. Respec

- 问题：角色构筑是否允许 respec？如果允许，是完全重置、部分重置，还是受消耗/地点限制？
- 影响：决定构筑变更审计、已学技能回退规则、存档迁移和编辑器验证。

### 10. 当前阶段是否允许只用空白示例技能资产验证链路

- 当前答案：不再停留在“空白示例技能资产 + 空执行/空表现”。
- 当前阶段允许使用“测试技能资产”直接验证动画、碰撞盒、属性和按键链路，但这些资产仍不是正式技能内容。

### 11. 玩家炼金式法术配置的自由度

- 当前答案：玩家法术配置允许配置触发和反应逻辑，不只是属性数值变化。
- 待确认：第一版玩家 UI 是槽位式、链式，还是直接自由节点图；若没有进一步确认，默认先做槽位/链式配方数据合同，保留后续节点 UI 升级空间。
- 影响：决定 `SpellRecipe` 存档形状、模块合法性校验、成本预算、运行时解释器和 Mod 权限边界。

## Safe Framework Work Before Answers

以下内容不依赖上述答案，可以先做：

- 技能编辑相关的数据合同、校验框架和参考矩阵记录。
- 删除旧的样例修补入口与错误作者流残留，不让它们继续污染正式方案。
- 稳定 ID、数据库登记、引用解析和重复/缺失校验这类内容无关的数据合同。
- 技能授予/撤回来源追踪框架，用于记录“这项技能为什么存在”，但不预设正式职业或正式技能树。
- 空白示例技能资产和最小 smoke 入口，用来验证资产创建、保存、加载、校验、运行时挂接和 UI 读取链路。
- 编辑期验证框架：缺字段、重复 ID、非法引用、循环引用、未登记资产、阻塞发布错误等。
- 运行时挂接点：角色读取技能定义、执行基础合法性检查、把失败原因反馈给 UI，但不承诺具体职业和技能内容。
- 以 GAS 为前提的最小能力资产流：基础攻击和蓄力攻击的能力壳层、标签、效果容器和命中事件挂接点，但不预设职业体系。
- 技能作者工具的参考矩阵与差距记录：可以先记录外部参考、当前落点、差距和验证口径；但在矩阵闭环前，不实现新的判定框 UI 或正式资产模型。
- `AbilityDefinition / CastDefinition / CostDefinition / TargetDefinition / EffectDefinition / TriggerDefinition / ProcDefinition / ResolutionDefinition` 配置型规则合同草案；该草案只能定义职责边界、稳定 ID、引用关系和校验方向，不能落正式技能内容。表现引用作为规则结果的附属配置，不作为独立规则顶层。
- `AbilityExecutionAsset` 合同草案：定义时间轴模式、节点模式、投射物/区域/召唤/近战窗口等执行语义，但不落正式技能内容。
- 玩家炼金式配方模块的白名单、触发入口、条件动作合同和成本预算模型草案；不得同时实现玩家 UI、正式数值平衡或默认流派。

## Must Wait For User Confirmation

以下实现必须等用户拍板后再做：

- 正式职业资产模型。
- 正式技能树资产结构和解锁规则。
- 正式技能类别全集及其执行分支。
- 资源池正式集合及 HUD/存档表达。
- 冷却分组策略和共享规则。
- 固定或动态技能栏/快捷栏结构。
- Respec 规则和构筑回退逻辑。
- 任何正式技能内容、职业内容、流派内容或默认构筑模板。
- 玩家炼金式法术配置的最终 UI 形态，特别是是否直接开放自由节点图。
- 玩家/Mod 可用法术模块全集、成本公式和材料经济。

## Questions Deferred Out Of This First Slice

如果当前小阶段严格只做基础攻击闭包，那么以下问题可以暂缓到下一阶段再拍板，不阻塞当前基础攻击代码结构：

- 职业是固定主职业、多职业还是转职。
- 技能树按职业独占还是跨职业共享。
- 是否允许 respec。

但它们只是“暂缓”，不是“不用定义”；进入正式角色构筑前仍必须由用户确认。

## Current Slice Decisions

当前已经锁定、不再阻塞第一小阶段结构的事项：

1. 基础攻击当前按“主动技能”建模。
2. 当前小阶段的最小属性先只锁 `生命 / 攻击力 / 攻击速度`。
3. 基础攻击不额外引入冷却条目，只跟动画/武器执行节奏走。
4. 当前小阶段命中目标先只支持“前方方向/碰撞盒命中的单位”。
5. 技能栏/输入绑定先直接复用现有 `FireAbility1` 硬槽位测试，不做技能栏 UI。
6. GAS 时间轴资产必须至少有可见执行节点和命中窗口参考轨道；当前真正命中判定仍由 `MeleeAttackAbilitySheet.hitWindow` 和 `MeleeAttackAbility` 承担，避免 GAS 时间轴与 GameCore 命中盒形成两套伤害真相。
7. 上一条只能作为迁移期现态，不是最终裁决；进入下一轮基础攻击收口时，必须先比较 EX-GAS 原生 `TimelineAbility / TargetCatcher / GameplayEffect`、参考能力/武器闭包和当前混合闭包，选择证据上更好的方案。
8. 当前没有正式判定框可视化编辑器；只读检查、命令行 smoke、普通 Inspector 和当前静态命中框预览都不能冒充策划编辑器。
9. 当前正式方向是配置型规则模型，编辑器后置；近战攻击、火球和陨石都不能倒推顶层架构。
10. 玩家炼金式法术配置进入同一套 Ability / Effect / Trigger / Cost 规则模型，允许触发和反应逻辑，但第一版不默认自由节点图。
11. 旧的 `BasicAttackAuthoringWorkbench`、`SkillWorkbench` 测试技能登记、`BasicAttackTestSceneRuntimeBootstrap` 场景保活器、玩家默认挂接的超范围测试技能和“准备链路 / 修复接线”入口已被判定为错误方向，应删除而不是转地下保留。

仍待进一步确认但未阻塞当前测试闭包的问题：

1. 蓄力攻击与背刺是否需要独立冷却条目，还是也只跟执行节奏走。
2. 后续正式角色构筑阶段的职业结构、技能树归属、 respec 与技能获取方式。
3. 玩家炼金式法术配置第一版 UI 采用槽位式、链式还是自由节点图。

## First Safe Implementation Batch

用户确认本提案后，第一批安全范围建议限定为：

1. 先清除旧错误作者流：删除 `BasicAttackAuthoringWorkbench`、样例修补菜单、场景保活器、错误文档口径、越界测试技能正式接线和 `SkillWorkbench` 旧语义。
2. 定义统一技能入口：以 `AbilitySheet` 作为技能定义入口，补正式执行资产引用而不是继续堆修补字段。
3. 定义统一执行数据：先写 `AbilityExecutionAsset` 合同与校验框架，明确时间轴模式与节点模式共用一套运行语义。
4. 保留最小运行时测试入口：继续复用 `FireAbility1` 作为内部基础攻击 smoke，不做技能栏 UI，不把 smoke 包装成策划流程。
5. 下一批安全实现的优先级不是继续加新技能，而是先完成“技能定义 -> 执行数据 -> 运行时壳 -> GAS 规则 -> 表现反馈”的单一路径收口。
6. 判定框编辑器的下一步不是继续包装普通资产入口，而是先做正式执行数据层的近战时序/命中框可视化编辑，再继续基于 Kybernetik Platformer、EX-GAS Timeline/TargetCatcher 和 TopDown 武器闭包补参考矩阵；矩阵未闭合前，不新增第二套正式判定框资产模型。
7. 在下一批实现前，先把配置型规则模型和执行数据模型写成规格合同，避免基础攻击、投射物、GAS Cue、GameplayFeedbackSet 和玩家炼金配方互相抢同一职责。
8. 玩家炼金配方第一批实现只能做数据合同和校验框架，不落正式火球内容、不做完整玩家 UI、不做自由节点图运行时。

## Explicit Non-Goals

- 不实现正式职业、技能树、技能内容。
- 不为了占位而创建默认战士/法师/盗贼等模板。
- 不在没有行为树或正式等价 AI 框架时做敌人 AI。
- 不为了规避待决问题新造第二套兼容层、并行 owner 或临时真相源。
- 不把基础攻击、近战攻击或普通投射物技能强行做成节点图。
- 不做两套技能运行时解释器；未来若有正式编辑器、玩家炼金配置和 Mod 编辑器，也必须共享同一套运行语义，只开放不同权限子集。
- 不在没有主流参考或本地成熟参考记录的情况下发明正式架构层级；缺参考时只能登记候选方案和待验证问题。
